[侧面板](/window/side-panel)（<kbd>⌘ J</kbd>）中的**源代码管理**选项卡是一个功能完整的 git 客户端，用于管理当前焦点窗格所在的仓库。它会跟随窗格：使用 `cd` 进入另一个仓库时，面板也会随之切换。

<a id="changes"></a>
## 更改

文件按 git 识别的状态分组：

| 分组 | |
|---|---|
| **合并更改** | 存在冲突的文件，提供*解决冲突*和*标记为已解决*操作 |
| **已暂存的更改** | 下一次提交将包含的内容 |
| **更改** | 已修改但尚未暂存的文件 |
| **未跟踪** | 新文件 |

每一行都提供**暂存更改**、**取消暂存更改**、**放弃更改**和**打开更改**操作，其中**打开更改**会打开[差异视图](/git/diffs)。分组标题上提供针对整个分组的*全部暂存*、*全部取消暂存*和*全部放弃*操作，破坏性操作会先要求确认。

<a id="committing"></a>
## 提交

在顶部的输入框中填写提交信息，然后选择提交操作：

| | |
|---|---|
| **提交** | 提交已暂存的内容 |
| **全部提交** | 暂存所有内容，然后提交 |
| **提交（修订）** | 替换上一次提交——操作前会要求确认，因为已经获取该提交的人都需要协调这一变更 |
| **提交并推送** | 提交，然后推送 |
| **提交并同步** | 提交，然后拉取并推送 |

光标位于提交信息框中时，按 <kbd>⌘ ⏎</kbd> 即可提交。这里也提供**全部贮藏**操作。

提交草稿按仓库的 **Host + 工作树根目录** 保存，而不是按窗格保存。同一标签页内切换窗格时，显式选择的仓库仍优先；切换标签页后恢复跟随窗格。切换仓库、连接断开和重连不会主动删除未发送的消息；远端仓库也不会借用本地 Host 执行同名路径上的操作。

提交请求发出并不代表提交成功。只有原仓库的 HEAD 已改变、输入框仍保留发送时的原文时，既有清理规则才会删除草稿；执行期间继续编辑的消息会保留。验证拒绝和 Git 失败保留消息，失败还会解除等待 HEAD 变化的清理状态，避免之后无关的提交误清草稿。取消修订确认不会关闭修订模式，也不会启动草稿清理。「提交并推送／同步」仅在提交成功后继续，失败或取消不会执行后续操作。

<a id="branches-and-remotes"></a>
## 分支与远程仓库

面板顶部的分支名称是一个下拉菜单，其中包含：

| | |
|---|---|
| **分支列表** | 点击某个分支即可检出。分支超过十二个后，列表会滚动显示，而不是继续增高到窗口之外 |
| **创建分支…** | 可从这里创建，也可从历史记录中的任意提交创建 |
| **获取** · **拉取** · **推送** | 可分别执行 |
| **切换仓库** | 仅当窗口中的窗格分属多个仓库时显示 |

旁边的同步按钮会先拉取再推送；如果分支尚未设置上游，它的标签会变为**发布分支**。

全局搜索的 **Git** 分类下提供这些操作：*Git：提交*、*全部暂存*、*全部取消暂存*、*全部放弃*、*创建分支*、*同步*、*推送*、*拉取*、*获取*，因此可以为它们绑定快捷键。检出需要选择目标，而不是直接执行单一操作，因此只在下拉菜单中提供。

<Warning>
  检出时不会自动为你贮藏更改。如果检出会覆盖工作区中尚未提交的更改，git 就会拒绝检出；lyrel 会以通知形式显示 git 原本的拒绝信息，而不是绕过这一限制。
</Warning>

当仓库正在执行某项操作时——合并、变基、拣选、还原、二分查找或应用补丁——面板会显示相应状态，而不会假装一切正常。

<a id="history"></a>
## 历史记录

点击*历史记录*区域的标题会打开提交图：分支以泳道形式绘制，并提供筛选框、**当前分支**或**所有分支**选项，以及底部的*加载更多*。

**Git：切换提交历史记录**可通过键盘执行相同操作。此操作没有默认快捷键，可在**设置 → 键盘快捷键**中绑定。

点击某个提交可查看详情，包括提交信息、父提交以及涉及的文件，每个文件都可打开差异视图。提交菜单提供以下操作：

| | |
|---|---|
| **检出提交** · **在此处创建分支…** | 切换到该提交 |
| **拣选** · **还原提交** | 在当前位置应用或撤销该提交 |
| **重置（软 / 混合 / 硬）** | 将分支移动到该提交——硬重置会要求确认，因为该提交之后的提交将不再属于此分支，且未提交的更改会被丢弃 |
| **复制提交 SHA** | |

历史记录区域默认折叠，并会记住你是否将其展开（`scm_graph_expanded`）。

<a id="in-the-sidebar"></a>
## 侧边栏中的状态

无需打开面板，也能了解当前状态：每个[侧边栏行](/window/sidebar)都会显示对应窗格的分支，以及工作区的 `+N −M` 计数；这些信息会在执行 `cd` 和命令结束时刷新。点击计数即可打开差异浮层。

## SCM 状态与调用接口

窗口直接持有一个 `ScmPanelState`，它是仓库选择、标签页内选择覆盖、提交输入框、逐仓库草稿和提交生命周期的唯一状态所有者，不新增 Entity、锁或通用管理器。工作台只提供窗格／标签页上下文，负责 GPUI 调度、系统确认、通知和跨能力导航；动作、快捷键、按钮仍通过 `ScmIntent` 使用既有 Git 操作。

- 选择通过 `follow_pane`、`enter_tab`、`select_repository` 更新；消费者通过 `pane_repo` 或 `active_repo` 读取，不直接修改选择字段。
- `repository_context`／`RepoKey::context` 返回一次调度所捕获的仓库、对应 `SharedHost` 和刷新 epoch。不可用的覆盖选择会被丢弃；Host 与根目录不能分别回退。`RepoKey::refresh_epoch` 支持无需复制路径的刷新身份读取。分支加载已使用这个接口，历史图和详情仍保持各自原有的新鲜度规则。
- `commit_input` 负责保存旧仓库文本、恢复新草稿和合并消息预填；输入 Entity 保持窗口内身份不变。`prepare_commit` 复用可见按钮的验证规则生成操作，但不改变提交状态。
- 只有实际派发时才调用 `commit_dispatched`；错误回调调用 `commit_failed`。Host I/O 仍由 `HostOps`／既有 Git 数据层执行，破坏性确认仍在窗口中完成。草稿清理留在 SCM 内部，不能从工作台回调直接删除消息。
