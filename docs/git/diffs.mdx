<a id="opening-one"></a>
## 打开差异

| 入口 | 操作 |
|---|---|
| 侧边栏 | 点击某一行的 `+N −M` 计数 |
| 源代码管理 | 对文件选择**打开更改**，或点击该行 |
| 历史记录 | 在提交的详情视图中点击文件 |

差异视图会停靠在终端旁边，占用与打开文件相同的栏位，因此你正在阅读的窗格仍会保留在屏幕上。按 <kbd>Esc</kbd> 可关闭差异视图；标题栏末尾的两个按钮——与打开文件时相同的“停靠 / 填满”切换按钮——则可让差异视图铺满整个窗口。
[了解更多关于该栏位的信息 →](/window/side-panel#where-it-opens)

<a id="side-by-side-or-unified"></a>
## 并排或统一视图

“停靠 / 填满”切换按钮旁边的两个按钮用于选择差异的显示方式：两个窗格左右排列表示并排视图，上下堆叠表示统一视图。将鼠标悬停在按钮上即可看到其名称，也可以在全局搜索中使用**切换统一 / 并排差异视图**，通过键盘完成相同操作。此选择全局生效——所有差异共用一个设置，与 VS Code 的 `diffEditor.renderSideBySide` 设置作用相同——并以 `diff_view` 保存在 `config.json` 中。

<a id="what-it-shows"></a>
## 显示内容

- 每个已更改的文件及其状态和 `+N −M` 计数
- **未跟踪文件**的内容预览，最多支持 4 MB；超过此大小时，卡片会提示读取失败，而不会显示被悄悄截断的文件
- 当差异从历史记录打开时，显示该次提交中的文件

以下两项限制可避免大型差异造成漫长等待：

| 限制 | 数值 | 处理方式 |
|---|---|---|
| 渲染的文件数 | 300 | *“……还有 N 个已更改文件——请在终端中运行 git diff 查看。”* |
| 自动折叠的行数阈值 | 每个文件 400 行 | 大文件默认折叠；可展开你关注的文件 |

触发任一限制时，浮层都会明确提示，不会悄悄省略任何内容。
