# 通过经 Host 鉴权的内部只读回环服务承载 HTML 预览

- 状态：accepted

## 背景与决策

侧面板「浏览器」原先按 `#382` 仅允许 `http://`、`https://` 与 `about:blank`，在协议层与原生 WebView 层全面拒绝 `file://`。新需求要求支持从终端、文件树、编辑器及 `lyrel preview` 直接在「浏览器」中预览本机和远端工作区的 `.html`/`.htm`/`.xhtml` 文件（包括智能体生成的 UI 原型），同时终端内所有 `http(s)` 链接默认也在「浏览器」中打开。

我们决定**继续保持 WebView 层与协议路由层全面禁止 `file://`**，改为由桌面端按需懒启动内部只读回环 HTTP 服务（`127.0.0.1:0`），经所属工作区的 `Host` 在限定目录边界内（严格限定为 HTML 所在父目录，拒绝 `..` 遍历与越界符号链接）读取 HTML 及其相对静态资源，并以带随机令牌的回环地址供 WebView 加载；地址栏与标签页向用户呈现文件路径而非内部端口和令牌。

## 生命周期与资源边界

- **服务层**：按需懒启动，无 HTML 预览时 0 端口、0 线程；首次打开 HTML 预览时全进程共享 1 个 `127.0.0.1:0` 监听端口与轻量监听线程（空闲 0% CPU），仅响应只读 `GET`/`HEAD` 并附带 `Cache-Control: no-store`；所有活跃挂载清空后主动停服回收端口与线程，进程退出时零临时文件残留。
- **挂载层**：每个挂载绑定随机高熵令牌、`SharedHost` 与父目录只读根。内置「浏览器」页签持有的挂载随页签关闭、导航离站、工作区关闭或远端 Host 断开注销（重连后按新 `SharedHost` 重挂）；外跳「系统浏览器」持有的挂载同文件复用、不设短时过期，通过容量上限（LRU 淘汰）、远端 Host 断开清理及进程退出释放。

## 备选方案与取舍

- **被否决方案（混合：本机受限 `file://` + 远端回环服务）**：远端 SSH 主机上的文件在本机磁盘不存在，无论如何都必须经 `Host` 提供，混合方案无法省去回环服务；同时原生 `file://` 在 WebView2 与 WKWebView 中处于 `null` 源，会因 CORS 阻断多文件 UI 原型常见的 `<script type="module">` 与相对 `fetch`，并扩大与外网 `http(s)` 网页共存时的本地文件越权风险。
- **收益**：本机与远端工作区共用同一套 `Host` 读取路径，零临时文件、零新增第三方依赖、未打开 HTML 预览时不占端口与线程，完整支持多文件静态原型与 ES Modules，且守住 WebView 禁止 `file://` 的安全边界。
- **后果**：本机与远端 HTML 的「在系统浏览器中打开」同样复用该内部只读回环映射地址，保证内置浏览器与系统浏览器（例如使用 Chrome DevTools 审查多文件 UI 原型）渲染行为一致；对应映射随当前 Lyrel 桌面进程与所属 Host 连接存活，退出或断连后失效。若需脱离 Lyrel 打开本机原始文件，可通过「在文件夹/Finder 中显示」直接访问。
