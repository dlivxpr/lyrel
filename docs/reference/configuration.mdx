| | |
|---|---|
| macOS / Linux | `~/.config/lyrel/config.json` |
| Windows | `%APPDATA%\lyrel\config.json` |
| Windows 便携模式 | `<lyrel-app.exe 所在文件夹>\data\config.json` |
| 覆盖整个目录 | `LYREL_CONFIG_DIR` 或 `--config-dir` |

所有配置键都是可选的——缺少某个键时会使用其默认值，因此只需填写要修改的配置。超出范围的数字会被限制在有效范围内，而不是被拒绝；无法识别的枚举值会回退到默认值并记录一条日志，不会导致整个文件加载失败。

```json
{
  "font_family": "JetBrains Mono",
  "font_size": 14,
  "theme_follow_system": true,
  "theme_preset_light": "one_light",
  "theme_preset_dark": "dracula",
  "macos_option_as_alt": true,
  "scrollback_limit": 50000
}
```

<a id="where-the-directory-comes-from"></a>
## 目录如何确定

配置目录保存实例需要保留的所有内容，不仅仅是 `config.json`，还包括主题、会话、回滚缓冲区、历史记录以及后台服务器的套接字。以下来源按优先级从高到低排列，首先匹配的生效：

1. 命令行上的 `--config-dir <dir>`——例如 `lyrel-app.exe --config-dir D:\lyrel-data`，或在其他平台上使用 `lyrel-app --config-dir ~/lyrel-alt`。应用会将该参数传递给它启动的服务器，因此整个实例的数据都会迁移到此目录。
2. `LYREL_CONFIG_DIR` 环境变量。与命令行参数不同，它还会影响无法直接控制参数的启动方式——资源管理器中的**在 lyrel 中打开**、桌面启动文件，以及其他终端中的 `lyrel` 命令。
3. **Windows 便携模式**：解压便携 ZIP 后，`lyrel-app.exe` 旁的 `data` 文件夹（该 ZIP 带有 `.lyrel-portable` 文件）。参见[安装](/getting-started/installation)。
4. 上表中的平台默认目录。

两个目录对应两个独立实例，各自拥有自己的服务器和会话。

标签导航固定在左侧，窗口六按钮常驻。加载旧配置时精准移除 `tab_bar_position` 和 `auto_hide_titlebar_buttons`，不将整个配置重写为默认值；其他键（含当前版本不识别的键）、主题、字体、opacity、快捷键及工作区文件均保留。侧栏收起状态仍由 `sidebar_collapsed` 控制。

`.md`、`.markdown`、`.mdx` 文件默认使用原生 Markdown 即时编辑；状态栏或 `ToggleDocumentPreview` 可在即时编辑与源码间切换，两种模式共用同一份文档和撤销历史。旧 `editor_markdown_preview` 键已退役，加载时作为未知键忽略，不会触发专门迁移；下次正常保存配置时不再写出。没有替代设置或只读预览偏好。

“新建 Markdown 文档”（`EditorNewMarkdownFile`）显式创建未命名 Markdown 文档，另存为建议使用 `.md`。普通新建文本（包括编辑器中的 `Ctrl+N`）与终端回滚内容导出仍使用普通文本编辑器，不会静默变为 Markdown。外部 HTTP(S) 图片初始不请求，须在当前文档选择“加载外部图片”；详见[隐私与权限](/reference/privacy#what-leaves-your-machine)。

<a id="links"></a>
## 链接

| 键 | 类型 | 默认值 | |
|---|---|---|---|
| `link_url` | bool | `true` | 为 URL 添加下划线，并在 ⌘/Ctrl+单击时打开。 |
| `link_file_open` | string | `internal` | 文件链接的打开方式：`internal`（lyrel 编辑器，并定位到相应行）、`system`（操作系统的文件关联）、`command`。另一台机器上的文件始终使用 `internal`。 |
| `link_file_command` | string | — | `link_file_open: command` 时用于打开文件链接的命令。会替换 `{path}`、`{line}`、`{column}`；缺少值的选项会被移除。 |
| `ssh_loopback_forward` | bool | `true` | 转发远程窗格开始提供服务的端口，并通过这些转发打开其 `localhost:PORT` 链接。 |

相对文件路径先按窗格的工作目录解析，再尝试所在仓库的根目录；远端路径使用对应 Host 的路径格式，不把远端的 `/`、盘符或 `~` 当成本机路径解释。内置导航保留文件链接的行、列；目录链接交给文件树定位。仅在本机存在同名文件，不能证明另一台机器输出的路径有效。

实现中，`src/terminal/link.rs` 的 `LinkInteraction` 独立持有路径探测、仓库根目录、悬停与修饰键，以及右键菜单捕获的目标。Host、目录或网格尺寸变化会使旧异步结果失效；目标变化后只重新解析当前指针位置。`TerminalView` 保持原有 GPUI 身份，仅调度 Host 任务、绘制提示和发出导航请求。菜单中的打开、复制路径、显示所在目录和默认应用操作使用右键时的目标；内置导航按发出请求的窗格身份恢复工作区，源窗格已消失或已改属其他 Host 时不会误开当前工作区的同名文件。

<a id="serversjson"></a>
### servers.json

保存的主机不在 `config.json` 中，而是存放在同一目录下的 `servers.json` 中，因此可以在机器之间同步 `config.json`，而不必同时同步服务器列表。文件以 `0600` 权限写入，读取时与 `config.json` 一样宽容；如果无法解析，lyrel 会在 `servers.json.corrupt` 保留副本，并在修复前停止保存该文件。

| 键 | 类型 | 默认值 | |
|---|---|---|---|
| `ssh_profiles` | array | `[]` | 通过**设置 → SSH** 管理。机密信息保存在操作系统钥匙串中，绝不会存放在此处。 |
| `ssh_profile_frecency` | object | `{}` | 每台主机的使用频率和最近使用时间，用于排序。由应用写入。 |

如果旧版 `config.json` 仍包含 `ssh_profiles`，支持拆分存储的 lyrel 首次读取时会将其拆分：先写入 `servers.json`，然后才从 `config.json` 中移除这两个键，其余内容保持原样。如果两个文件都包含主机，则以 `servers.json` 为准，并在下次保存设置时移除 `config.json` 中的副本。

`ssh_profiles` 中的每个对象还可以设置：

| 键 | 类型 | 默认值 | |
|---|---|---|---|
| `remote_clipboard_write` | bool | `false` | 允许该 SSH 主机上的程序通过 OSC 5522 将 PNG、JPEG、GIF 或 WebP 图片写入本机剪贴板。 |

<a id="keys-lyrel-manages-itself"></a>
## lyrel 自行管理的键

`shell_frecency` 和 `command_frecency` 记录打开 shell 或运行命令的频率及最近时间，以便新建标签页菜单和“全局搜索”进行排序。它们由应用写入，无需手动编辑。

<Note>
  如果文件无法解析，lyrel 会使用默认配置启动，将原始文件保留为 `config.json.corrupt`，并记录原因。它绝不会静默覆盖你写入的内容。
</Note>
