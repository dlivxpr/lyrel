## 技能：先选机器，再选项目

从**设置 → 技能**进入，也可在设置搜索中输入 `skills`、`SKILL.md`、智能体名称或「共享」。机器默认是桌面本机；远端选项只列出已连接的 Host。切换工作区不会替你切换机器或项目。

需要项目技能时，输入**目标机器上的绝对项目路径**，按 Enter 或选择**应用项目**。留空只查看用户级来源。不能解析的相对路径、旧远端缺少环境能力、断连和读取失败会明确报告，不会回退读取桌面目录。切换机器会清空项目选择，避免把本机路径当成远端路径。

可按名称、描述或记录的来源搜索，并筛选用户共享、项目共享和智能体私有来源。列表分页显示；同一真实目录的链接别名可合并来源，同名但不同位置的副本仍是独立安装。打开详情后可阅读实际 `SKILL.md`、查看来源入口、更新时间、伴随文件数量和字节数，以及有记录的参数提示。缺少 frontmatter、无效 UTF-8、不可读、超过 1 MiB 或遍历上限会明确报告；没有来源和时间时保留未知，不补造信息。

**打开 SKILL.md**通过 lyrel 编辑器打开所选 Host 的文件。**复制路径**复制实际安装路径。本机**浏览文件**在文件管理器定位；远端则在技能详情中列出目标 Host 的文件，文件通过同一远端编辑入口打开，绝不把远端路径交给本地文件管理器。详情和远端文件列表均可用 Escape 返回上一层，来源下拉框沿用设置的键盘导航与取消规则。

### 安装 GitHub 技能到所选机器

技能页的**发现并安装技能**支持 `owner/repo`、`github:owner/repo/subpath` 和 `https://github.com/owner/repo/tree/ref/subpath`。可单独填写分支、标签或 commit 与仓库子路径；单独填写的值覆盖来源中的相应选择。明确 ref 的内容不会被 skills.sh 的非固定快照替代。只支持 github.com 来源，不支持本地目录、压缩包或其他 Git 主机。

GitHub 仓库发现、授权解析和所有 tree／blob 下载始终在**桌面本机**完成，复用现有 `GH_TOKEN`、`GITHUB_TOKEN` 或 `gh` 授权，不建立第二套 GitHub 账号。私有仓库须由这些已有授权可见；401 表示授权被拒绝，403 表示权限／组织 SSO 限制，404 表示仓库或 ref 不存在或当前授权不可见，限流与网络／代理失败分别显示。不要把 token 写进来源 URL。安装到远端时只经所选 Host 传输技能内容和来源记录，不发送 GitHub token、授权环境、凭据 argv 或 gh 配置。

也可搜索 **skills.sh**。它使用 skills CLI 同款、无凭据且未公开稳定契约的 `/api/search` 接口；失败与空结果分别显示。目录还包含其他 HTTP 注册表，本页仅显示支持的 GitHub 来源，不会因混入其他来源而隐藏合法候选。选择搜索结果仅填入 GitHub 来源，仍需点击**发现技能**、明确勾选仓库候选，再点击**审查安装**，不会点击即安装。每个候选列出实际仓库路径，允许选择多个技能。

**共享安装作用域**默认用户共享；项目共享只有应用明确绝对项目路径后才可审查安装。用户目标是所选 Host home 下的 `.agents/skills`，项目目标是所选项目下的 `.agents/skills`；即使桌面 Windows 连接 Linux，路径仍由目标 Host 解释。原生智能体 profile 只决定只读发现与启用状态，不会把共享安装重定向到其私有 profile 目录。审查界面列出机器、home／项目、每个具体目录、文件影响、固定 tree SHA 及来源锁路径；审查期间机器与项目选择锁定，须先**取消安装**才能更改目标。确认复用同一个 Host 与已下载快照，不因工作区切换、晚到响应或 registry 连接替换而改写另一目标。已有同名目录默认保留，只有逐项勾选**替换此现有目录**才整目录替换，不合并 Markdown。**取消安装**或 Escape 丢弃审查，不写文件或来源锁。

确认后只写选定共享目录及兼容来源记录，不创建智能体私有链接、不改原生配置、不向 TUI 投递命令，也不自动提交项目变更。写入结果逐项显示具体目标；网络、权限、安全校验或来源锁错误不会冒称成功。断连或记录失败时保留已完成项与恢复路径，不自动重复安装、不回退本机；先查看报告及目标文件，再重新审查需要恢复的项目。安装完成后自动刷新当前范围，选择**浏览已安装技能**即可查看实际 Markdown、伴随文件及来源。即使所有原生 profile 都覆盖了 home，所选 Host home 下的共享安装仍可浏览；无法核实原生读取时显示未知，不宣称已经加载。

下载使用有界 GitHub tree／blob API，而不是解包任意归档。截断树、路径逃逸、符号链接、submodule 和不安全条目会拒绝；不跟随已有安装路径的链接。每次安装选择最多 1,000 个源文件、总计 50 MiB，单个 `SKILL.md` 最多 1 MiB；GitHub tree 响应最多 16 MiB／20,000 个条目。整个多技能选择在下载伴随文件前统一检查上限，超限会明确报错。Host 在阶段边界复核路径和快照；它不提供操作系统级目录句柄事务，因此不声称可对抗恶意并发文件系统置换。

### 受保护更新

在具体共享安装的详情中选择**检查更新**。只有来源锁可核实 GitHub 仓库、ref 和技能路径时才查询上游；不从同名、描述或目录名称猜测地址。界面分别显示有更新、没有更新、上游技能已消失、检查失败与来源无法核实。上游消失不会自动删除本地内容，检查失败也不等于没有更新。

更新审查固定原安装身份、来源与 ref，并列出实际目录和来源锁。即使基线一致也默认保留；本地修改或基线无法核实时明确提示，必须逐项勾选**替换此安装并丢弃其当前内容**再选择**替换安装**。替换是整项写入，不自动合并、不另建备份系统。**取消，保留文件、来源记录与链接**或 Escape 不修改任何内容。检查与下载仍在桌面执行，只有固定快照通过同一个 Host 写入共享安装。

### 安全移除共享安装

选择**移除安装…**后，先审查实际共享目录、受影响的来源锁与条目，以及精确指向此安装的 symbolic link／Windows junction 路径和记录目标。其他读取同一共享目录的工具也会受影响。关联链接按所选机器的有效原生来源收集，包括不同名称的别名和相对链接；不能证明一致的条目保留并解释，真实副本、不同目标及仅名称相同的条目不会被删除，也不会新建私有链接。

选择**移除共享安装**前可以取消或按 Escape，文件、锁及链接均保持不变。执行时再次通过固定 Host 复核安装身份、路径、内容、原始锁及每个链接目标；确认后发生变化的目标保留，不按名字扩大删除，也不跟随链接删除外部内容。删除结果分别列出安装、来源记录及每个链接；权限、断连、记录失败或应答丢失会保留失败、部分成功或结果未知，不冒称完成。先检查报告中的具体路径再恢复，不要盲目重复移除。

远端只读链接目标能力通过 `host-read-link-v1` 协商，control 协议为 15，pane 协议仍为 7。旧远端须升级，能力不足不回退本机。来源锁仍保留合法未知字段与无关项，损坏或未知格式不会强制重写；项目锁变更不自动提交。



### 发现不等于原生启用

浏览与检查不会修改文件；安装、替换和移除只在明确确认后写入所选共享安装及匹配来源记录。技能页不修改智能体配置、不授予项目信任，也不向运行中的 TUI 发送命令。状态「磁盘已发现」只说明存在文件；能证明来源开关关闭时显示未启用，运行时权限、信任、名称过滤和包过滤无法完整核实时显示未知。

## 搜索与编辑

搜索可匹配设置名称、描述、英文别名，以及 `mouse_zoom_modifier` 等配置键。结果按分区分组，可直接编辑；点击分区名称即可打开该分区。按 ⌘F（Ctrl+F）可跳转到搜索框。

使用**仅显示已修改项**可查找与默认值不同的设置。已修改的设置会在名称旁提供**重置**操作；安装和维护操作不提供通用的重置功能。

普通控件会自动保存。文本字段会在按下 Enter 或焦点离开字段时提交有效值。自定义主题的编辑在保存前仅作预览；取消会恢复原始主题。SSH 主机也需要显式保存。

录制已被其他操作使用的键盘快捷键时，会先询问是否接管：**替换**会将快捷键移交给当前操作，**取消**则让两个操作都保持原样。
离开已编辑的表单时，会提示保存、放弃更改或继续编辑。

## 原生历史统计

从**设置 → 统计**进入，或搜索「统计」「Token」「omp」「pi」「Kimi」「OpenCode」。先选择本机或已连接远端；
选择不会随当前 SSH 工作区隐式改变，一次只展示一台机器。「智能体来源」可选择全部智能体或单个有效来源；一个来源发现失败不会清空其他已读取来源，失败原因显示在来源诊断中。
范围支持今天、本周、本月、本年、全部与自定义日期（`YYYY-MM-DD`，包含两端）。
所有日期按桌面本机时区的日历边界解释，星期一为周起点；快照显示时间、时区与实际结果范围。
本周／本月／本年比较截至当前日期的对应前期；全部不制造基期，无有效分母时显示「不可比较」。

数据读取正式 omp `18.12.1` 的原生 JSONL，包括其他终端产生的可发现历史，
并遵循所选 Host 的有效 home、`OMP_PROFILE`／`PI_PROFILE`、`PI_CONFIG_DIR`、
`PI_CODING_AGENT_DIR` 及 `agent_launch.omp` 的明确作用域与绝对 `--session-dir`。命名 profile 不读取默认 profile。
macOS／Linux 的已存在 XDG 数据／状态目录按上游规则解析；自定义文件通过原生
`custom-session-files` 和 `terminal-sessions` 标记发现，不猜测任意项目路径。
相对路径依赖原生 cwd 而无法核实时明确报错，不借用 GUI home。
远端复用 Host 文件操作与非秘密环境元数据；旧 server 缺能力时要求升级，不回退本机。

Kimi Code 使用正式 `2.2.0` 的 protocol `1.5` durable `usage.record`，
只读取所选 Host 的有效 `KIMI_CODE_HOME`（优先采用 `agent_launch.kimi` 中的明确选择），
缺省为该 Host 的 `~/.kimi-code`，不读取旧产品 `~/.kimi`。
显式空值／相对 home 缺少原生 cwd 时拒绝，不回退 daemon 或桌面默认目录。
会话元数据接受 `state.json` 与 `session-meta/state.json` 的第一方读取顺序，
逐个读取 `agents/*/wire.jsonl`，不会把 session index 当作用量文件。

第一方 `UsageAgentModel.record()` 直接持久化本次请求的 `input.usage`，
`usageScope` 仅区分 turn 请求与 operation 请求；`status().total` 累加两种 scope。
因此 `turn`、`session` 和缺省 scope 都按单次增量计入，不能将 `session` 行误认累计值而跳过。
Token 分别取 `inputOther`、`output`、`inputCacheRead`、`inputCacheCreation`，缺项保留未知；
原生 wire 没有费用，显示未计价，不根据模型名或 Token 推算。

Kimi 主会话、子代理与 child 会话分别识别：非 main agent 和 `custom.parent_session_id`
标记的 child 不计主会话，但其可核实新增用量计入总量。
fork／child 逐个 agent journal 以最后一条可靠 `forked` 标记切除继承前缀；
标记之后新建的子代理仅在 journal 的原生创建时间严格晚于 fork 创建时间时确认为新增。
缺少可靠边界显示受限，不全额累加或静默当作零。空 fork 不根据继承的 `updatedAt` 计作活跃会话。
wire 没有独立请求 ID，不能按 turn、模型、时间或相同 Token 合并真实的多次调用；
重复发现的同一原生 session／agent journal 按持久位置去重，并保持 Host／agent／有效 home 隔离。

### OpenCode 2.x

来源下拉可选全部、omp、pi、Kimi Code 或 OpenCode。OpenCode 适配依据正式 `2.0.32` 的公开
`experimental.session.stats`、`session.list` 和 `session.message.list`，不扫描旧 SQLite。
打开的原生 TUI 使用已认证、有界的只读客户端桥；没有绑定客户端时使用配置的
`agent_launch.opencode` 和所选 Host 的 home／环境调用正式 `opencode api`。
绑定来源断连、认证不足或服务身份变化只显示诊断，绝不借用另一默认服务。
远端要求独立能力 `opencode-statistics-v1`；旧 server 必须升级，不能回退本机。

分页遵循不透明 `cursor.next`，消息页上限 200，会话页 100；重复游标、分页字段缺失、
5,000 个会话、50,000 条计量消息、约 4 MiB 计量投影或查询期限均标记不完整。
服务端聚合作为独立覆盖检查，不与逐消息数据相加。日期筛选和日界使用桌面日历时区。
Token 总量为 input + output + reasoning + cache.read + cache.write；推理单列，
不重复加到 output。子代理用量计入总量，但 `parentID` 子会话不计主会话；

活动计数只采用 user／assistant 消息；不将无消息的创建事件伪装成活跃会话。
Host、服务 pid／公开 URL、有效 home／存储选择器共同隔离来源；缓存不含客户端认证材料。
压缩请求的公开 `compaction` 消息若携带 Token／费用，也纳入真实用量；但该响应只提供
消息创建时间，不能核实原生 `usageRecorded` 事件的完成时间，因此明确标记日期归属受限。
服务端聚合还交叉核对 Token 各分项、费用与 assistant steps；不一致不会显示完整成功。

### pi 原生历史

pi 独立按正式 `@earendil-works/pi-coding-agent@1.3.0` 解析，不使用 omp 的 profile、XDG 或 `model_usage` 字段。
有效来源依次采用 `agent_launch.pi` 的 `--session-dir`、`PI_CODING_AGENT_SESSION_DIR`、有效配置根下 `settings.json:sessionDir`，否则读取 `PI_CODING_AGENT_DIR|~/.pi/agent` 下的 `sessions`。
已知 Host 历史返回的会话作用域可补充原生 pane 捕获的存储、home 与配置根；捕获 cwd 可用于项目 `.pi/settings.json` 及相对路径。没有原生 cwd 的相对设置明确报错，绝不回退默认目录。历史发现 API 的最近 500 条窗口仅限制额外已知来源发现，不限制已发现目录内的完整计量扫描；不可发现的任意项目目录不自动猜测。

pi 按官方 `usage-totals` 口径计入全文件全部分支：assistant（包括失败／中断）、toolResult 可选用量、顶层任意 `kind` 的 `usage`、compaction／branch_summary 可选用量。
总 Token 使用 `input + output + cacheRead + cacheWrite`；`reasoning` 已包含在 output、`cacheWrite1h` 已包含在 cacheWrite，不重复相加，也不采用可能不同的 `totalTokens`。模型优先使用真实 `responseModel`；工具／摘要缺少 provider／model 时保留未知，不沿用前一个模型。
原生 pi 无通用子代理身份字段，工具嵌套调用计入用量但不增加主会话；不凭文件夹名称或 `parentSession` 猜子代理身份。磁盘 v1／v2／v3 可读，v1 缺条目 ID 仅独立根文件按行身份计量，继承不可核实则受限。
pi 的 `parentSession` 是精确父文件路径；只在相同 Host、home、有效配置根及存储作用域内核实继承条目 ID。缺父文件、跨作用域或循环时排除该文件不可核实的用量并显示排除条数，不冒充全额或免费。新用量不会因整个文件是分叉而丢弃；相同短 ID 但计量／时间／内容摘要不同的条目保留并报冲突。原始正文不进入结构化缓存。

pi 格式与算法依据：[Session format](https://github.com/earendil-works/pi/blob/v1.3.0/packages/coding-agent/docs/session-format.md)、[usage-totals.js](https://unpkg.com/@earendil-works/pi-coding-agent@1.3.0/dist/core/usage-totals.js)。记录费用是 pi 按自身模型价表计算的历史值（含合法零），不代表服务商账单。

### 统计口径与缓存

总览与分析共用唯一用量 visitor 和活动时间流。pi 在扫描阶段已切除可核实继承，不会在分析时再次扣除；Kimi 仅保留最后可靠 fork 边界后的 prompt／steer 及用量时间，不采用 metadata 的创建或更新时间。OpenCode 活动仅来自 user／assistant 消息，日期未知的 compaction 用量只进入全部范围总量。

主会话按范围内活动计数，独立分叉仍计主会话；原生 artifact 子会话不计主会话，
但可核实新增 Token 与费用计入总量。重复副本与可解析 `parentSession` 链的继承记录去重；
同名 ID 在不同 Host／有效配置作用域中保持独立。继承关系未知、坏文件、权限失败、
链接遗漏或扫描上限均显示受限状态，不冒称完整。分项缺失显示未知，与有效零不同。

费用优先采用原生记录中的有效 USD 费用，包括零；缺失时仅按下节明确配置的类别单价估算，
分别展示记录、自定义／公共估算与未计价覆盖。金额是历史计量小计，不是服务商账单、余额或套餐额度。
平均 Token 包含子代理用量，分母是活跃主会话；结果不完整或分母无效时不显示精确平均值。

扫描、解析与聚合在后台执行；按机器及来源缓存结构化计量，未变文件无需重解析。
缓存只在当前设置会话内保留，不写提示词、对话正文或凭据到磁盘。
刷新失败时保留带时间的旧结果并明确标为过期；切换机器／范围或离开页面后，晚到结果不会覆盖新选择。
当前扫描上限为 5,000 个文件、20,000 个目录、单文件 16 MiB、每轮变更读取 256 MiB。
来源关联与价格管理见下节；未实现的其他智能体不提供成功占位。
Kimi 元数据单文件上限 256 KiB、durable 单行上限 256 KiB；其他文件／目录／字节上限同上。
旧版／未知 protocol、坏行、截断和不可核实继承均显示诊断，不影响其他可读 agent。

原生格式与目录依据：[会话契约](https://github.com/can1357/oh-my-pi/blob/v18.12.1/docs/session.md)、
[配置作用域](https://github.com/can1357/oh-my-pi/blob/v18.12.1/docs/config-usage.md)、
[目录实现](https://github.com/can1357/oh-my-pi/blob/v18.12.1/packages/utils/src/dirs.ts)。
Kimi 口径依据：[正式 2.2.0 分发包](https://unpkg.com/@moonshot-ai/kimi-code@2.2.0/dist/main.mjs)
中的 `usageAgentModel.ts`、`sessionUsageService.ts`、`appendForkedMarker()`、`sessionMetaSchema`；
独立样本来自 [ccusage 原生 wire 样本补丁](https://github.com/ccusage/ccusage/commit/69fbca0f1d3fd691c89ad892dc54a8f7583fd1f3)，
但不采用该第三方跳过 session-scope 的错误口径。
确定性文件／Host 测试不等于真实 SSH 或桌面视觉验收；Windows／macOS 实机、真实 SSH、
窄窗口、主题、界面放大和键盘流程的实际验收证据须分别记录。

### 来源关联与明确单价

在「设置 → 统计 → 来源」审查当前机器的已发现及额外关联，选择智能体后添加来源。
omp／pi 接受所属 Host 的绝对历史目录或 JSONL 文件，Kimi 接受原生 sessions 目录；
OpenCode 使用正式服务 HTTP(S) 地址，不能填写旧数据库目录；Hermes 使用有效 profile home，
经正式 launcher 重建并验证，不把数据库文件作为入口。选择器不能包含账户凭据。
重复、目录重叠、非法或不可读来源会显示原因。检查只读取对应来源；移除只取消关联，
不删除任何原生历史。关联改变后立即重新扫描当前范围；失败保留旧计量并标为不完整。

「Token 单价」支持新增、编辑和删除精确服务商 ID、模型 ID、币种及每百万 Token 单价。
输入、输出、reasoning、缓存读取、缓存写入独立填写，未知类别留空，不填零，也不借用其他类别。
有效原生记录费用（包括零）始终优先；缺记录时按自定义价、已启用目录价的顺序估算。
原生估算、自定义估算、公共目录估算分别标明；部分计价保留已知金额和未计价覆盖，
不同币种分开展示，既不混加也不换算。累计或未知日期费用不会摊到日格。

models.dev 默认禁用、零联网。阅读页面说明后显式启用，再点「检查公共价表」，
桌面才会请求固定的 `https://models.dev/api.json`；不运行自动周期检查，不发送会话、
路径、提示词或账户凭据，且不跟随重定向。只消费 provider-specific 目录，不以 canonical model
借用另一服务商单价。目录以 USD／每百万 Token 表达，依据为 [models.dev](https://models.dev/)
与[正式目录说明](https://github.com/sst/models.dev)。估算不是账单、余额或账户对账。

关联、自定义单价、公共目录缓存、下载时间和最近检查时间单独保存于桌面配置目录的
`statistics-settings.json`，不保存原生正文。网络失败继续使用带来源与时间的旧价表；
禁用公共价表立即停止使用目录估算，但保留缓存供再次启用。Escape 取消当前编辑并恢复焦点，
不会提交草稿；窄窗口及放大字号时可继续滚动访问所有操作。

### 活动热力图与分解明细

「活动与明细」直接使用同一快照与去重口径；只展示已发现真实来源中的智能体。
「分析智能体」仅筛选分析区域，上方总览保持其原有机器／来源范围。年度热力图可切换
Token、历史记录费用、活跃主会话；指标只改变图格深浅，日期详情始终保留全部指标。
年度切换只改变日历，智能体／常用模型／常用项目明细仍覆盖完整所选日期范围。

每月从星期一开始，日期边界和日期说明均使用桌面本机时区，不使用远端机器时区。
选择日期或将焦点移入日历后，可用方向键按日／周移动，Page Up/Down 按月移动，
Home/End 到年首／年尾，Enter 展开详情，Escape 隐藏详情，再按可关闭设置。
当前日期及完整数值有常驻说明，不依赖悬停；月份自动换行，控件跟随界面字号缩放。

图例深浅按本年、所选范围和智能体筛选中的已知最大值解释；`?` 为未知／不完整，
`–` 为范围外，范围外不代表零活动。费用图格只显示覆盖完整且币种唯一为 USD 的统一计价结果，
包含有效记录或明确估算；多币种、部分缺价或扫描失败保持未知。原生估算和各目录估算在详情中分开显示。
累计跨日记录只在完整覆盖其时间区间的范围内计入总量，不摊到每天；相交但无法归属的
日格标为不完整，不能据此计算连续使用。当前／最长连续天数只在可见年份与所选范围内计算；
今天没有活动时，当前连续天数可从昨天开始。不完整来源不构造连续天数。
没有可靠活动时间的累计记录只在「全部」范围保留可得总量；有边界的范围与日格显示未知，
不把占位时间解释为真实日期。所选智能体在当前机器没有已发现来源时也明确提示来源缺失，
不会回退其他来源或显示为零活动。
累计记录与逐次调用分开标明，不把一条会话累计记录当作真实调用次数。累计会话只有路由模型
元数据、不能可靠分摊到逐次模型时，保留为「无法归属」模型用量，而不是伪造模型排名。

分解保留智能体、来源作用域和模型提供商身份；缺少项目或模型时显示「无法归属」，
不静默丢弃。已知 Token 总量降序排列，未知值不参与排名；每页可查看十条完整明细并翻页。
同一主会话可能跨日期、模型或项目参与，因此这些会话数不可相加；子代理用量计入用量，
但不增加主会话数。原生副本和可核实继承记录先由总览共用的唯一算法消重，再执行日期／模型／项目分解。
刷新期间保留带快照时间的旧结果，扫描诊断及不完整状态仍可见。

## Hermes 原生历史统计

「设置 → 统计」可筛选 Hermes 或全部来源，并固定选择本机或远端机器。有效 home/profile
复用已配置的 Hermes 启动命令与 Host 环境，不读取另一机器的默认 profile，不猜测系统 Python。
仅通过 Hermes 0.22.2 正式 launcher 的 `--print-runtime-command --module tui_gateway.entry`
查询 `projects.tree`；远端需要独立的 `hermes-statistics-v1` 能力，旧 server 明确要求升级。
统计响应在数据所属 Host 剔除 `title`／`preview`，不为统计传输会话标题或提示词片段；仅缓存结构化计量元数据。

仅纳入 `source=cli` 的原生持久会话。正式项目路径用于项目归属，无项目进入 Home 桶；
可见 branch/reset 是独立主会话，compression 谱系已由上游合计，重叠谱系不会重复计费。
输入、输出与总 Token 保留有效零，缺失项仍未知；实际 USD 和原生估算 USD 分别展示，
估算不是账单，二者不能相加，也不以估算替代实际费用。

接口只有会话累计用量，没有逐消息日期：仅当选择范围覆盖整个会话活动区间才纳入累计值。
与范围相交却跨界的累计值不分摊、不归到最后一天，而是显示不完整；全部范围仍保留可得用量。
缺少可靠活动日期时，已知 Token 和费用仍保留在「全部」范围；有限日期范围显示受限，不虚构日期或单日会话活动。
调用数表示计量记录，Hermes 累计记录不等于模型请求次数。

每次最多请求 501 个会话元数据，达到全局／项目预览边界会显式提示无 offset/cursor，
不将有限窗口冒充全部历史。公开接口排除子代理用量、归档、零消息与自动任务，故总量始终受限。
成功空响应不能区分空历史和 profile 数据库不可用，显示未知诊断而非完整零值。
一个来源失败不会清除其他来源；读取失败保留对应来源带时间的缓存，不回退默认 profile。

正式响应依据：[projects.tree](https://github.com/NousResearch/hermes-agent/blob/v0.22.2/tui_gateway/methods_config.py)、
[会话投影和可见性](https://github.com/NousResearch/hermes-agent/blob/v0.22.2/tui_gateway/methods_projects.py)。

## 设置文件

设置窗口写入的所有设置都保存在同一个文件中：

| | |
|---|---|
| macOS / Linux | `~/.config/lyrel/config.json` |
| Windows | `%APPDATA%\lyrel\config.json` |

SSH 主机单独保存在同一目录下的 `servers.json`。[servers.json →](/reference/configuration#ssh)
用量账户的非秘密元数据与快照保存在 `usage-accounts.json`；API key 仅保存在桌面本机系统凭据库的 `lyrel-usage` 服务中，不随配置同步。

可通过 `--config-dir` 或 `LYREL_CONFIG_DIR` 将整个目录（包括配置、主题和状态）移至其他位置。配置目录的优先级为：`--config-dir` > `LYREL_CONFIG_DIR` > Windows 便携模式的 `data` 目录 > 平台默认目录。

你可以手动编辑此文件；少数选项只能在文件中设置。有关每个配置键、类型及默认值，请参阅[配置参考](/reference/configuration)。

<a id="how-it-handles-mistakes"></a>
### 如何处理错误

文件以原子方式写入，读取时则采用宽容处理：

- **缺少配置键**时使用默认值，因此只需写入要修改的设置。
- **数值超出范围**时会被限制在允许的范围内，而不是被拒绝。
- **无法识别的枚举值**会回退到默认值并记录一条日志，而不会导致整个文件加载失败。
- **无法解析的文件**不会被覆盖。lyrel 会使用默认值启动，将副本保存在 `config.json.corrupt`，并在日志中说明情况。

<Note>
  文件开头允许存在 UTF-8 BOM；如果你使用 Windows 编辑器编辑过文件，这一点尤为重要。
</Note>

<a id="language"></a>
## 语言

**设置 → 通用 → 语言**提供「跟随系统」「English」「简体中文」三种选择，实际翻译只有英文和简体中文。新配置或未设置 `gui_language` 时默认跟随系统；手动固定的语言优先于系统。

跟随系统读取 Windows 的最高优先界面语言或 macOS 的首选界面语言，不读取 shell 的 `LANG`／`LC_*`。明确 `Hans` 脚本使用简体中文；未指定脚本时，`CN`／`SG` 地区使用简体中文。显式脚本优先于地区，所以 `zh-Hans-TW` 使用简体中文、`zh-Hant-CN` 使用英文。繁体、裸 `zh`、其他语言或读取失败均使用英文。

## DeepSeek 用量账户

从**设置 → 用量**进入，或搜索 `DeepSeek`、`Kimi`、`Command Code`、余额、会话、浏览器、`LocalStorage`。点击**添加账户…**，输入便于区分的名称，选择**服务商**与**认证来源**，再点击**验证并保存**。DeepSeek 支持官方 API key、手工平台会话或浏览器 LocalStorage。
lyrel 从桌面本机请求 [DeepSeek 官方余额接口](https://api-docs.deepseek.com/api/get-user-balance)：`GET https://api.deepseek.com/user/balance`，认证为 `Authorization: Bearer <API key>`。仅验证成功才写入系统凭据库；不会读取智能体或远端机器的密钥，不导入 vortex 数据。

余额保留接口返回的 CNY／USD 金额字符串，分别显示总余额、赠送余额、充值余额与更新时间，不换算币种、不伪造百分比。接口不提供用户姓名、邮箱、账单周期或重置时间，因此页面使用自定义名称及稳定的本地账户 ID 区分账户，不冒称已确认服务商用户身份。

每个账户可重命名、停用／启用刷新、替换来源、手动刷新及移除。相同名称不会合并账户。替换时先验证；长期秘密写入全新凭据槽，浏览器来源只保存非秘密引用。认证、读取、凭据库或本地保存失败均保留旧来源及旧快照，不切换到其他账户。移除仅清理所选本地查询账户、快照及自己的凭据槽，不注销 DeepSeek 账户、浏览器登录态或撤销 API key；清理失败可重试移除。

默认仅手动刷新，可选择页面可见时每分钟或每 5 分钟刷新。应用启动不查询；离开用量页、进入搜索或关闭设置后，不再启动新的周期请求。已经发出的请求可以收尾，但不得重新启动轮询或恢复已移除／旧凭据的账户状态。请求使用 lyrel 的代理解析规则，连接超时 10 秒、总超时 30 秒，并拒绝重定向以避免认证材料发往其他来源。

认证失败、限流、网络、服务响应结构、系统凭据库和本地保存错误分别显示。刷新失败保留旧快照并标注其时间与状态，不将未知余额填为零。没有授权的真实 DeepSeek 账户时，受控响应测试不能证明真实账户或系统凭据库集成已验收。

### 私有平台手工会话

选择**私有平台 · 手工会话**后，从 `https://platform.deepseek.com` 的开发者工具 → Application／Storage → LocalStorage 复制 `userToken`，可粘贴裸值、`userToken=…`／`user_token=…`、对应 JSON，或仅请求平台固定汇总端点的 Bearer cURL。lyrel 不执行 cURL，不接收 Cookie 头、其他站点请求或官方 API key 作为平台会话。只保存解析出的必要 token，不保存整段粘贴内容。

私有查询固定为 `GET https://platform.deepseek.com/api/v0/users/get_user_summary`，钱包按 `normal_wallets`（充值）与 `bonus_wallets`（赠送）分开保留原币种、金额字符串，包括 `0E-16`；不相加冒充官方总余额、不换算历史费用，也不推测用户身份或周期。平台会话是私有兼容入口，不代表 DeepSeek 官方支持。

DeepSeek 第一方 [deepseek-harness 凭据源码](https://github.com/deepseek-ai/deepseek-harness/tree/687f282e8625c6b8d11ff58211a90524be2e4317/packages/credentials/deepseek-account-platform/src) 的 Harness grant 与网页 token 不是同一种来源：grant JSON 必须含 `version: 1`、`token` 和精确 `issuer: "https://platform.deepseek.com"`，也接受官方 `{kind:"grant",payload:{…}}` 包装；验证 issuer 后用 `x-dsh-auth-token` 发送，仅将 token 长期存入系统凭据库。网页 `userToken` 则使用 Bearer。后者仅有第三方兼容实现佐证，本次无认证读取平台页面均返回 HTTP 429，尚未取得第一方 Web JS 或授权真实账户的有效性证据，不能据受控测试声称真实平台集成通过。

### 主动选择浏览器与 profile

选择**私有平台 · 浏览器**，先选择 Chrome、Edge、Brave、Chromium 或 Firefox，再选择明确的 profile，最后点击**验证并保存**。发现 profile 时只读所选浏览器的元数据；不扫描所有浏览器登录态、不自动验证候选。DeepSeek 实际读取仅查询所选 profile 的精确 `https://platform.deepseek.com` origin 与 `userToken` 键，不读取 Cookie、其他服务商或刷新 token。只读数据库锁定、访问拒绝、格式不支持、profile 消失和会话失效分别显示，不会改用另一来源或当作零余额。

Windows／macOS 的 Chromium 系支持现行 LevelDB LocalStorage；恢复在内存文件系统中完成，不写秘密数据库临时副本。Firefox 支持现行每 origin SQLite、UTF-8／UTF-16 与 Snappy 压缩，并保留已提交 WAL 的读取语义。Safari、Firefox container origin 和 Chromium 新 SQLite LocalStorage 后端不支持，不绕过系统保护；浏览器版本变化可能使导入不可用，可改用手工会话。

浏览器 token 只在请求期间驻留内存，材料类型不能序列化或调试输出，离开请求后释放；不写系统凭据库、配置、快照、日志或临时文件。持久化仅含浏览器、profile ID／显示名称，以及路径和原 token 的 SHA-256 绑定指纹，不含原始路径或 token。每次刷新重新读取同一 profile，后台从不请求系统权限；来源或 token 改变时保守要求主动重新导入，无法确认同一服务商身份时绝不静默接受另一账户。

真实浏览器导入需要用户对目标浏览器、profile 与平台账户的明确授权。本次开发只使用临时 LevelDB／SQLite 样本和回环 HTTP，未获读取真实浏览器及查询真实 DeepSeek 平台账户的授权；Windows／macOS 实际浏览器、系统凭据库与真实平台查询仍须分别验收。

两家账户沿用上述桌面本机账户、凭据库、代理、失败替换保护与页面可见期间刷新生命周期。认证来源不会因当前 SSH 工作区、读取失败或接口失败而改变。API-key 用量接口均为第一方客户端使用的私有接口，可能随服务商版本变化；本地受控响应测试不等于已通过真实账户验收。

### Command Code

API key 是主要认证，按第一方 [`command-code@1.84.0`](https://unpkg.com/command-code@1.84.0/dist/cli.mjs) 请求 `https://api.commandcode.ai/alpha/whoami?limits=1`，并对返回的可选组织请求 `/alpha/billing/credits?orgId=…` 与 `/alpha/billing/subscriptions?orgId=…`，再用订阅的 `currentPeriodStart` 请求 `/alpha/usage/summary?orgId=…&since=…`。服务商用户身份、套餐、月度周期、组织限制与各窗口重置分别展示；月度 Credit、购买 Credit、免费 Credit、5 小时／周滚动窗口、当期费用／请求数及 Sandbox 分钟不相加、不折算为历史费用。滚动窗口与购买 Credit 的规则见[第一方用量限制说明](https://commandcode.ai/docs/resources/usage-limits)。

已添加 Command Code API-key 账户后，点击**设置会话增强…**，选择手工会话或浏览器来源。手工来源从你已授权的该站登录请求中明确复制一个会话 Cookie 的 `name=value`；不接受整段 Cookie、cURL 或 API key 代替会话。浏览器来源先明确选择浏览器，再选择 profile，最后确认验证；发现 profile 只读所选浏览器元数据，不扫描会话或替你选择账户。先向 `GET https://api.commandcode.ai/auth/get-session` 验证会话身份，只有 `user.id` 与主要 API-key `whoami.user.id` 相同时才查询 `GET https://api.commandcode.ai/internal/billing/subscriptions` 并合并套餐／周期。不会凭空假设订阅响应有 `userId`。两个增强请求均仅发送所选 Cookie，不发送 API key。

身份端点与基址来自[第一方 auth client](https://commandcode.ai/assets/auth-client-DR7oY-YF.js) 的 `baseURL=https://api.commandcode.ai/auth` 及 [root 会话身份读取](https://commandcode.ai/assets/root-CycwDi3N.js)；账务 endpoint、GET、Cookie 凭据与 `{success,data}` 包装来自[第一方常量](https://commandcode.ai/assets/constants-oAoFBSr8.js)及[第一方订阅 hook](https://commandcode.ai/assets/use-legacy-pro-status-B1iLcEZv.js)。私有接口不等于公开第三方支持保证。

浏览器增强还必须填写**精确会话 Cookie 名称**，只填名称、不填值；该名称是非秘密来源选择器，保存后用于刷新相同来源。仅读取适用于 `api.commandcode.ai` 的 host-only `api.commandcode.ai` 或域 Cookie `.api.commandcode.ai`／`.commandcode.ai`；不会读取 apex host-only `commandcode.ai`、`www.commandcode.ai` 或相似恶意域。未找到指定名称、同名 scope 歧义、过期、锁定或权限拒绝均明确失败，不尝试其他 Cookie 名或 profile。

不能把框架默认名当成服务端事实：[第一方 auth client](https://commandcode.ai/assets/auth-client-DR7oY-YF.js) 带有 BetterAuth 客户端版本 `1.6.23`，但没有公开服务端 Cookie 配置。[正式发布包的 createCookieGetter](https://unpkg.com/better-auth@1.6.23/dist/cookies/index.mjs) 与 [BetterAuth Cookie 文档](https://better-auth.com/docs/concepts/cookies) 说明，默认 `${prefix}.session_token` 与 HTTPS `__Secure-` 前缀可被 `advanced.cookiePrefix`、`advanced.cookies.session_token.name` 或 `advanced.useSecureCookies` 改写；客户端版本也不证明服务端版本完全相同。匿名 `get-session` 不返回可核实名称的 `Set-Cookie`，因此本入口不预填默认名、不建立猜测白名单。自动名称识别仍缺第一方服务端实际配置或经用户授权的真实 `Set-Cookie` 证据；显式名称入口不要求 Lyrel 研究或扫描你的真实浏览器。

手工增强仅在身份与账务查询均成功后保存到独立系统凭据槽。浏览器增强使用独立的非秘密来源引用，Cookie 只在请求期内存中使用，从不调用手工凭据保存路径；来源引用不含原始路径或 Cookie。手工与浏览器增强相互替换，但不替换主要 API key；成功切换至浏览器后清理该账户旧的手工增强槽。失败、身份失配或保存失败保留旧来源。可见期间每次刷新重读同一 profile，并先重新匹配服务商身份，允许同身份的 Cookie 轮换，不会静默切换账户。增强失败单列，仍展示成功查询的主要 API 额度，不用旧增强结果伪装最新完整数据。移除只删除本地账户自己的主要／增强槽；取消、来源替换、关闭页面或删除后的晚到结果不能绑定浏览器来源、复活账户或重启轮询。

真实服务商账户、Windows／macOS 系统凭据库与真实浏览器读取均未获本票授权，因此仍为未验收项；没有发送服务商认证请求，没有读取用户真实浏览器或申请系统权限。

- Windows Chromium 系：支持传统同用户 DPAPI 行密文，以及 `Local State` 中 `DPAPI` 主密钥对应的 `v10`／`v11` AES-GCM；对 schema v24 以上校验域名哈希。使用 `CRYPTPROTECT_UI_FORBIDDEN`，不弹授权。遇 App-Bound Encryption 或 `v20` 明确拒绝，不注入浏览器、不提权、不改策略、不引导关闭保护。格式变化、锁定或解密失败明确显示，可改为手工会话或受支持的 Firefox profile。
- macOS Chromium 系：主动导入可调用官方 Keychain 授权读取对应浏览器 Safe Storage；刷新固定使用 `kSecUseAuthenticationUISkip`，绝不后台弹授权。拒绝／需要重新授权时明确失败；不解锁钥匙串或更改 ACL。
- macOS Safari：只在显式选择 Safari 来源并确认后，尝试读取所选传统 `Cookies.binarycookies`。该二进制格式没有 Apple 公开规范，解析为有边界的尽力支持，不能保证所有现代 Safari profile／版本适用；不能识别时明确失败，不回退到其他浏览器或来源。读取被系统拒绝会明确提示全盘访问限制；Lyrel 不修改隐私设置、不自动申请全盘访问。系统没有可保证无 UI 的 FDA 文件读取模式，因此后台拒绝重新读取 Safari，需用户主动重新导入；不能以已有授权推断后续访问一定不会弹窗。

浏览器材料仅在请求期间驻留内存、不进入凭据库、配置、快照、日志或临时文件。只保存浏览器/profile 的非秘密引用和来源绑定指纹；每次刷新重读同一来源，材料轮换或身份变化保守要求主动重新导入。关闭页面不再启动新的周期请求。

### 额度口径与验收边界

StepFun 根据 `plan_family` 区分请求窗口与 Credit 套餐；直接剩余比例、Credit 额度池、重置与到期分别展示，不把不同单位相加。MiMo 账户总余额、现金、赠送、冻结与 Token Plan 分开；保留服务端金额及币种，缺失币种仅在 `userProfile.idc` 可确定区域时使用相应 CNY／USD。`tokenPlan/usage` 第一方结构为 `data.usage.items[]`，不是 `monthUsage`；每个池的名称、已用、上限与单位单列。`currentPeriodEnd` 为 UTC 到期时间，不冒充固定月度重置。缺失数值、未知余额或不可用套餐不补零／百分之百，失败保留带时间的旧快照。

StepFun 契约核验来自[官方 SDK bundle](https://platform.stepfun.com/_next/static/chunks/28300-12e20e884619af74.js)、[Connect/protobuf 运行时](https://platform.stepfun.com/_next/static/chunks/40714-0dc15cb8037b0613.js)与[用量页](https://platform.stepfun.com/_next/static/chunks/app/(dashboard)/account-overview/page-e82dc4ae140e2d0f.js)：实际 JSON 字段使用 camelCase、枚举通常为字符串名；解析亦兼容 proto 字段名和数值枚举。窗口／额度池时间戳为 Unix 秒；订阅 `expiredAt` 与桶 `expireAt`／`nextResetAt` 分开保留。

MiMo 契约核验来自[官方控制台主 bundle](https://platform.xiaomimimo.com/static/main.f2b8e14e661a38ce.chunk.js)、[余额页](https://platform.xiaomimimo.com/static/904.6fb4d0fff1570f70.chunk.js)和[套餐页](https://platform.xiaomimimo.com/static/279.8ef7328eee268de2.chunk.js)的公开源码。静态源码与隔离真实格式 SQLite／受控 HTTP 只能证明相应确定性路径；未读取真实浏览器、未发真实账户认证请求，也未在 macOS 实机验证 Keychain 允许／拒绝与后台静默。两家授权账户的手工／浏览器真实查询、系统凭据库和跨平台矩阵均保持未验收，不据构建或受控响应声称通过。
