## 技能：先选机器，再选项目

从**设置 → 技能**进入，也可在设置搜索中输入 `skills`、`SKILL.md`、智能体名称或「共享」。机器默认是桌面本机；远端选项只列出已连接的 Host。切换工作区不会替你切换机器或项目。

需要项目技能时，输入**目标机器上的绝对项目路径**，按 Enter 或选择**应用项目**。留空只查看用户级来源。不能解析的相对路径、旧远端缺少环境能力、断连和读取失败会明确报告，不会回退读取桌面目录。切换机器会清空项目选择，避免把本机路径当成远端路径。

可按名称或描述搜索，并筛选用户共享、项目共享和智能体私有来源。列表分页显示；同一真实目录的链接别名可合并来源，同名但不同位置的副本仍是独立安装。打开详情后可阅读实际 `SKILL.md`、查看来源入口、更新时间、伴随文件数量和字节数，以及有记录的参数提示。缺少 frontmatter、无效 UTF-8、不可读、超过 1 MiB 或遍历上限会明确报告；没有来源和时间时保留未知，不补造信息。

**打开 SKILL.md**通过 lyrel 编辑器打开所选 Host 的文件。**复制路径**复制实际安装路径。本机**浏览文件**在文件管理器定位；远端则在技能详情中列出目标 Host 的文件，文件通过同一远端编辑入口打开，绝不把远端路径交给本地文件管理器。详情和远端文件列表均可用 Escape 返回上一层，来源下拉框沿用设置的键盘导航与取消规则。

### 发现不等于原生启用

技能页只读取文件，不安装、不移除、不修改智能体配置、不授予项目信任，也不向运行中的 TUI 发送命令。状态「磁盘已发现」只说明存在文件；能证明来源开关关闭时显示未启用，运行时权限、信任、名称过滤和包过滤无法完整核实时显示未知。

发现依据以下正式版本契约（核验于 2026-10-19）：

| 智能体 | 主要用户根与项目来源 | 原生调用／刷新提示 |
| --- | --- | --- |
| omp 18.12.2 | `~/.omp/agent/skills`；命名 profile 使用 `~/.omp/profiles/<name>/agent`。遵循 `PI_CONFIG_DIR`、默认 profile 的 `PI_CODING_AGENT_DIR`、`OMP_PROFILE`／`PI_PROFILE` 及 lyrel 配置的启动选择器；同时发现 `.agent[s]/skills`、已安装包和 Skillshare 锁指向的包。原生根只发现一层 | `/skill:name`；在原生智能体启动时发现，来源开关与名称过滤仍由 omp 管理 |
| pi 1.3.0 | `$PI_CODING_AGENT_DIR/skills`，默认 `~/.pi/agent/skills`；`.pi/skills`、`.agents/skills`、配置的技能路径及已安装包。递归发现，项目资源受原生信任控制；没有 omp 的 profile 概念 | `/skill:name [args]`；`/reload` 刷新资源 |
| Kimi Code 2.2.0 | `$KIMI_CODE_HOME/skills`，默认 `~/.kimi-code/skills`；`.kimi-code/skills`、`.agents/skills`、`extra_skill_dirs`；`--skills-dir` 替换自动目录。支持平铺 `.md` | `/skill:name` 或 `/name`；新增技能在新会话可用 |
| OpenCode 2.0.32 | `$XDG_CONFIG_HOME/opencode/skills`，默认 `~/.config/opencode/skills`；显式配置根为 `$OPENCODE_CONFIG_DIR/skills`。同时读取 `.opencode/skills`、兼容共享来源、平台系统来源及 `opencode.json(c)` 的额外本地路径。在线目录不会因只读浏览而自动下载，相关限制会报告 | `@skill-id` 或模型的 `skill` 工具；每个模型步骤刷新列表，不假定存在技能专用重载命令 |

来源记录只读兼容 skills CLI 1.7.2：用户级 v3 `.skill-lock.json`（含 `XDG_STATE_HOME/skills` 路径）及项目级 v1 `skills-lock.json`。记录只会绑定到对应共享目录的真实安装，不因名称相同而套到私有副本；损坏或未知版本不会重写。声明来源不代表 lyrel 已在线核验其内容。

扫描在后台执行。刷新期间可保留旧快照，显示原有扫描时间；断连、权限不足和部分来源失败不会被显示为新的完整成功。切换机器、项目、离开页面及重新打开设置后，旧请求结果不能覆盖新范围。缓存仅属于当前设置会话，不复制原生配置或技能到 lyrel 持久化目录。
一次快照最多保留 2,000 个安装与 32 MiB Markdown，单文件上限 1 MiB；目录与伴随文件遍历也有总上限，触及时显示不完整状态。OpenCode 的系统目录依据所选 Host 生成的 `LYREL_HOST_OS` 元数据区分平台，旧服务端未报告时明确提示升级，不采用桌面本机的平台作猜测。

## 搜索与编辑

搜索可匹配设置名称、描述、英文别名，以及 `mouse_zoom_modifier` 等配置键。结果按分区分组，可直接编辑；点击分区名称即可打开该分区。按 ⌘F（Ctrl+F）可跳转到搜索框。

使用**仅显示已修改项**可查找与默认值不同的设置。已修改的设置会在名称旁提供**重置**操作；安装和维护操作不提供通用的重置功能。

普通控件会自动保存。文本字段会在按下 Enter 或焦点离开字段时提交有效值。自定义主题的编辑在保存前仅作预览；取消会恢复原始主题。SSH 主机也需要显式保存。

录制已被其他操作使用的键盘快捷键时，会先询问是否接管：**替换**会将快捷键移交给当前操作，**取消**则让两个操作都保持原样。
离开已编辑的表单时，会提示保存、放弃更改或继续编辑。

## 原生历史统计

从**设置 → 统计**进入，或搜索「统计」「Token」「omp」「Kimi」。先选择本机或已连接远端；
选择不会随当前 SSH 工作区隐式改变，一次只展示一台机器。「智能体来源」可选择全部智能体或单个有效来源；一个来源发现失败不会清空其他已读取来源，失败原因显示在来源诊断中。
范围支持今天、本周、本月、本年、全部与自定义日期（`YYYY-MM-DD`，包含两端）。
所有日期按桌面本机时区的日历边界解释，星期一为周起点；快照显示时间、时区与实际结果范围。
本周／本月／本年比较截至当前日期的对应前期；全部不制造基期，无有效分母时显示「不可比较」。

数据读取正式 omp `18.12.1` 的原生 JSONL，包括其他终端产生的可发现历史，
并遵循所选 Host 的有效 home、`OMP_PROFILE`／`PI_PROFILE`、`PI_CONFIG_DIR`、
`PI_CODING_AGENT_DIR` 及 `agent_launch.omp` 的明确作用域与绝对 `--session-dir`。命名 profile 不读取默认 profile。
macOS／Linux 的已存在 XDG 数据／状态目录按上游规则解析；自定义文件通过原生
`custom-session-files` 和 `terminal-sessions` 标记发现，不猜测任意项目路径。
相对路径依赖原生 cwd 而无法核实时明确报错，不借用 GUI home。
远端复用 Host 文件操作与非秘密环境元数据；旧 server 缺能力时要求升级，不回退本机。

Kimi Code 使用正式 `2.2.0` 的 protocol `1.5` durable `usage.record`，
只读取所选 Host 的有效 `KIMI_CODE_HOME`（优先采用 `agent_launch.kimi` 中的明确选择），
缺省为该 Host 的 `~/.kimi-code`，不读取旧产品 `~/.kimi`。
显式空值／相对 home 缺少原生 cwd 时拒绝，不回退 daemon 或桌面默认目录。
会话元数据接受 `state.json` 与 `session-meta/state.json` 的第一方读取顺序，
逐个读取 `agents/*/wire.jsonl`，不会把 session index 当作用量文件。

第一方 `UsageAgentModel.record()` 直接持久化本次请求的 `input.usage`，
`usageScope` 仅区分 turn 请求与 operation 请求；`status().total` 累加两种 scope。
因此 `turn`、`session` 和缺省 scope 都按单次增量计入，不能将 `session` 行误认累计值而跳过。
Token 分别取 `inputOther`、`output`、`inputCacheRead`、`inputCacheCreation`，缺项保留未知；
原生 wire 没有费用，显示未计价，不根据模型名或 Token 推算。

Kimi 主会话、子代理与 child 会话分别识别：非 main agent 和 `custom.parent_session_id`
标记的 child 不计主会话，但其可核实新增用量计入总量。
fork／child 逐个 agent journal 以最后一条可靠 `forked` 标记切除继承前缀；
标记之后新建的子代理仅在 journal 的原生创建时间严格晚于 fork 创建时间时确认为新增。
缺少可靠边界显示受限，不全额累加或静默当作零。空 fork 不根据继承的 `updatedAt` 计作活跃会话。
wire 没有独立请求 ID，不能按 turn、模型、时间或相同 Token 合并真实的多次调用；
重复发现的同一原生 session／agent journal 按持久位置去重，并保持 Host／agent／有效 home 隔离。

### OpenCode 2.x

来源下拉可选全部、omp 或 OpenCode。OpenCode 适配依据正式 `2.0.32` 的公开
`experimental.session.stats`、`session.list` 和 `session.message.list`，不扫描旧 SQLite。
打开的原生 TUI 使用已认证、有界的只读客户端桥；没有绑定客户端时使用配置的
`agent_launch.opencode` 和所选 Host 的 home／环境调用正式 `opencode api`。
绑定来源断连、认证不足或服务身份变化只显示诊断，绝不借用另一默认服务。
远端要求独立能力 `opencode-statistics-v1`；旧 server 必须升级，不能回退本机。

分页遵循不透明 `cursor.next`，消息页上限 200，会话页 100；重复游标、分页字段缺失、
5,000 个会话、50,000 条计量消息、约 4 MiB 计量投影或查询期限均标记不完整。
服务端聚合作为独立覆盖检查，不与逐消息数据相加。日期筛选和日界使用桌面日历时区。
Token 总量为 input + output + reasoning + cache.read + cache.write；推理单列，
不重复加到 output。子代理用量计入总量，但 `parentID` 子会话不计主会话；
原生分叉是独立主会话，复制的旧消息按 `fork` 与原生创建时间守卫排除。
活动计数只采用 user／assistant 消息；不将无消息的创建事件伪装成活跃会话。
Host、服务 pid／公开 URL、有效 home／存储选择器共同隔离来源；缓存不含客户端认证材料。
压缩请求的公开 `compaction` 消息若携带 Token／费用，也纳入真实用量；但该响应只提供
消息创建时间，不能核实原生 `usageRecorded` 事件的完成时间，因此明确标记日期归属受限。
服务端聚合还交叉核对 Token 各分项、费用与 assistant steps；不一致不会显示完整成功。

正式契约：[会话与统计](https://github.com/anomalyco/opencode/blob/v2.0.32/packages/protocol/src/groups/session.ts)、
[消息分页](https://github.com/anomalyco/opencode/blob/v2.0.32/packages/protocol/src/groups/message.ts)、
[统计与分叉守卫](https://github.com/anomalyco/opencode/blob/v2.0.32/packages/core/src/session/stats.ts)。

### 统计口径与缓存

主会话按范围内活动计数，独立分叉仍计主会话；原生 artifact 子会话不计主会话，
但可核实新增 Token 与费用计入总量。重复副本与可解析 `parentSession` 链的继承记录去重；
同名 ID 在不同 Host／有效配置作用域中保持独立。继承关系未知、坏文件、权限失败、
链接遗漏或扫描上限均显示受限状态，不冒称完整。分项缺失显示未知，与有效零不同。

费用只采用记录中的有效 USD 费用，包括零；缺失费用显示未计价调用数，
已知费用仅为小计，不是服务商账单、余额或套餐额度。本页不联网查询价表，不推算缺失费用。
平均 Token 包含子代理用量，分母是活跃主会话；结果不完整或分母无效时不显示精确平均值。

扫描、解析与聚合在后台执行；按机器及来源缓存结构化计量，未变文件无需重解析。
缓存只在当前设置会话内保留，不写提示词、对话正文或凭据到磁盘。
刷新失败时保留带时间的旧结果并明确标为过期；切换机器／范围或离开页面后，晚到结果不会覆盖新选择。
当前扫描上限为 5,000 个文件、20,000 个目录、单文件 16 MiB、每轮变更读取 256 MiB。
未实现的其他智能体与价格管理不提供成功占位。
Kimi 元数据单文件上限 256 KiB、durable 单行上限 256 KiB；其他文件／目录／字节上限同上。
旧版／未知 protocol、坏行、截断和不可核实继承均显示诊断，不影响其他可读 agent。

原生格式与目录依据：[会话契约](https://github.com/can1357/oh-my-pi/blob/v18.12.1/docs/session.md)、
[配置作用域](https://github.com/can1357/oh-my-pi/blob/v18.12.1/docs/config-usage.md)、
[目录实现](https://github.com/can1357/oh-my-pi/blob/v18.12.1/packages/utils/src/dirs.ts)。
Kimi 口径依据：[正式 2.2.0 分发包](https://unpkg.com/@moonshot-ai/kimi-code@2.2.0/dist/main.mjs)
中的 `usageAgentModel.ts`、`sessionUsageService.ts`、`appendForkedMarker()`、`sessionMetaSchema`；
独立样本来自 [ccusage 原生 wire 样本补丁](https://github.com/ccusage/ccusage/commit/69fbca0f1d3fd691c89ad892dc54a8f7583fd1f3)，
但不采用该第三方跳过 session-scope 的错误口径。
确定性文件／Host 测试不等于真实 SSH 或桌面视觉验收；Windows／macOS 实机、真实 SSH、
窄窗口、主题、界面放大和键盘流程的实际验收证据须分别记录。

### 活动热力图与分解明细

「活动与明细」直接使用同一快照与去重口径；只展示已发现真实来源中的智能体。
「分析智能体」仅筛选分析区域，上方总览保持其原有机器／来源范围。年度热力图可切换
Token、历史记录费用、活跃主会话；指标只改变图格深浅，日期详情始终保留全部指标。
年度切换只改变日历，智能体／常用模型／常用项目明细仍覆盖完整所选日期范围。

每月从星期一开始，日期边界和日期说明均使用桌面本机时区，不使用远端机器时区。
选择日期或将焦点移入日历后，可用方向键按日／周移动，Page Up/Down 按月移动，
Home/End 到年首／年尾，Enter 展开详情，Escape 隐藏详情，再按可关闭设置。
当前日期及完整数值有常驻说明，不依赖悬停；月份自动换行，控件跟随界面字号缩放。

图例深浅按本年、所选范围和智能体筛选中的已知最大值解释；`?` 为未知／不完整，
`–` 为范围外，范围外不代表零活动。费用图格仅使用完整记录费用，不将估算、未计价

今天没有活动时，当前连续天数可从昨天开始。不完整来源不构造连续天数。
没有可靠活动时间的累计记录只在「全部」范围保留可得总量；有边界的范围与日格显示未知，
不把占位时间解释为真实日期。所选智能体在当前机器没有已发现来源时也明确提示来源缺失，
不会回退其他来源或显示为零活动。

元数据、不能可靠分摊到逐次模型时，保留为「无法归属」模型用量，而不是伪造模型排名。

分解保留智能体、来源作用域和模型提供商身份；缺少项目或模型时显示「无法归属」，
不静默丢弃。已知 Token 总量降序排列，未知值不参与排名；每页可查看十条完整明细并翻页。
同一主会话可能跨日期、模型或项目参与，因此这些会话数不可相加；子代理用量计入用量，
但不增加主会话数。原生副本和可核实继承记录先由总览共用的唯一算法消重，再执行日期／模型／项目分解。
刷新期间保留带快照时间的旧结果，扫描诊断及不完整状态仍可见。

## Hermes 原生历史统计

「设置 → 统计」可筛选 Hermes 或全部来源，并固定选择本机或远端机器。有效 home/profile
复用已配置的 Hermes 启动命令与 Host 环境，不读取另一机器的默认 profile，不猜测系统 Python。
仅通过 Hermes 0.22.2 正式 launcher 的 `--print-runtime-command --module tui_gateway.entry`
查询 `projects.tree`；远端需要独立的 `hermes-statistics-v1` 能力，旧 server 明确要求升级。
统计响应在数据所属 Host 剔除 `title`／`preview`，不为统计传输会话标题或提示词片段；仅缓存结构化计量元数据。

仅纳入 `source=cli` 的原生持久会话。正式项目路径用于项目归属，无项目进入 Home 桶；
可见 branch/reset 是独立主会话，compression 谱系已由上游合计，重叠谱系不会重复计费。
输入、输出与总 Token 保留有效零，缺失项仍未知；实际 USD 和原生估算 USD 分别展示，
估算不是账单，二者不能相加，也不以估算替代实际费用。

接口只有会话累计用量，没有逐消息日期：仅当选择范围覆盖整个会话活动区间才纳入累计值。
与范围相交却跨界的累计值不分摊、不归到最后一天，而是显示不完整；全部范围仍保留可得用量。
缺少可靠活动日期时，已知 Token 和费用仍保留在「全部」范围；有限日期范围显示受限，不虚构日期或单日会话活动。
调用数表示计量记录，Hermes 累计记录不等于模型请求次数。

每次最多请求 501 个会话元数据，达到全局／项目预览边界会显式提示无 offset/cursor，
不将有限窗口冒充全部历史。公开接口排除子代理用量、归档、零消息与自动任务，故总量始终受限。
成功空响应不能区分空历史和 profile 数据库不可用，显示未知诊断而非完整零值。
一个来源失败不会清除其他来源；读取失败保留对应来源带时间的缓存，不回退默认 profile。

正式响应依据：[projects.tree](https://github.com/NousResearch/hermes-agent/blob/v0.22.2/tui_gateway/methods_config.py)、
[会话投影和可见性](https://github.com/NousResearch/hermes-agent/blob/v0.22.2/tui_gateway/methods_projects.py)。

<a id="the-settings-file"></a>
## 设置文件

设置窗口写入的所有设置都保存在同一个文件中：

| | |
|---|---|
| macOS / Linux | `~/.config/lyrel/config.json` |
| Windows | `%APPDATA%\lyrel\config.json` |

SSH 主机单独保存在同一目录下的 `servers.json`。[servers.json →](/reference/configuration#ssh)
用量账户的非秘密元数据与快照保存在 `usage-accounts.json`；API key 仅保存在桌面本机系统凭据库的 `lyrel-usage` 服务中，不随配置同步。

可通过 `--config-dir` 或 `LYREL_CONFIG_DIR` 将整个目录（包括配置、主题和状态）移至其他位置。配置目录的优先级为：`--config-dir` > `LYREL_CONFIG_DIR` > Windows 便携模式的 `data` 目录 > 平台默认目录。

你可以手动编辑此文件；少数选项只能在文件中设置。有关每个配置键、类型及默认值，请参阅[配置参考](/reference/configuration)。

<a id="how-it-handles-mistakes"></a>
### 如何处理错误

文件以原子方式写入，读取时则采用宽容处理：

- **缺少配置键**时使用默认值，因此只需写入要修改的设置。
- **数值超出范围**时会被限制在允许的范围内，而不是被拒绝。
- **无法识别的枚举值**会回退到默认值并记录一条日志，而不会导致整个文件加载失败。
- **无法解析的文件**不会被覆盖。lyrel 会使用默认值启动，将副本保存在 `config.json.corrupt`，并在日志中说明情况。

<Note>
  文件开头允许存在 UTF-8 BOM；如果你使用 Windows 编辑器编辑过文件，这一点尤为重要。
</Note>

<a id="language"></a>
## 语言

**设置 → 通用 → 语言**提供「跟随系统」「English」「简体中文」三种选择，实际翻译只有英文和简体中文。新配置或未设置 `gui_language` 时默认跟随系统；手动固定的语言优先于系统。

跟随系统读取 Windows 的最高优先界面语言或 macOS 的首选界面语言，不读取 shell 的 `LANG`／`LC_*`。明确 `Hans` 脚本使用简体中文；未指定脚本时，`CN`／`SG` 地区使用简体中文。显式脚本优先于地区，所以 `zh-Hans-TW` 使用简体中文、`zh-Hant-CN` 使用英文。繁体、裸 `zh`、其他语言或读取失败均使用英文。

切换选择后界面立即更新，并保存选择模式；`system` 不会被当时解析出的语言覆盖。下次启动重新读取系统偏好，运行期间不监听系统语言变化。已有明确保存的 `en`／`zh-CN` 保持原选择；旧日语、俄语和其他无效值回退英文，其他配置继续加载，仅加载不强制重写配置文件。

设置、应用菜单、托盘和已注册的 Explorer 菜单标签随语言更新；这不会新增 Explorer 菜单注册。CLI 输出始终保持英文，shell 字符环境、终端文字、编程语言与 LSP 行为不变。

```json
{ "gui_language": "system" }
```

## DeepSeek 用量账户

从**设置 → 用量**进入，或搜索 `DeepSeek`、余额、会话、浏览器、`LocalStorage`。点击**添加账户…**，输入便于区分的名称，在 **DeepSeek 认证来源**选择官方 API key、手工平台会话或浏览器 LocalStorage，再点击**验证并保存**。
lyrel 从桌面本机请求 [DeepSeek 官方余额接口](https://api-docs.deepseek.com/api/get-user-balance)：`GET https://api.deepseek.com/user/balance`，认证为 `Authorization: Bearer <API key>`。仅验证成功才写入系统凭据库；不会读取智能体或远端机器的密钥，不导入 vortex 数据。

余额保留接口返回的 CNY／USD 金额字符串，分别显示总余额、赠送余额、充值余额与更新时间，不换算币种、不伪造百分比。接口不提供用户姓名、邮箱、账单周期或重置时间，因此页面使用自定义名称及稳定的本地账户 ID 区分账户，不冒称已确认服务商用户身份。

每个账户可重命名、停用／启用刷新、替换来源、手动刷新及移除。相同名称不会合并账户。替换时先验证；长期秘密写入全新凭据槽，浏览器来源只保存非秘密引用。认证、读取、凭据库或本地保存失败均保留旧来源及旧快照，不切换到其他账户。移除仅清理所选本地查询账户、快照及自己的凭据槽，不注销 DeepSeek 账户、浏览器登录态或撤销 API key；清理失败可重试移除。

默认仅手动刷新，可选择页面可见时每分钟或每 5 分钟刷新。应用启动不查询；离开用量页、进入搜索或关闭设置后，不再启动新的周期请求。已经发出的请求可以收尾，但不得重新启动轮询或恢复已移除／旧凭据的账户状态。请求使用 lyrel 的代理解析规则，连接超时 10 秒、总超时 30 秒，并拒绝重定向以避免认证材料发往其他来源。

认证失败、限流、网络、服务响应结构、系统凭据库和本地保存错误分别显示。刷新失败保留旧快照并标注其时间与状态，不将未知余额填为零。没有授权的真实 DeepSeek 账户时，受控响应测试不能证明真实账户或系统凭据库集成已验收。

### 私有平台手工会话

选择**私有平台 · 手工会话**后，从 `https://platform.deepseek.com` 的开发者工具 → Application／Storage → LocalStorage 复制 `userToken`，可粘贴裸值、`userToken=…`／`user_token=…`、对应 JSON，或仅请求平台固定汇总端点的 Bearer cURL。lyrel 不执行 cURL，不接收 Cookie 头、其他站点请求或官方 API key 作为平台会话。只保存解析出的必要 token，不保存整段粘贴内容。

私有查询固定为 `GET https://platform.deepseek.com/api/v0/users/get_user_summary`，钱包按 `normal_wallets`（充值）与 `bonus_wallets`（赠送）分开保留原币种、金额字符串，包括 `0E-16`；不相加冒充官方总余额、不换算历史费用，也不推测用户身份或周期。平台会话是私有兼容入口，不代表 DeepSeek 官方支持。

DeepSeek 第一方 [deepseek-harness 凭据源码](https://github.com/deepseek-ai/deepseek-harness/tree/687f282e8625c6b8d11ff58211a90524be2e4317/packages/credentials/deepseek-account-platform/src) 的 Harness grant 与网页 token 不是同一种来源：grant JSON 必须含 `version: 1`、`token` 和精确 `issuer: "https://platform.deepseek.com"`，也接受官方 `{kind:"grant",payload:{…}}` 包装；验证 issuer 后用 `x-dsh-auth-token` 发送，仅将 token 长期存入系统凭据库。网页 `userToken` 则使用 Bearer。后者仅有第三方兼容实现佐证，本次无认证读取平台页面均返回 HTTP 429，尚未取得第一方 Web JS 或授权真实账户的有效性证据，不能据受控测试声称真实平台集成通过。

### 主动选择浏览器与 profile

选择**私有平台 · 浏览器 LocalStorage**，先选择 Chrome、Edge、Brave、Chromium 或 Firefox，再选择明确的 profile，最后点击**验证并保存**。发现 profile 时只读所选浏览器的元数据；不扫描所有浏览器登录态、不自动验证候选。实际读取仅查询所选 profile 的精确 `https://platform.deepseek.com` origin 与 `userToken` 键，不读取 Cookie、其他服务商或刷新 token。只读数据库锁定、访问拒绝、格式不支持、profile 消失和会话失效分别显示，不会改用另一来源或当作零余额。

Windows／macOS 的 Chromium 系支持现行 LevelDB LocalStorage；恢复在内存文件系统中完成，不写秘密数据库临时副本。Firefox 支持现行每 origin SQLite、UTF-8／UTF-16 与 Snappy 压缩，并保留已提交 WAL 的读取语义。Safari、Firefox container origin 和 Chromium 新 SQLite LocalStorage 后端不支持，不绕过系统保护；浏览器版本变化可能使导入不可用，可改用手工会话。

浏览器 token 只在请求期间驻留内存，材料类型不能序列化或调试输出，离开请求后释放；不写系统凭据库、配置、快照、日志或临时文件。持久化仅含浏览器、profile ID／显示名称，以及路径和原 token 的 SHA-256 绑定指纹，不含原始路径或 token。每次刷新重新读取同一 profile，后台从不请求系统权限；来源或 token 改变时保守要求主动重新导入，无法确认同一服务商身份时绝不静默接受另一账户。

真实浏览器导入需要用户对目标浏览器、profile 与平台账户的明确授权。本次开发只使用临时 LevelDB／SQLite 样本和回环 HTTP，未获读取真实浏览器及查询真实 DeepSeek 平台账户的授权；Windows／macOS 实际浏览器、系统凭据库与真实平台查询仍须分别验收。
