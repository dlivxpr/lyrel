**设置 → 外观 → 主题**，或全局搜索中的**更改主题…**，均可打开主题选择器。

<a id="built-in"></a>
## 内置主题

| 浅色 | 深色 |
|---|---|
| 浅色 *（默认）* · One Light · Catppuccin Latte · Rosé Pine Dawn | 深色 · Dracula · Harbor · One Dark Pro · Rosé Pine · Catppuccin Mocha · Gruvbox Dark · Nord · Tokyo Night |

<a id="following-the-system"></a>
## 跟随系统

开启**与系统同步**，并分别为浅色和深色外观选择主题。lyrel 会实时跟随操作系统切换，无需重启或重新加载。

```json
{
  "theme_follow_system": true,
  "theme_preset_light": "one_light",
  "theme_preset_dark": "dracula"
}
```

<a id="legible-bright-colours"></a>
## 清晰可辨的亮色

有些调色板中的 ANSI 亮色与背景色过于接近，导致难以辨认。**提高亮色可读性**（默认开启）会适度调亮或调暗这些颜色，使其清晰可辨。如果希望完全使用作者原定的调色板，可设置 `theme_legible_palette: false` 关闭此功能。

<a id="transparency"></a>
## 透明效果

**设置 → 外观 → 透明效果**：

| | |
|---|---|
| **不透明度** | 0.2–1.0，应用于所有主题。选择*跟随主题*时，使用主题自身的 `opacity` 值。 |
| **模糊** | 模糊半透明窗口后方的内容（macOS）。 |
| **背景材质** | 仅限 Windows：*自动*、*模糊*、*Mica*、*Mica Alt*、*Acrylic*、*关闭*。仅列出当前 Windows 版本支持的预设。 |

终端和两侧栏共用一个原生窗口材质。选择半透明时，侧栏仅叠加当前主题的轻量底色，不再独立保持不透明；没有左右侧栏各自的模糊设置。不透明度为 `1.0` 时，窗口内容与侧栏真正不透明。设置、文件和 diff 等覆盖层仍保持不透明，以保证内容阅读。

切换材质不重置主题、字体或不透明度。不透明度依次采用手动设置、主题的 `opacity`、默认值。Windows 显式选择可用材质且未设置不透明度时，默认使用 `0.82`；*自动* 保留原有默认行为，不会在更新后自动变透明。macOS 的模糊开关保持本地控制，不受从 Windows 同步的材质选项影响。

Windows 材质由 DWM/WCA 提供，macOS 模糊由原生合成器提供；Mica 与实时桌面模糊不同，也不等同于浏览器的模糊半径或饱和度。透明度较低或背景图片对比强烈时，请在实际桌面背景上检查文字与焦点的可读性，必要时自行提高不透明度；应用不会暗中改写你的透明度配置。Windows 与 macOS 的实窗验证结果必须分别记录，不能互相替代。

<a id="writing-your-own"></a>
## 编写自定义主题

设置中的**打开主题文件夹**会打开当前配置目录下的 `themes` 文件夹。默认路径为：

| | |
|---|---|
| macOS / Linux | `~/.config/lyrel/themes/` |
| Windows | `%APPDATA%\lyrel\themes\` |

配置目录的优先级为：`--config-dir` > `LYREL_CONFIG_DIR` > Windows 便携模式的 `data` 目录 > 平台默认目录。

将 `.yaml` 文件放入其中，主题就会出现在选择器中。文件名是主题的 ID；`name` 是显示名称。

```yaml
name: "午夜"
background: "#0d1117"
foreground: "#c9d1d9"
accent: "#3fdd8c"
cursor: "#3fdd8c"
selection: "#264f78"
opacity: 0.95
blur: true
ansi:
  normal:  ["#484f58", "#ff7b72", "#3fb950", "#d29922", "#58a6ff", "#bc8cff", "#39c5cf", "#b1bac4"]
  bright:  ["#6e7681", "#ffa198", "#56d364", "#e3b341", "#79c0ff", "#d2a8ff", "#56d4dd", "#f0f6fc"]
```

除 `background`、`foreground`、`accent` 和 `ansi` 外，其余字段均为可选。

<a id="gradients-and-images"></a>
### 渐变和图片

`background` 也可以接受两种颜色：

```yaml
background: { top: "#0d1117", bottom: "#161b22" }
# 或
background: { left: "#0d1117", right: "#161b22" }
```

主题还可以在终端背后显示图片：

```yaml
background_image:
  path: "/Users/me/Pictures/wall.jpg"
  opacity: 0.25
```

设置面板为这两项都提供了选择器，因此通常无需手动编写配置。

<a id="editing-in-the-app"></a>
## 在应用内编辑

选择一个内置主题，然后点击**创建副本以编辑**。内置主题为只读，因此编辑器会修改你的副本。在编辑器中，你可以调整所有颜色，包括十六个 ANSI 色位，以及背景图片。

颜色和图片编辑先作为当前设置会话的草稿实时预览，不会在每次调整时写文件；点击保存后才将草稿以 YAML 写回主题文件夹。放弃会恢复开始编辑时的主题；将值改回原值也会清除该草稿的未保存标记。保存失败时保留草稿和错误，修正问题后可重试。离开有未保存修改的页面、切换主题或关闭设置时，仍由设置窗口统一询问保存、放弃或继续编辑。

主题草稿由 `settings::theme_edit::ThemeEditing` 直接持有，颜色、图片、脏状态、保存、放弃以及延迟选择结果的有效性在同一所有者中处理。`SettingsWindow` 负责 GPUI 输入订阅、原生文件选择器和配置／主题应用的适配；工作台交互继续沿用现有设置桥与 `SettingsEvent`，不创建第二套配置应用路径。主题注册表中的预览通过既有全局主题应用更新窗口；只有主题草稿保存才写主题文件，模式和主题选择仍按原时机保存配置。通用字体菜单与跨页弹出菜单不属于主题草稿；主题切换不重置字体或界面语言，`System` 仍只表示跟随系统外观。

颜色控件重建、主题切换、图片选择被替代、放弃或离开页面后，已失效的选择结果不会再写入草稿；关闭并重新打开设置会创建新的主题编辑会话，旧会话的图片选择结果不能作用于新会话。原生文件选择器的显示与焦点由现有窗口适配保留，不由主题状态创建额外窗口或 Entity。

<a id="importing-from-iterm2"></a>
## 从 iTerm2 导入

将 `.itermcolors` 文件放入主题文件夹，lyrel 即可直接读取，无需转换。

<Note>
  lyrel 无法加载的主题文件会列在设置中的**未能从主题文件夹加载**下，并显示原因，而不会被静默忽略。
</Note>
