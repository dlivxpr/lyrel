<kbd>⌘ J</kbd>（Windows：<kbd>Ctrl ⇧ J</kbd>）可打开窗口右侧的面板。面板默认隐藏；下次打开时，会回到上次停留的选项卡。

窗口右上角的圆角组依次为向右分屏、向下分屏、面板开关；面板收起时仍常驻，不与 Windows 原生窗口按钮或 macOS 交通灯重叠。信息、文件、更改、GitHub 位于下方独立页签行，当前项以正文色与 medium 字重区分。拖动面板左边缘调整宽度，悬停不显示蓝色边线。

<a id="info"></a>
## 信息

lyrel 掌握的有关当前聚焦窗格的所有信息，集中在一列中：

| 区域 | 显示内容 |
|---|---|
| **会话** | 工作目录、shell、SSH 连接、git 分支、`+N −M` 更改，以及编程智能体及其状态（空闲 / 工作中 / 等待中 / 已完成） |
| **进程** | 窗格内的进程树，并标记前台进程 |
| **端口** | 这些进程正在监听的所有端口 |

将鼠标悬停在某一行上时，该行右端会显示可用操作：工作目录、SSH 主机和分支旁会显示**复制**；对于本机可访问的工作目录，还会显示**在 Finder 中显示** / **打开文件夹**。点击 `+N −M` 计数可打开[差异浮层](/git/diffs)，与点击侧边栏中的计数效果相同。

原生 SSH 连接没有报告远端登录 shell 时，shell 行显示 `—`，不会把本机默认的 PowerShell 等程序显示为远端 shell。

端口区域能最快回答“这个窗格正在提供什么服务，地址在哪里”——它与 `lyrel procs` 输出的数据相同。点击端口行可复制 `localhost:PORT`；对于本地窗格，还会在浏览器中打开该地址。

<a id="files"></a>
## 文件

本机文件树按当前标签页各窗格的项目目录聚合：仓库内使用仓库根，仓库外使用工作目录。远程工作区的文件树则跟随当前前景终端的实际工作目录，包括同一仓库内的子目录；切换窗格会切换浏览根目录。路径和文件操作始终交给该工作区的 Host，远端 POSIX 路径不会按 Windows 盘符或反斜杠改写。每一行都带有 git 状态标记，顶部有一个搜索框。搜索框中有内容时，会显示清除按钮。

- **点击文件**，在内置编辑器中打开它。
- **Ctrl 点击**切换多选（macOS 使用 Cmd），**Shift 点击／方向键**选择连续范围；修饰键选择不会打开文件或展开目录。普通点击恢复单选。
- **Ctrl+C／Ctrl+V**复制、粘贴实际文件和目录（macOS 使用 Cmd）；也可使用右键菜单。右键已选项保留集合，右键其他项先改选。删除键批量删除（macOS 使用 Cmd+Backspace），确认框列出数量、所属主机与完整目标；祖孙重复选择只处理最外层目录。
- **将文件拖出**到 Finder 或 Explorer，将其复制到那里。
- **从桌面拖入文件**，将其复制到光标下的文件夹中。拖到文件夹行上会复制到该文件夹；拖到文件行上会复制到该文件所在的文件夹；拖到文件树下方的空白区域则会复制到文件树的根目录。文件夹会完整复制，可执行位会保留；如果名称已被占用，会先询问，而不是直接替换。

这两个方向也都适用于[远程工作区](/remote/workspaces)：在一台机器上读取，在另一台机器上写入，大小上限为单个控制帧所能承载的数据量——超出后，面板会提示你使用 [SFTP](/remote/sftp)。

### 文件树职责与刷新规则

`FileTreeState` 是窗口内文件树的唯一状态所有者。其私有 `src/ui/file_tree/lifecycle.rs` 集中处理目录结果、进行中的加载、监视失效、仓库根目录与真实路径别名、乐观写入结果，以及“随处搜索”的文件索引生命周期。目录缓存始终按 `HostId` 和路径区分；不同机器上的同名路径不能互相覆盖。工作台只提供当前 Host、标签页和窗格的 `files_cwd`，接收刷新决定，并执行打开文档、更新编辑器路径、跨能力导航与最终焦点交接；编辑器不直接修改文件树编辑状态，搜索也不直接修改索引缓存。

目录加载、仓库探测、监视建立／更新和文件操作继续通过 `HostOps` 在后台执行，由原有 Host 抽象决定本机或远端位置。GPUI 完成回调只把结果交回所有者，再通知界面或执行导航，不持有另一套缓存。刷新保留已有列表；如果加载期间又发生失效，已返回的快照仍可显示，并在对应 Host 仍处于活动状态时调度下一次加载，不一律丢弃旧结果，也不先清空可用目录。

折叠目录停止监听后，其缓存不再代表最新磁盘状态；重新展开会保留原列表并立即重新列举。活动标签页／Host 切换时重新同步监听，监听建立后补读目录以覆盖建立窗口内的写入；已退役连接的迟到监听结果不能接管当前连接。同一防抖窗口内的不同 Host 事件分别处理，目录级通知也会使其子项列表失效。

创建、重命名和删除保留乐观显示。成功后使对应目录失效；失败时移除猜测的目录快照、显示原有错误并重新列举，而不是把旧快照恢复到较新的列表之上。复制只在确实有文件写入时使目标目录失效，名称冲突仍先询问。

浏览根目录和搜索范围有意不同：远程工作区浏览跟随当前前景终端，但内容搜索仍聚合标签页各窗格的仓库根目录（仓库外使用工作目录），不会因进入子目录而缩小项目搜索。文件树在没有窗格项目目录时只可回退到本机 `HOME`，不会用本机 HOME 代替远端目录；内容搜索不继承这项回退。“随处搜索”的文件索引还会排除 `HOME`、文件系统根目录和被外层根目录覆盖的子目录。路径显示由文件树所有者按 Host 和项目根目录解析别名，编辑器仍使用规范路径标识文档。索引刷新失败会保留同一范围内已有的可用结果；较早的索引任务不能覆盖后来发起的任务。

### 文件浏览的原生验收

以下场景需在隔离配置和临时工作区中实际执行；它们是职责迁移的待执行验收，不表示已经通过。Windows 与 macOS 分别记录；远端场景需要独立测试 SSH Host，不能用本机同名路径代替。

1. 展开有子目录的项目，在加载期间持续创建、重命名文件。确认可用列表没有先被清空，最后能显示最新结果；切换标签页和 Host 后检查同名路径保持独立。
2. 创建文件并确认编辑器打开；成功重命名后检查已打开文档继续对应新路径。对临时的不可写目录执行操作，确认保留错误提示、移除乐观猜测并恢复真实目录内容。
3. 打开文件、文件搜索结果和带行列号的搜索结果，核对文档内容、树定位及焦点交接；在无项目目录时检查浏览回退不会自动扩大搜索范围。
4. 在远端工作区重复监视刷新、成功／失败操作及搜索，核对更改只发生在远端，且本机同名文件不变；复制冲突继续先询问。
5. Ctrl／Cmd 切换多个文件与目录，Shift 扩展范围，右键选中项后复制到另一目录；逐字节核对全部目标和原件，名称冲突先取消再确认，确认前不覆盖。
6. 多选父目录及其后代后删除，检查确认数量按最外层目标去重；混合可写／不可写目标时，成功目标删除，失败目标保留并显示路径与原因，根目录不可删。

2026-10-31 的 Windows 隔离实窗已覆盖：本机／普通 SSH 的 Ctrl 多选及两文件批量复制，逐字节核对目标与原件；普通 SSH 批量删除的取消、确认与原件保留；同一 SSH 窗格 `cd` 后目录跟随及外部新建自动显示；本机“文件”和“更改”同时识别外部新文件；“信息”的本机／SSH 目录及 shell 来源；GitHub 实际拉取请求列表和外部修改 remote 后自动切换仓库。普通 SSH 的完整输入／操作使用真实窗口验证，不用合成 pane 的镜像状态冒充原生会话；macOS 原生窗口仍未执行。

<a id="search"></a>
## 搜索

在文件选项卡所显示的项目范围内搜索文件内容：搜索范围是当前标签页中各窗格的仓库根目录；若不在仓库中，则是其工作目录。通过选项卡图标、全局搜索中的**右侧面板：搜索**，或 `ShowRightPanelSearch` 操作打开该选项卡时，光标会自动定位到搜索框。

结果会在输入时实时显示，按文件分组，并显示每个文件的匹配数；点击文件行可折叠该组。每条匹配结果显示其所在行，并高亮匹配内容；**点击结果会在内置编辑器中打开文件，并将光标定位到对应的行和列**。如果文件在此期间发生变化，可在搜索框中按 <kbd>Enter</kbd> 重新搜索。

搜索框末尾有三个开关：

| | |
|---|---|
| **Aa** | 区分大小写——默认关闭，因此 `needle` 也能找到 `Needle` |
| **ab** | 全字匹配——`foo` 不再匹配 `foobar` 或 `foo_bar` |
| **.\*** | 正则表达式，使用 Rust [`regex`](https://docs.rs/regex) 语法。如果表达式无法解析，会以红色显示原因，而不会执行搜索 |

搜索范围与文件树显示的内容一致：无论文件夹是否位于仓库中，其 `.gitignore` 都会生效，并且会跳过点文件和点目录。二进制文件和超过 1 MB 的文件也会被跳过。当达到 2,000 个匹配行、单文件 100 个匹配行、20,000 个文件或十秒中的任一限制时，搜索就会停止，并在结果下方说明——缩小查询范围即可查看其余结果。

在[远程工作区](/remote/workspaces)中，搜索在远程机器上运行，只有匹配结果通过网络传输。如果远程 `lyrel-server` 的版本早于此功能，则无法搜索；选项卡会明确说明并提示更新服务器，而不是显示空结果。SSH 窗格的文件通过 [SFTP](/remote/sftp) 浏览，无法对其执行搜索——如需搜索，请将该主机作为远程工作区打开。

<a id="source-control"></a>
## 源代码管理

当前聚焦窗格所在仓库的 git 面板，分为四组：**合并更改**、**已暂存的更改**、**更改**、**未跟踪**。无需离开窗口即可编写提交消息、提交并推送。

新建或克隆仓库后，进入该工作树，“更改”面板会自动识别，无需退出应用。命令结束、目录变化等事件会触发更新；即使 shell 没有报告命令完成标记，当前可见窗格也会约每 10 秒轻量检查一次仓库位置。嵌套仓库采用当前窗格所在的内层工作树，不继续显示父仓库的更改；位置未变化时，不因此重复扫描完整改动列表。

<a id="github"></a>
## GitHub

以只读方式显示当前聚焦窗格所在仓库的议题和拉取请求。选项卡读取仓库的远程地址，并关联到 `github.com` 上的远程仓库；对于 fork，如果 `origin` 是你的仓库，而 `upstream` 是原项目，则会选择 `upstream`。存在多个 GitHub 远程仓库时，顶部的名称会成为一个菜单，列出所有 GitHub 远程仓库。不支持 GitHub Enterprise 主机。

通过终端添加、修改或删除远程地址后，可见的 GitHub 面板会监视仓库元数据并重新读取 remote 列表，不依赖先打开“更改”页或 shell 的命令完成标记；先执行 `git init`、再添加 GitHub `origin` 也无需重启。没有 GitHub 远程仓库时，空状态中的**刷新**按钮可重新探测当前仓库。GitHub 页的元数据监视本身不会触发完整工作树改动扫描。

- **议题 | 拉取请求**和**开放 | 已关闭**用于切换列表，按最新活动优先排序，每次显示 50 条，下方提供**加载更多**。
- 每行都有一个状态图标，其*形状*表示开放、已关闭、不计划处理、已合并或草稿；此外还显示编号、作者、最后更新时间及标签。**点击标签**可仅显示带有该标签的条目，点击旁边的 × 可清除筛选。
- **点击某一行**可查看详情：标题、状态、作者、标签，以及以 Markdown 呈现的描述和讨论。拉取请求还会显示分支、改动规模和更改的文件——点击文件可在[差异浮层](/git/diffs)中打开其补丁。
- ↗ 按钮会在 github.com 上打开仓库或议题；↻ 用于刷新。

列表按仓库缓存，因此切换标签页或窗格不会重新获取；数据超过两分钟后，只要仍显示在屏幕上，就会在后台刷新。

<a id="signing-in"></a>
### 登录

无需在 lyrel 中另行登录。它会复用 GitHub CLI 的登录凭据：依次从 `GH_TOKEN`、`GITHUB_TOKEN`、`gh auth token` 获取令牌。系统会在 `PATH`、常见的 Homebrew 路径和 `/usr/local/bin` 中查找 `gh`，因此即使从 Finder 打开 lyrel，也能找到它。

没有令牌时，公共仓库仍然可用，但受 GitHub 未认证请求每小时 60 次的限制。对于私有仓库或已耗尽的请求额度，面板会明确说明，并建议运行 `gh auth login`；之后按 ↻ 即可使用新的登录凭据，无需重启。

对于配置了 GitHub 远程地址的仓库，信息选项卡会增加一个 **GitHub** 行。它会在当前分支所跟踪的远程仓库上打开该分支；如果分支尚未推送，则打开仓库页面。

GitHub 上的 Markdown 来自陌生人，因此渲染时有两项限制：只加载由 GitHub 自身托管的图片，例如粘贴到议题中的截图；其他图片会转换为可在浏览器中打开的链接。此外，会禁用所有并非打开网页或电子邮件的链接。参见[哪些数据会离开你的机器](/reference/privacy#what-leaves-your-machine)。

<a id="the-editor"></a>
## 编辑器

<kbd>⌘ ⇧ E</kbd> 可切换代码面板的显示状态；点击文件选项卡中的文件会在此处打开。普通代码提供语法高亮、行列位置和自动换行；Markdown/MDX 默认使用原生即时编辑，保留完整源码模式。

| | |
|---|---|
| <kbd>⌘ S</kbd> | 保存 |
| <kbd>Esc</kbd> | 返回终端 |

编辑器会监视磁盘上的文件：未修改的文档自动载入外部更改；已有未保存编辑时则保留文本并显示冲突，不覆盖你的修改。关闭时存在未保存的编辑，会先询问再丢弃。超过 4 MB 的文件以及看起来是二进制的文件会被拒绝打开并显示提示，而不是勉强打开导致异常。

同一窗口中，同一 Host 上的同一文件在多个标签页之间共享一个 buffer、编辑内容和撤销历史；关闭其中一个展示位置不会丢弃其他标签页仍在使用的文档。不同 Host 上即使路径相同，也保持独立。外部监视只跟随当前工作区 Host 的文件；SFTP 文件仍在保存时检查远端版本，不用本机同名文件代替。文件链接、搜索和前后导航携带的行列位置随打开请求一起保留，已经失效的请求不会落到切换后的标签页或工作区。

实现中，`src/ui/code_editor/buffers.rs` 的 `EditorBuffers` 持有 buffer registry、Host-aware 打开、待定位光标、外部监视和重载规则；标签页只保留展示关系。每个文档分配独立的 `BufferId`，不再借用 `EditorState` 的 entity identity；保存、关闭等待、导航、Git gutter 与 LSP 请求均携带该文档身份，路径或编辑呈现不构成另一条身份通道。普通代码仍由原来的 `EditorState` 编辑。`src/ui/code_editor/saving.rs` 将保存规则、Host 写入、另存为、行内输入条、提示生命周期和 save waiters 的转换集中到 `EditorPanelState`；工作台只通过 `EditorBridge` 取得编辑器所有者并接收 `EditorEvent`，负责文件树／LSP、导航、有效内容焦点及最终窗口操作，不向保存实现交出整个工作台。

关闭文件、窗格、标签页、窗口或应用时，保存成功才允许执行当时捕获的 `AfterUnsaved`。文件关闭还记住原标签页、buffer 和稳定的编辑组身份，而不是左右位置；切换焦点或折叠另一组不改变目标，原组关闭后即使在同一侧重新分组，也不会关闭新组的文档。失败、编码问题、外部版本冲突、取消另存为或重复打开的目标都会撤销原来的等待；之后独立保存成功也不会重新执行那次关闭。冲突时仍显示既有覆盖确认；选择覆盖只保存文档，不恢复已经撤销的关闭。工作区切换会退役旧提示及关闭等待，原文件的已发出写入仍使用它自己的 Host。

### 保存与关闭的原生验收

文档身份解耦已在 Windows 隔离实例中验证普通文本的打开、输入、未保存关闭提示、选择保存、关闭及重开，并核对磁盘内容。此结果不代表下列完整清单、macOS、真实 SSH 或 Markdown 实时编辑已通过验收。

以下步骤需在 `cargo dev` 的隔离配置与临时工作区中逐项实际执行；它们是本次职责迁移的待执行场景，不表示已经通过。Windows 与 macOS 分别记录焦点和窗口行为；真实远端场景需要测试 SSH Host，不能用本机同名文件代替。

1. 打开临时文件，键入 Unicode 文本，保存并重新打开核对内容；有 `.editorconfig` 时确认去尾空白、末尾换行及撤销历史沿用。修改 `LF`／`CRLF` 后保存，核对实际字节。
2. 新建未命名文档，使用本机另存为面板选择目标；在两标签页共享同一文件时，关闭一个展示仍保留另一处编辑与撤销。远端另存为使用路径条，核对写入远端 Host，且本机同名路径不变；输入已有打开文档的路径时保持原文档和提示。
3. 修改文档后从外部重写原文件，执行保存并尝试关闭。确认出现冲突且原关闭停止；取消覆盖保留双方内容，重新保存并选择覆盖后文档仍打开，需要重新发起关闭。
4. 在临时目录选择不可写位置或目录作为保存目标，确认可见失败提示、编辑不丢失，文件／窗格／标签页／窗口／应用的原关闭均不继续；改用有效目标保存后也不应复活旧关闭。
5. 分别在未保存关闭提示、本机另存为、远端替换确认中取消；检查文档或仍有效的当前内容取得键盘焦点。跳转行号与重命名输入条的 Enter／Escape 及前后导航不改变目标文档。
6. 对文件、最后一个窗格、标签页、窗口、退出应用逐一走保存成功、取消与丢弃。保存等待期间切换标签页或编辑组，确认只执行原目标；原 buffer 被关闭／替换或切换工作区后，迟到的路径选择不能保存新文档或关闭新工作区。

### 全局文档状态

窗口底部只有一条全局状态栏，显示当前文档的真实行列、问题、自动换行、Markdown 即时编辑／源码、缩进、编码、换行符与语言。点击行列可跳转；点击问题可展开或收起列表；点击 `LF`／`CRLF` 显式转换文档的换行表示。普通保存始终通过文档所属 Host，远端路径不会按本机路径解析。

文档停靠时，点击旁边终端会让状态栏切回终端上下文；回到文档时恢复当前编辑组的信息。
查看差异时不会显示另一个被覆盖文档的行列与格式。填满工作区仍保留全局设置、随处搜索和时钟入口。
跳转框中按 `Esc` 只关闭跳转框并返回编辑器；文档状态操作完成后焦点回到文档，关闭文档面板则返回终端。
关闭设置后回到实际工作内容：填满窗口的文档恢复文档焦点；停靠布局恢复打开设置前的文档或终端上下文，不把输入送到被文档盖住的 shell。
窄窗口下可横向滚动文档状态区以访问所有状态操作。

<a id="where-it-opens"></a>
### 打开位置

编辑器停靠在终端旁，占据侧边栏与右侧面板之间空间的一半。终端会继续运行，保持可见，并且仍可输入——点击终端，查看智能体的输出，再点击回编辑器即可。差异视图也会在同一列中打开。

拖动分隔线，可将宽度调整为该空间的五分之一到五分之四——这也是 `document_ratio` 的取值范围；双击分隔线则会在三分之一、二分之一和三分之二之间循环切换。全局搜索中的**文档：三分之一 / 二分之一 / 三分之二宽度**也可执行相同操作。窗口较窄时，终端自身的最小宽度限制会让分隔线更早停止移动。

文档标题栏末尾的两个按钮用于切换布局：带有一列的窗口图标表示**停靠在终端旁**，实心图标表示**填满窗口**，即原有的全工作区浮层，行为不变。全局搜索中的**文档：填满窗口**和**文档：停靠在终端旁**也可进行相同切换。

在**填满窗口**模式下，编辑器和差异视图的标题栏左侧都会显示当前终端的名称。点击它可将文档停靠到终端旁，同时保持文件或差异视图打开。

填满或停靠布局**按标签页分别保存**：你可以在一个标签页中用整个窗口阅读长文件，同时在另一个标签页中让智能体占据一半空间，两者互不影响。新标签页的初始布局取自 `config.json` 中的 `document_layout`。宽度则是共享的，并通过 `document_ratio` 持久保存。

如果窗口太窄，无法同时为终端和文档提供可读宽度，则仅对当前文件临时使用填满窗口布局——加宽窗口后，分栏会恢复，而你的设置不会改变。

<a id="markdown-editor-design"></a>
### Markdown 即时渲染编辑

`.md`、`.markdown` 和 `.mdx` 默认使用原生即时编辑。普通正文直接输入，相关语法随光标局部显露；状态栏的**源码**／**即时编辑**按钮切换同一文档和历史，不打开只读预览。原有 `ToggleDocumentPreview` Action 标识保留，便于继续使用自定义快捷键；旧的只读 Markdown 预览设置已移除。

普通**新建文件**与终端 scrollback 导出继续使用纯文本编辑器。使用命令面板的**新建 Markdown 文档**创建未命名 Markdown；该命令默认没有快捷键，可在设置中绑定。未命名 Markdown 首次保存建议 `.md`，粘贴或拖入图片前先确定保存位置。普通代码的 `EditorState`、保存整理与语言服务不因 Markdown 切换而替换。

普通新文件首次另存为 `.md` 后，当前 buffer 仍保留原编辑器、选择和撤销历史；仅更新路径、语言与保存目标，不在保存中更换输入实体。关闭全部共享呈现、释放 buffer 后再次打开，才按该扩展名使用原生即时编辑。需要从创建起使用原生能力，请使用**新建 Markdown 文档**。

反向同样适用：已打开的 Markdown 另存为或重命名为其他扩展名后，当前 buffer 继续使用原生文档、编码／逐行行尾表示和撤销历史，外部重载也按当前输入实体解码；释放后重开才按新扩展名选择编辑器。更名不隐式执行全文整理或有损编辑器迁移。

#### 使用隔离配置复验

复验时使用临时配置和工作区，不需要开发开关：

```bash
cargo run --locked -p lyrel --bin lyrel-app -- \
  --config-dir <临时配置目录> --open-path <临时工作区>/shared.md
```

将临时配置的 `install_cli_on_path`、`check_for_updates`、`auto_download_updates` 设为 `false`，避免 CLI 安装和更新。文件继续使用既有 Host 打开、保存、另存为、dirty、外部冲突和关闭协调，不另建保存系统。

在此入口使用编辑器分组命令打开同一文档的第二份呈现：两边共享源码、revision 和公开 `UndoHistory` 支撑的撤销历史；光标、选择、焦点和滚动分别保留。连续输入按呈现与光标连续性分组；粘贴、删除、组合输入提交各自形成事务，撤销后输入会替换旧的重做分支。关闭其中一份不会丢弃另一份的编辑。

即时编辑把普通段落、ATX／Setext 标题和分隔线投影到公开 `editor_host` 的原生块渲染；正文是一个连续的原生输入表面，不为每个段落创建 `Input`，也不因点击段落而弹出源码框。`Enter` 插入段落分隔，`Shift+Enter` 插入双空格硬换行；既有单换行按软换行流排，双空格或反斜杠换行保持硬换行。段首 `Backspace`／段尾 `Delete` 通过最小源码事务合并相邻正文，拖动或 Shift 选择可以跨相邻段落复制、剪切和删除。转义标点与字符实体显示为对应文字，编辑位置映射回原始源码区间；Unicode 移动和删除仍遵守 grapheme 边界。

两种模式保留同一文档 identity、源码选择、dirty 和统一撤销历史；呈现模式、选择、焦点与滚动分别保留。所选内容的剪贴板表示始终是原始 Markdown；occurrence 多选按源码顺序以换行连接，输入、粘贴和删除经一次稀疏事务，不导入任意 HTML/CSS。

表格相邻单元格按文档中的实际顺序连接；从一个单元格的可见末尾按 `Shift+Right` 到下一格开头时，选择保留两者之间原始的空白和 `|`，反向选择与回缩遵循同一边界，不跳过相接源码区间的单元格。图片和未显露的行内公式仍作为完整原子跨越，不把其源码内部当作普通字符停靠点。

表格结构命令只处理当前 revision 投影确认的所属表格及必要容器前缀，不同步复制或解析全文；过期的表格范围不执行。已有表头、分隔行和正文行各自保留原始行终止符，行移动／表头提升时终止符随行移动；新增行使用文档的换行约定，无最终换行的表格仍不补末尾换行。行列操作、对齐及撤销／重做继续使用同一文档事务和 Host 保存路径。已经满足的对齐命令不创建虚假的源码历史项，但仍分隔命令前后的连续输入，撤销分别恢复两次输入。

正文投影按文档语法使用唯一带源码位置的解析路径：普通 Markdown 使用与 `gpui-base 0.8.1` 相同的正式 `markdown 1.0.0`，MDX 使用正式 `ox_content_parser 3.4.0`，把公开字节区间 AST 转换为现有投影的 `mdast` 数据。同一文档不由两个解析器竞争，也不从渲染字符串反查源码。YAML/TOML 元数据作为原始前缀分区，后续区间回到同一源码坐标，不插入占位或改写解析输入。输入后只更新受影响块及其直接相邻上下文；完整解析在后台合并调度，落地前检查原文档 identity 与 revision。未完成或无效的输入保留在源文档中。稳定的块／leaf identity 复用原生渲染状态；选择、点击、原生输入法候选位置取自每帧重新收集的 `LeafGeometry`，宽度、字体、缩放和滚动改变后不复用旧布局几何。

长文呈现仅构建视口及前后缓冲区的原生块；表格单元格作为同一布局行保留，离屏块使用带 leaf identity／version 的高度提示占位。缺少当前帧几何仅表示未布局，不删除源码、选择或历史。返回离屏位置先按源码定位所属块，再以新帧几何校正光标；宽度、字体与 rem 缩放改变后重测。晚到的图片、公式、图形与解析结果更新布局时，仍在视口中的光标继续保持可见，阅读位置按稳定 leaf 锚定；主动滚动不被旧锚点抵消。

光标重入请求要等到新帧中的光标实际进入滚动区才完成，不能在发出像素位移时就清除。滚动区边界取自 `ScrollHandle::bounds()`，不拿包含工具栏的整个编辑器边界代替；在 prepaint 中校正位移后通知所属 Entity 重新构建虚拟视口，不依赖绘制阶段会被忽略的 `Window::refresh()`。

完整解析采用一个运行中的后台任务及一个可替换的最新请求，避免连续输入排队执行多份全文解析。同步局部语法解析限制为 32 KiB；超大容器的受影响区域暂时显示可编辑源码，随后由匹配 identity／revision 的后台结果恢复排版。过大补丁先保留 Rope 源码区间，只为视口内的有界片段生成显示文字；Unicode 边界通过借用 Rope chunk 的 `GraphemeCursor` 查询，不为单个宽行复制全文。该策略不改变唯一源码及撤销所有权，也不意味着任意大小单个段落、代码块或表格已经完成性能验收。

#### 源码保真与共享文档

源码保真指普通编辑与保存不改写未编辑区域，而不只是保持渲染结果相同。编辑模块遵守以下约束：

- 源码 buffer 是唯一内容来源；语法树、源码区间映射和渲染结果均为派生数据，不通过整篇重新序列化保存。
- 视觉操作转换为最小必要源码修改。修改表格结构可以改动该表格，但不能重排其他段落；原有标记写法、空白、引用式链接和未适配语法保持原样。
- 即时渲染与源码模式共用内容和撤销历史。切换模式不重建文档、不清空撤销、不制造未保存状态；光标与选择通过源码位置映射。
- 复用现有 `EditorBuffers` 与 `EditorPanelState` 的 Host 身份、共享 buffer、保存、外部版本冲突和关闭确认机制，不另建保存系统。同一路径在不同 Host 上仍是不同文档。
- 普通保存保留编码、BOM 和原有换行，包括混合换行；只有显式格式化或转换才能扩大改写范围。不能编码的输入仍需明确处理，不得静默替换字符或转换编码。
- Markdown/MDX 的源码保真优先于 `.editorconfig` 自动保存整理：不自动执行去尾空白、补末尾换行或换行转换，避免移除双空格硬换行等有效语法。配置仍可指导新输入的缩进；其他代码文件保持现有规则。
- 解析、公式与图形渲染不阻塞输入；异步结果必须匹配文档身份与版本，过期结果不得覆盖新内容。

Markdown/MDX 普通保存不执行全文整理；严格解码保留编码、BOM 与各行终止符，经同一文档表示元数据编码，再执行所属 Host 的既有写入与冲突检测。损坏的声明编码拒绝打开；不可编码输入保留未保存状态，仅明确选择转换 UTF-8 才改变编码。状态栏换行切换是显式整篇转换。普通代码文件继续调用 `editor_text::apply_save_rules`。

新增的确定性回归覆盖已观察到的混合换行归一化问题、局部输入、删除、组合输入取消、稀疏批量替换、撤销／重做、编码失败，以及经已有工作台与 Host 保存后关闭重开并逐字节比较。正文与命令切片合并前，Windows 集成运行的编辑器回归 129 项、codec 回归 37 项均通过；这些是既有记录，不是本次合并后重新运行的结果。真实原生窗口分别打开本机与一次性 SSH Host 的同一份 72 字节 UTF-8 BOM 文档（4 个 CRLF、2 个 LF、尾部双空格、无末尾换行）：无编辑保存不变；插入 `new\n` 仅增加 `new\r\n` 的 5 字节；撤销保存与关闭重开均恢复原始字节。远端保存没有改写同名本机文件；两处 `.editorconfig` 的去尾空白、补末尾换行及转 LF 规则均未作用于普通 Markdown 保存。该实窗结果不覆盖其他编码的逐项 UI 验收、资源流程、live 模式或 macOS。

同一 Windows source 模式另已实测 UTF-16LE BOM 中文文档的局部输入与撤销保存，逐字节结果符合原编码；Windows-1252 文档输入不可编码的 emoji 后出现原生转换／取消提示，取消不改磁盘字节，撤销后可用原编码保存。损坏的已声明 UTF-8 BOM 文件被拒绝打开并显示错误，未生成替代字符文档或修改原文件，见 [#105 原生编码错误记录](https://github.com/dlivxpr/lyrel/issues/105#issuecomment-6495240023)。

#### 原生实现路线与候选依赖

自建源码保真的 Markdown 编辑模块，复用 GPUI Kit 的公开渲染接口，不直接采用会重新序列化文档的富文本模型。当前锁定的 `gpui-kit 0.8.1` 已包含 `gpui_kit::base::text::editor_host`；它提供块渲染与文字几何信息，但不提供完整编辑内核。文档身份、源码映射、编辑事务、撤销、选择、焦点、原生输入法接入和无障碍仍由编辑模块负责，见 [GPUI Kit 的 editor host 职责](https://github.com/longbridge/gpui-kit/blob/main/docs/ARCHITECTURE.md)。

`gpui-kit-markdown-editor` 作为交互与架构参考，不直接集成其 `0.1.1` 发布版：该版本固定 `gpui-pre =0.3.9`，而 lyrel 使用 `0.3.10`；它还明确存在首次保存改变列表紧凑度、空段落消失、缺少源码偏移映射，以及 Windows/macOS 原生输入未验证等限制，见 [发布版依赖与限制](https://docs.rs/crate/gpui-kit-markdown-editor/0.1.1)。不以 Git 依赖、第三方源码复制或构建补丁绕过仓库依赖约束。

原生实现使用正式 [RaTeX 0.1.15](https://docs.rs/ratex-svg/0.1.15/ratex_svg/) 的 `parse → layout → glyph SVG` 路径，以及 [Merman 0.9.2](https://docs.rs/crate/merman/0.9.2) 的 `all-diagrams`／`complete-svg` 与完整 `resvg_safe` 管线，不启用 ELK。两者由 resvg 光栅化为原生图像，不依赖 Node.js、Chromium 或项目 JavaScript；MiTeX／Typst 未加入产品依赖。

依赖、字体与第三方许可以正式发布包和 `Cargo.lock` 为准，见[源码构建依赖](/getting-started/installation)。消费者、Windows 实窗、真实 SSH 与离线证据分别记录，不把其中一种当作其他平台或完整上游语法通过。

#### 三阶段范围与验收目标

下表是三阶段完整验收目标；已实现和已运行范围分别记录，未满足的门槛不记为通过。

| 阶段 | 交付范围 | 必须证明的行为 |
|---|---|---|
| 一：Markdown/GFM | CommonMark 与 GitHub Flavored Markdown（GFM）正文的即时渲染编辑，包括标题、段落、强调、删除线、引用、嵌套列表、任务列表、代码块、行内代码、链接、图片和表格；保留源码模式 | 中文输入法、跨块选择、复制粘贴、撤销重做、表格单元格与行列操作；无编辑保存保持原文，局部编辑不改无关区域；本机与真实 SSH 文件分别验证 |
| 二：公式与 Mermaid | 显示真实公式与图形，激活后编辑局部源码并更新渲染，与正文共用撤销历史 | 数学语法清单逐项验证；按选定 Mermaid 原生实现发布版核验图形类型与兼容范围；错误原因可见、源码不丢失；断开外网后仍能渲染无需外部资源的公式与图形 |
| 三：MDX/JSX | 下列 12 个组件的专用原生编辑视图；其余组件的通用属性与子内容结构编辑 | 嵌套内容、属性修改、局部源码映射与撤销正确；不执行项目 JavaScript，不把动态表达式源码编辑当作真实页面预览 |

公式按明确数学语法清单验收，不承诺完整 TeX 或完整 KaTeX 兼容。最低清单为：

- 行内与块级公式、上下标、分数和根式
- 希腊字母、常用运算符、积分与求和
- 矩阵、分段函数、多行对齐和公式内文本

任意宏包、文件读取和 TeX 程序执行不在范围内。Mermaid 接受原生实现与 Mermaid.js 的合理字体、布局差异，不要求逐像素一致；图形类型和语法的支持声明必须依据发布版兼容清单与实际样例。未支持或解析失败时保留源码并报告原因，不把显示代码块算作支持渲染。

Mermaid 派生输出按稳定图形 identity、原始图形源码及实际字体／颜色等渲染输入复用。普通正文编辑不使未改图形重新进入等待状态，也不丢弃其正在运行的渲染；新增、内容改变或样式改变的图形才重新请求。异步发布仍验证当前文档、图形 identity、源码、样式和请求代次，旧请求不能覆盖后续修改或另一文档。

##### Merman 0.9.2 的原生样式边界

完整目标仍为 34 族、37 行 primary 与独立的 zenuml 对照通道，不因某族失败而缩减。集成回归已观察到平面及带 `systemBoundary` 的 `usecase` 均被原生管线拒绝，实际原因为 `validate-resvg-compatible-svg` 报告 `invalid <style> content: unclosed CSS string, comment, or URL`，不是源码语法错误或缺少 ELK。

该发布版的 Usecase 样式输出先把字体 CSS 字符串的引号写成 XML 字符引用，随后 CSS 清洗器却在解码前解析序列化文本，引用末尾的分号因而截断字体声明。宿主现通过公开 `SvgPostprocessor`，仅在普通 `<style>` 文本中将发布版生成的 `&quot;`／`&#39;` 恢复为 XML 文本允许的字面引号；属性、标签、其他实体与文档源码均不改写，CDATA 保持原样。之后仍执行完整 `resvg_safe` 清洗、资源策略和终态验证，不旁路验证或把错误图当渲染成功。

##### 结构公式消费者矩阵与验收边界

隔离 Markdown 工作台沿用现有 RaTeX `parse → layout → glyph SVG → resvg → GPUI image` 路径。结构公式没有独立文档、专用历史或另一份行内投影：激活公式后显示同一文档的局部源码，输入、组合输入与正文共用 command/transaction。RaTeX 公开 API 已表达矩阵、分段和对齐环境，不增加按源码字符串改写公式的兼容包装。

`structured_math_syntax_matrix_edits_renders_and_reopens_through_workbench` 为以下每项分别建立行内 `$…$` 和独立块级 `$$` 文件，经真实工作台打开、公式命中、局部输入、撤销／重做、Host 保存、关闭与重开检查；所有用例均比较完整保存字节，包括 UTF-8 BOM、混合 LF/CRLF、末尾双空格和无最终换行。图像几何与较简单的参照公式比较，检查增加行数、上下标、分数或运算符后应有的高度／宽度关系，不能用非空输出、源码标签或固定占位图代替。

| 回归项 | 明确输入范围 |
|---|---|
| 基础最低清单 | `x_i^2`、`\frac{a+b}{c}`、`\sqrt[3]{x}`、`\alpha+\Gamma`、`\lim`／`\sin`／`\cos`、定积分、带上下限求和 |
| 矩阵 | `matrix`、`pmatrix`、`bmatrix` 的两行两列；与单行矩阵比较高度；单元格组合上下标、分数、根式和求和 |
| 分段函数 | `cases` 两分支，含上下标、条件运算和 `\text{…}` |
| 多行对齐 | `aligned` 两行，组合上下标、求和和积分 |
| 公式内文本 | `\text{when }` 与上下标、关系运算和求和组合；当前回归只使用内嵌字体覆盖的拉丁文本，不宣称 CJK／emoji 字形支持 |

`structured_math_local_invalid_recovery_composition_and_selection_keep_one_history` 另外覆盖上述结构公式及文本组合的行内／块级局部编辑：删去闭合花括号后出现带原因的错误；错误仍能激活源码；撤销恢复公式和光标；反向选择中的 preedit 取消不破坏 redo，提交只占一次历史；切换 source/live 后仍能恢复原选择与字节。这里的组合输入通过生产 `EntityInputHandler` 的测试适配器驱动，不是操作系统输入法验收。

上述两个结构公式消费者回归均已在 Windows 通过，覆盖 36 个行内／块级工作流及错误恢复、组合输入 handler、统一历史和完整保存字节。Windows/macOS 实窗中的矩阵括号、分支及对齐、行内基线与段落间距、系统 IME 候选窗和提交／取消、真正断网后的渲染、真实 SSH 保存／重开及输入到绘制性能仍须分别记录；headless 几何、库级 SVG/PNG 探针和本机 Host 文件测试不能替代这些门槛。任意 TeX 宏包、文件访问、完整 TeX／KaTeX 兼容和 Word 式结构编辑仍不在范围内。


#### MDX 原生组件与执行边界

MDX 的可视化编辑不等于执行 React 页面。以下组件需要专用原生编辑视图，保留内容与交互语义，但不复刻 Mintlify 的 CSS、字体或动画：

| 组件类别 | 专用编辑视图覆盖 |
|---|---|
| 提示 | `Note`、`Tip`、`Info`、`Warning` |
| 卡片 | `Card`、`CardGroup` |
| 标签页 | `Tabs`、`Tab` |
| 步骤 | `Steps`、`Step` |
| 折叠区 | `Accordion`、`AccordionGroup` |

隔离工作台为 `Note`、`Tip`、`Info`、`Warning` 提供专用原生提示块：名称文字与语义色边界共同表达备注、提示、信息和警告，正文仍是可连续编辑的嵌套 Markdown，不运行网站组件。现有属性入口直接选择原属性值；“编辑提示块源码”仅在当前组件范围显示完整原文，“返回提示块正文”恢复格式化内容。两者共用同一输入、文档事务与撤销历史；切换先结束组合输入，再将焦点交回原输入，不创建独立属性或源码编辑器。

四种提示块的 Windows 消费者覆盖属性、嵌套格式、局部源码、组合输入 handler、键盘返焦、共享历史与完整 Host 字节。输入上下文仅在文本自身聚焦时启用，不抢占原生按钮的 Enter／Space。实窗和系统 IME 证据另见前述记录，macOS 本次未执行。
隔离工作台中的 `Accordion` 使用原生按钮展示标题与展开状态，`AccordionGroup` 保留分组结构；属性与嵌套 Markdown 继续使用原文映射及同一输入、事务和撤销历史。折叠只改变当前呈现的布局，不修改源码、脏状态或保存内容。折叠前结束当前预编辑，并把选择与输入焦点移到可见组件头部；显式定位或撤销回到隐藏内容时，需要展开其祖先，不能把输入继续发送给隐藏光标。布局过滤须与虚拟化统一处理，不保留被折叠内容的旧高度占位。

折叠区消费者回归已在 Windows 通过，覆盖展开状态的真实无障碍元数据、键盘激活、隐藏几何、属性／子内容编辑、折叠、重开、撤销展开祖先与逐字节 Host 保存。直接调用 `EntityInputHandler` 的预编辑覆盖不代表 Windows/macOS 系统 IME、候选位置、原生像素或真实 SSH 已验收。

`Tabs`／`Tab` 使用原生标签控件。点击或左右方向键、Home／End 切换分支后，原输入返焦且选择进入可见子内容。隐藏分支不参与布局，但完整保留源码、属性和统一历史；活动标签按稳定组件身份保存在当前呈现，不写源码或产生撤销项。切换先结束组合输入；定位或撤销返回隐藏内容时展开必要祖先。Windows 消费者与本机／SSH 混合实窗均覆盖上述状态，macOS 本次未执行。

在标签页正文内，`Alt+Page Up`／`Alt+Page Down` 切换最近一层标签组；嵌套组的状态独立保留。`Tab` 仍用于正文缩进或表格导航，不被改作组件切换键。

未知组件显示明确标注的标签名、属性与子内容结构编辑；动态属性、表达式、函数和 `import`/`export` 保留并编辑源码，不执行项目 JavaScript，也不加载项目 React 组件。未知组件的通用结构视图不是组件的真实渲染结果。

#### 图片资源与网络访问

图片插入与加载遵守以下规则：

- 支持截图粘贴与图片拖入：在文档同级 `assets/` 创建资源文件，再插入相对链接；现有图片链接不自动搬迁。
- 资源写入文档所属 Host；远端文档的图片写入同一远端 Host，不能误写本机同名路径。未命名文档先确定保存位置。
- 撤销插图或放弃文档修改不自动删除已创建图片，避免删除其他文档引用的文件；接受可能留下未引用资源的取舍。
- 点击即时编辑中的图片会显露该图片原始语法，并把插点放入 alt／引用源码内部，可继续编辑 alt、URL 或引用标识；这不是打开链接或联网加载的授权。`Right`、`Shift` 和跨图片选择／复制仍按完整原子边界处理，不因点击显露路径改变原始 Markdown 剪贴板表示。
- HTTP(S) 外链图片默认不请求，主动加载后才联网；本机或 SSH 文件图片通过所属 Host 读取，不按外链处理。
- 本节策略只针对文件编辑器，不改变 GitHub 面板现有图片策略。实现外链加载时同步更新[隐私说明](/reference/privacy#what-leaves-your-machine)。

#### 实现前的验证门槛

最大风险是编辑内核与源码映射，不是静态 Markdown 渲染。开始正式替换前，必须在原生窗口验证以下路径：

1. 中文输入法组合输入、候选框定位、软换行边界、跨块选择与删除。
2. 即时渲染和源码模式之间的光标、选择映射，以及统一撤销历史；切换前后的内容与未保存状态一致。
3. BOM、编码、混合换行、空白、引用式链接和嵌套列表的保存字节；同时验证无编辑保存与局部修改后的未编辑区域。
4. 表格、长文和多公式场景下的输入与滚动，确认解析和渲染不会阻塞输入或应用过期结果。

Windows 各阶段在隔离配置、临时工作区与真实 SSH 验证，具体负载、输入方式和字节证据见上文。编译、单元测试或静态截图不能代替输入、保存和重开；本机结果不能替代远端 Host。

发现失败应保留原因与源码，不能降级为只读预览、WebView 或静默放宽保真。现有证据不承诺所有字体／DPI 组合、完整 TeX／Mermaid.js 等价或 macOS 实机通过；父规格 #102 的最终接受由负责人按工单记录评估。
