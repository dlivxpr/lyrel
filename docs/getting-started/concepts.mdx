四个词就能解释 lyrel 的大部分功能。其中三个看得见；第四个则是前三个在重启后仍能恢复的原因。

<a id="pane"></a>
## 窗格

一个**窗格**就是一个终端：一个连接到 PTY 的 shell（或程序）。它是 lyrel 中唯一真正运行程序的组件。

窗格在整个生命周期内都有固定的 ID，例如 `%42`。[CLI](/cli/overview) 通过这个 ID 定位窗格，窗格内部的 `$LYREL_PANE` 保存的也是这个 ID。

<a id="tab"></a>
## 标签页

一个**标签页**就是一组窗格的布局。最初只有一个窗格；将它拆分后，标签页就容纳了两个窗格，按行列排列，可以拖动调整。

标签页固定显示在左侧边栏中。标签页的标签会采用 lyrel 能获取到的最合适的信息：优先使用你设置的名称，否则使用其中运行的编程智能体名称，再否则使用其工作目录的最后一级名称。

<a id="workspace"></a>
## 工作区

一个**工作区**是一组有名称的标签页，通常对应一个项目。一个窗口同一时间显示一个工作区，按 <kbd>⌘ ⇧ O</kbd> 可打开切换器，在工作区之间切换，或打开第二个窗口来显示另一个工作区。

切换器是一个扁平列表，最近使用的工作区排在最前面。本地和远程工作区列在一起，每一行都标明其所在的机器。输入内容会按工作区、标签页或机器名称进行筛选，因此输入某台机器的名称即可只查看那台机器上的工作区。按 <kbd>⌘ ⇧ N</kbd> 可打开“新建工作区”表单，在其中选择机器（本机或任何已配置的 SSH 主机），并可选填名称。

前九个工作区还会编号为 1 到 9：编号显示在切换器中各工作区的旁边，**窗口**菜单也按此顺序列出它们。编号按照工作区在本机上首次打开的顺序分配，不会随着切换而变化，因此绑定到**前往工作区 3**（`SelectWorkspace3`，默认未绑定）的按键始终会跳转到同一个工作区。删除工作区后，排在它后面的工作区编号会依次前移。

工作区让 lyrel 中的十个仓库不至于变成四十个难以区分的标签页。工作区也可以位于远程：远程机器上的工作区依然是工作区，通过同一个切换器打开。

<a id="the-server"></a>
## 服务器

关键在这里：**管理 shell 的不是窗口，而是后台服务器。**

退出 lyrel 会关闭窗口，但服务器会继续运行。构建继续进行，智能体继续工作，SSH 会话也保持连接。再次打开 lyrel 时，它会重新连接到原来保留的状态。

这也解释了为什么：

- **在任何终端中都能使用 `lyrel`。** CLI 与同一个服务器通信，完全不需要运行 GUI。
- **崩溃并不意味着一切丢失。** 窗格恢复时会显示之前的内容：每个窗格输出末尾的一段内容会按容量上限保存在磁盘上，并在具有相同 ID 的窗格重新打开时交给它。
- **停止所有进程需要明确操作。** 托盘菜单中的*退出并停止服务器…*是结束所有进程的唯一常规方式，而且操作前会发出警告。

实现中，`lyrel-core` 的 `daemon/pane.rs` 中 `DaemonPane` 持有会话身份与生命周期权威；
`daemon/pane/lifecycle.rs` 私有持有 PTY master／child、集成临时目录及原生 SSH channel handle，负责平台资源接入、进程探测、resize 和关闭。
`daemon/pane/launch.rs` 仍是 shell、工作目录与环境准备的唯一实现，`daemon/pane/replay.rs` 仍负责有界输出缓冲及几何分段。
`daemon/pane/subscriptions.rs` 拥有控制器／观察者身份、epoch、顺序回放、广播、剪贴板权限和各输出流的背压；
`daemon/pane/subscriptions/capacity.rs` 拥有随连接存活的图形容量租约。
桌面的 `src/terminal/paste.rs` 独立处理剪贴板文件／图片路径、远端私有暂存目录及上传生命周期；
`TerminalView` 只负责输入投递和失败提示。这些内部职责拆分不改变协议、配置或会话恢复规则。

新控制器先接收模式、文字／几何和图形回放，再接收对应状态与实时输出；接管只替换旧控制器，不替换观察者。
观察者始终只读，其回放与实时输出共用独立预算：停止读取或已经断开的观察者会被移除，不能阻塞控制器输出。
图形权威状态仍属于原 pane，回放准入不创建新的 shell，也不在容量不足时静默丢图。
订阅转换与输出排序仍在原有 `PaneState` 锁内完成；图形授权等待在锁外进行，容量租约锁仍先于 pane 锁。
退出协调位于 `daemon/pane/lifecycle/exit.rs`：reader 在转发 EOF 前的输出后报告退出，Windows 监视器在后台释放 ConPTY master，释放时不持有 master slot 锁。
监视器沿用既有 2 秒排空窗口；继承输出管道的后代进程阻止 EOF 时，仍按原策略有界报告，不把窗口误当作无限排空保证。
reader 与监视器共享同一个单次报告者；退出码探测继续使用有界 `try_lock`，主动 teardown 不额外广播 `Exited` 或竞争回收。
Unix 的 `daemon/pane/lifecycle/inherited.rs` 沿用 exec 继承的 descriptor／child，恢复 close-on-exec、查询内核尺寸，并保留原进程组信号规则；不重启 shell。
原生 SSH 关闭 shell channel，不使用本地 PTY 的信号或 ConPTY 排空规则。所有 facts／subscriptions／graphics 的退出转换仍分借同一 `PaneState` 锁，未增加锁或 UI join。
相关回归分别归入 `lifecycle/tests.rs`、`lifecycle/exit/tests.rs` 和 `lifecycle/inherited/tests.rs`；真实 daemon 消费者继续覆盖最终输出与退出码，
显式 `native_ssh_lifecycle` 集成用例复用隔离 SSH fixture，验证真实原生 shell channel 的最终输出、单次退出和主动关闭静默语义。
这些是验证入口，不是本轮已执行的通过声明；Windows、Unix 与真实 SSH 的运行证据需要分别记录。

控制连接继续从 `lyrel-core::host::server` 的 `serve`／`serve_with`／`serve_halves`／`serve_halves_with` 接入。
私有 `host/server/connection.rs` 负责连接初始化与退出协调，`negotiation.rs` 负责 HELLO 和功能协商；
握手成功后才建立机器订阅、连接身份、GUI 注册与可选的工作区附着，再进入请求读取循环。
`attachments.rs` 的 `ConnectionIdentity` 私有持有连接 ID、客户端身份及共享 `AttachRegistry`，统一执行附着、分离、删除与 GUI 注册／注销；
请求分发只调用这些语义操作，不直接修改附着表。接管仍在同一 handover 锁内先更新机器记录、再更新 live registry，
释放锁后才向被替代者发送通知；只有专用连接会被关闭，共享 GUI／Host 连接可继续服务其他工作区。
`output.rs` 的单一 `Sink` 同步串行化响应与事件，并负责输出退休，不增加输出消费者或锁。
读取循环退出后，依次关闭工作池、清除 watch、释放工作区、注销 GUI、丢弃机器订阅、退休 Sink、关闭链接；
不会等待最后一个 worker 持有的 `Arc<Conn>` 释放才清理连接。
私有 `dispatch.rs` 保留逐项显式的 wire request 分发，借用同一连接的 Host、机器树与 `ConnectionIdentity`；
`requests.rs` 的 `Requests` 私有持有在途 request ID 与取消标记，负责完成关联、错误编码和 blob 响应。
取消只放弃回复，不强制终止已经开始的 Host 操作；完成时先释放在途表锁，再经原 `Sink` 输出，错误链与 CLI 退出结果不变。
`pool.rs` 的 `Pool` 独立持有原有 FIFO 队列、worker 数与唤醒条件：最多 64 个 worker、1024 个排队请求，空闲保温 10 秒；
连接退休关闭准入并丢弃尚未开始的工作；已经开始的 Host 操作可继续完成，不能因此推迟身份清理与 Sink 退休。
`subscriptions/watch.rs` 的 `Watches` 拥有目录订阅及按 request ID 暂存的 receiver：只有 `WatchId` 回复成功写出后才转发事件，
取消或回复失败则释放该订阅。`subscriptions/git.rs` 的 `GitStreams` 拥有原有并发 slot，chunk 仍同步写入同一个 `Sink`，
保持流内顺序、容量限制及慢接收者的背压；`subscriptions/layout.rs` 负责有界机器通知转发，落后超过原有 1024 条队列时，
丢弃已过时的 backlog 并发送 `LayoutResync`，不另建 publication authority。这些 owner 不增加锁、输出消费者或第二份连接身份。
Unix 的 socket 路径、私有权限、残留端点探测与监听属于 `host/server/unix.rs`；Windows 的认证 loopback TCP、
`control.port` 与存活探测属于 `host/server/windows.rs`。现有公共入口直接暴露真实实现，协议仍为 CONTROL 16／PANE 15，
协商、错误分类及断开前输出语义不变；Windows TCP、Unix socket、stdio 和真实 SSH 运行证据须分别记录。

桌面的 `src/terminal/remote/reader.rs` 由 `ReaderTask` 管理单次 reader 生命周期，
私有 `FrameReader` 同时拥有 parser、键盘／终端模式、回放位置和帧缓冲；连接编排只启动或退休 reader。
回放与实时文字、尺寸回显、剪贴板请求及图形更新仍由同一线程按流顺序消费，回放期间不重新回答历史查询或重放副作用。
退休先设置取消栅栏并使旧 decoder 代次失效，不等待静默连接退出；图形权威仍在 daemon，桌面只维护派生缓存与视口报告。

连接接入由 `src/terminal/remote/handshake.rs` 的 `PaneHandshake` 负责：路由、协议协商、
图形容量通告、Spawn／Attach 的应答分类及预读字节移交集中在此处。只有明确的“pane 不存在”
应答允许放弃原会话；静默、断流和图形 admission 失败不等于会话消失。本地、远程工作区与
原生 SSH 仍分别保留原有 Host、PTY 来源及远程剪贴板授权规则。

`remote/connection.rs` 的私有 `PaneConnection` 拥有 reader／writer 的配对、链接替换、
resize 去重与回显等待、viewport 重新发布和关闭次序；`remote/writer.rs` 独立拥有写队列、
背压与每条链接只报告一次的输入失败。替换时先退休旧 reader／decoder，再清理旧事件与
剪贴板请求、重置呈现、安装 successor，随后替换 writer、重新发布 viewport 并同步当前尺寸。
写入只入队，关闭最多等待既有短暂排空宽限，不在 UI 线程 join 静默 socket 线程。
冷 attach 的 agent 回放仍是初始基线；relink 则沿用原视图的活动基线，不吞掉断线期间完成的状态变化。

桌面终端的事件适配集中在 `src/terminal/view/events.rs`：`TerminalLifecycle` 仍唯一持有
事件 receiver、批量唤醒、显示状态登记、时钟与释放任务，按同一顺序调用 `TerminalView::handle_event`。
适配先处理退出事实、输入所有者、远端剪贴板队列和认证提示，再分派事件；不为各能力启动竞争消费者。
普通输出通过 `TerminalLifecycle::notify_output` 只通知正在显示的 pane；隐藏 pane 仍消费输出、
推进必要状态、解码图片并归还退役图形资源，不等待下一次可见绘制。transport 中断不能冒充进程退出，
只有真实 child exit 才发出 `ChildExited`。

`view/notices.rs` 负责标题稳定等待、铃声和通知的 GPUI 适配；`AgentActivity` 仍唯一维护 agent
活动、Host／pane 读取标记和延迟 Done 通知的取消句柄，新状态会取消尚未投递的旧通知。
退出时丢弃待采用的标题，避免定时器覆盖退出状态；程序通知仍在退出检查之前排空。
`view/presentation.rs` 保留原 `TerminalView` 的 `Render`、焦点入口与覆盖层次序，
`view/menus.rs` 组合通用命令，链接菜单仍由 Host-aware 链接适配提供；两者不接管 `TerminalElement` 的逐帧绘制。

事件消费者回归位于 `view/events/consumer_tests.rs`，标题／铃声／提示回归位于
`view/notices/tests.rs`；隐藏图片与窗口释放继续复用 `lifecycle_consumer_tests.rs`。
跨能力的 socket-backed GPUI fixture 集中在私有 `view/test_support.rs`，专属图形 fixture 不混入其中。
原生验收需使用隔离配置，对照可见／隐藏输出后的网格、通知计数与窗口重绘，再检查标题往返、
连续铃声、agent 未读及延迟通知取消、断线与真实退出、菜单的禁用项与焦点交接。
这些是待执行的验证入口，不是本轮通过声明；本机结果与 macOS、真实 SSH 等未验证前提分开记录。

连接迁移后的原生验收必须使用专用配置与会话，以下步骤是验收流程，不代表已经执行：

1. 为 GUI、CLI 和 daemon 指定同一个全新的 `--config-dir <isolated-dir>`，为测试远端另建隔离 daemon 配置；不要连接已安装实例或真实工作会话。
2. 在隔离 GUI 新建 pane，记录 CLI `pane ls --json` 的 pane ID、工作区归属和 shell PID；通过 GUI 输入 `echo before-link`，用同一隔离 CLI 的 `capture <pane> --plain` 确认输出。
3. 对专用远程工作区仅中断其测试 transport，保留远端 daemon 和 shell。断开期间调整分屏尺寸，确认其他 pane 仍能输入、窗口仍可交互；恢复同一 transport 后等待原 pane 重连，而不是重启服务器或新建 shell。
4. 再次记录 pane ID、归属和 shell PID，必须与断开前一致；通过 GUI 输入 `echo after-link`，确认原 pane 和 CLI capture 都出现新输出，且当前尺寸生效、输入没有落到相邻 pane。
5. 在同一专用会话中往返切换可见／隐藏 pane，并单独退出、重开 GUI 验证冷 attach。记录重连期间及冷 attach 后的 agent 未读／完成提示；Windows 的静默旧 peer、旧 reader 不能覆盖 successor 网格／decoder 的回归另由真实 socket 消费者覆盖。Windows 与 macOS 的原生结果分别记录，不能互相替代。

### 内部职责归属

这些模块将状态与转换规则放在一起，而不只是把协调器的方法分散到文件中：

| 能力 | 状态与行为所有者 | 协调器保留的工作 |
|---|---|---|
| 工作台 | `ui/tab` 的 `Tab`／`TabSet`、`session_lifecycle`、`pending_pane`、`window_chrome`、搜索与转发表单模块 | `LyrelApp` 组合窗口、执行跨能力导航并交接焦点 |
| 文件树与文件索引 | `FileTreeState` 管理列表、在途读取、监视失效、写入结果和 Host-aware 根目录／索引 | 工作台提供 Host 与标签上下文，执行文档导航、错误通知和最终焦点；搜索不直接修改缓存 |
| SCM | `ScmPanelState` 管理仓库、草稿、提交、分支、graph 与 detail 的转换 | 工作台适配 `ScmIntent`、提供当前仓库上下文，保留破坏性确认、Host 调度和文档／diff 导航 |
| 窗口连接与创建 | `WindowConnection` 管理尝试身份和单 pending／parked 创建意图；`RemoteLinks` 独占机器监督、重连与 pane relink | 切换器保留筛选和表单，工作台执行已接受结果的跨能力导航，不复制目标身份或连接状态 |
| 终端交互 | `PromptInput`、`TerminalHistory`、`TerminalCompletion`、`SelectionScroll`、`AgentActivity`、`LinkInteraction`、`TerminalLifecycle` | `TerminalView` 保留 GPUI 实体身份、绘制、事件适配与任务调度 |
| 文档编辑 | `EditorBuffers` 管理 Host-aware 缓冲区与加载／监视；`EditorPanelState` 管理保存与未保存提示 | 工作台执行保存成功后捕获的关闭意图；退休分组不能转而关闭新的呈现 |
| 布局同步 | `tree_sync/projection`、`reconcile`、`lifecycle::WindowSync` 分别拥有投影、操作排序、队列与恢复转换 | 原同步入口执行 I/O 与 GPUI 结果应用；`MachineMirrors` 仍独立 |
| 连接与 daemon | `PaneConnection`、`LinkWriter`、`FrameReader` 与 daemon 的 facts／subscriptions／lifecycle | `RemoteTerminal` 装配客户端；`DaemonPane` 保留会话权威和原有锁内顺序 |
| CLI | `crates/lyrel-cli/src/commands/` 按命令族处理目标、执行与输出 | 原 `execute`、`Outcome` 和 `Backend` 契约不变 |

接口传递目标身份、Host、借用数据或语义结果，不向能力模块开放整个可变工作台。
本次迁移没有改变协议版本、持久化格式、第三方依赖或平台范围；既有 settings、paste、launch 与 replay 实现仍是唯一入口。
协调器并非零方法：视图组合、跨能力操作与单流排序仍需集中；SFTP 等未纳入独立所有权重写的功能不因主文件缩短就被视为已解耦。

### 工作台组合与延迟窗格

`LyrelApp` 保留同一个窗口 Entity。私有 `app/initialization.rs` 组合已有能力所有者、恢复入口、订阅和窗口释放钩子，
不会将构造期的上下文保存在另一个管理器中；`app/composition.rs` 是窗口与工作区视图的组合适配，
继续只挂载一次 `WindowChrome`、终端、文档、右侧面板、状态栏和窗口浮层。
`app/actions.rs` 按工作区、窗格、导航、文档、会话与应用命令绑定 Action，调用既有语义入口，
不另设命令总线，也不拥有文件树、SCM 或连接策略。设置仍通过原 `settings_bridge` 应用。

`app/pane_binding.rs` 把 shell、新建原生 SSH 和 attach-only 请求绑定到已有 `PendingPane`：
同步返回的是已放置的 connecting slot，不是 shell 创建成功；真实失败、重试、取消、创建代次与资源释放仍由
`pending_pane/creation.rs` 拥有。没有可执行的同步失败或同步 Ready 恢复分支，也不保留旧工厂的转发别名。
`SessionRestore` 与树同步、sidecar 消费者使用同一个绑定入口，attach-only 失败不能生成替代 shell。

创建请求捕获工作区与 slot Entity 身份。`PendingPane::take_installation` 在领取结果前同时核对原工作区和仍存在的 slot，
关闭、替换或切换工作区后不能把晚到结果投递到邻近窗格。分屏仍由 `Tab::prepare_split` 捕获 tab／pane 目标；
`TabSet` 与 `Tab` 继续拥有放置、呈现映射与焦点记忆，`SessionLifecycle` 继续拥有会话记录与离开规则。
根只在合法安装之后绑定终端事件、执行该窗格的启动请求、保存会话，并在原 slot 仍持有焦点时交接给新终端；
后台 landing 不能选中自己的标签页或夺走搜索、设置及其他内容的焦点。

终端构造本身会设置焦点，因此安装适配在原 slot 未持有焦点时保存并恢复此前的焦点；此前没有焦点则保持未聚焦。
这样既允许后台结果安装，又不打断仍打开的搜索；原 pending 仍持有焦点时，根继续把焦点交给安装后的终端。

上述 interface 和测试入口不是运行通过声明。验收需在隔离原生窗口执行打开、分屏、切换、关闭重开与延迟创建，
记录真实 pane／shell 身份、附着状态、焦点与晚到结果去向；自动化、Windows、macOS 和真实 SSH 的证据分别记录。



<Warning>
  重启服务器会结束该机器上所有窗格中的所有进程，包括 shell、智能体和 SSH 会话。布局会保留，并在恢复时启动新的 shell。未经询问，切勿代他人执行此操作。
</Warning>

### 终端内联图片

**终端内联图片**是应用通过受支持的终端图形协议发送、直接显示在窗格终端内容中的图片。
它不依赖应用是否被识别为编程智能体；仅输出 SVG 源码、Markdown 图片链接或文件路径，不构成图片传输，lyrel 不主动解析或加载这些文本。

一份**图片资源**可以对应多次**图片放置**：前者是图片内容，后者是它在终端中的一次显示及其裁剪范围。传输资源不等于立即显示；删除某次放置也不必删除图片资源。

<Note>
  图片功能按 [#40–#47](https://github.com/dlivxpr/lyrel/issues/40) 分阶段实现。资源、独立放置、传输校验、布局、Unicode 占位符、聚合预算、历史回收及存活会话恢复均已接入。Windows 原生窗口已补充部分实测，见下方 omp、压力和恢复记录；macOS、其他显示缩放及完整真实 agent 验收仍未完成，不能将局部结果当作完整兼容性声明。
</Note>

完整实现规格与测试契约见 [GitHub Issue #39](https://github.com/dlivxpr/lyrel/issues/39)。

#### 当前实现：资源、独立放置与传输边界（#40／#41）

- `a=t` 只上传资源；后续 `a=p` 才创建显示。`a=T` 继续上传并显示。支持 PNG、raw RGB/RGBA、这三种格式的 `o=z`，以及分块传输。显式 `f=0` 等同默认 RGBA；只有最终块允许省略 Base64 padding，仍拒绝歧义长度或非零尾部位。首部、负载和终止符跨 PTY 读取保持同一结果；PNG 外层 zlib 在 daemon 有界展开后保留为 PNG，raw 压缩内容仍以压缩形式传输到桌面。
- 同一资源的多次放置共享解码像素。`x/y/w/h` 指定源裁剪，`c/r` 指定显示区域；只指定一轴时按比例推导，指定两轴时保持比例放入区域。`X/Y` 为单元内像素偏移，`C=1` 禁止本次放置移动光标。
- 图片 ID 在窗格内独立。非零图片 ID 与非零放置 ID 的组合替换同次放置；省略 `p` 或 `p=0` 时，每次放置独立。`I` 分配新的图片 ID，并让后续按编号的命令选择该编号最新的资源；同一命令不能同时指定 `i` 与 `I`。重新传输同一个 `i` 会移除其旧资源与全部旧放置，不会让旧位置显示新内容。
- 静态删除支持 `a/i/n/c/p/q/r/x/y/z` 及大写形式。`d=p` 是按 `x/y` 指定的单元删除，不是按放置 ID 删除；定位单次放置使用 `d=i,i=…,p=…`。小写保留可复用资源；大写只在资源没有其他放置引用时回收数据。缺资源、非法放置和不支持的操作返回带身份的错误，并遵守 `q=1/2`。
- daemon 持有唯一资源／放置／选帧状态，桌面只持有派生解码及绘制缓存。像素不进入持久文字回滚文件，不新增图片磁盘缓存。当前 pane 协议为 `16`（新增不可变完整帧关系与原子选帧），`CONTROL_VERSION` 保持 `16`；新连接先在实际 pane endpoint 双向协商版本及有限容量，再新建、附着或观察会话；路由前缀先于协商。旧客户端在创建 shell／订阅输出前被明确拒绝，新客户端遇到旧 daemon／远端 server 报告版本并要求更新，不能静默忽略图片消息。独立版本探测不要求开启会话。
- `a=q` 对实际图片内容进行校验，不存储、不替换资源；坏 PNG／zlib、无效像素长度、超限尺寸及不支持的操作不会回报成功。直接传输可跨主机；文件、临时文件及 POSIX shared memory 只在发送方确实共享负责 daemon 的 Unix 主机时接受，Windows 或跨主机上下文明确拒绝，不把远端路径解析到桌面。文件必须是 regular file，临时文件仅在临时目录且路径包含 `tty-graphics-protocol` 时允许协议删除；间接媒体按下述平台规则有界读取。
- 应答关联 `i/I/p` 并写回 PTY，不作为终端文本显示；`q=1` 只保留失败，`q=2` 全部静默，没有图片身份的请求不注入应答。续块仅以非零 `q` 覆盖首块的 quiet，显式 `q=0` 不解除此前的静默。删除中止未完成上传；损坏或取消的 APC 不会与后续命令拼成图片。拒收不创建放置、不移动光标，也不删除其他已接受资源。

##### 完整帧与手动选帧（#140）

正常图片是第 1 帧（root）。`a=f,i=…` 或 `a=f,I=…` 追加与 root 同尺寸的完整帧，支持现有 RGB／RGBA／PNG、zlib 与分块路径；分块续块可带 `a=f`。`a=a,i=…,s=1,c=N` 停止并选择从 1 开始的帧，省略 `s` 的 `a=a,…,c=N` 也可手动选帧。同一图片的全部 direct／Unicode 放置共用选择结果，不为每个放置复制像素。未放置的 transmit-only 图片即使追加或选帧，也不显示。

每帧拥有独立且不复用的 pane-local key、源内容、元数据与准入租约；`Select { key, frame, revision }` 只改变根资源的选择，不重复传输已保留的像素。恢复在同一次文字快照／live 切换中重放全部保留帧、帧关系、最新选择及放置；替换、删除、screen 清理和旧 worker 退休沿用同一代次约束。预算回收以整份帧序列为单位，不静默删去某个中间帧；追加失败保留已接受的全部帧和选择。资源上限 1,024 包含 root 与所有追加帧；单图片最多 256 帧（含 root），并仍受下表全部字节和元数据限制。当前默认预算不构成双窗格各 60 张 1080p 帧的容量承诺。

此切片不实现自动播放、帧 gap／循环、partial-frame 编辑、合成或单帧删除；这些命令明确返回不支持，不把它们伪装成成功。原生 Windows／macOS 呈现及 fresh-client 取证尚未执行，新增自动化用例也须由集成验证统一运行，不能把现有静态图片的历史证据算作完整帧验收。

原生入口：在隔离的 lyrel 原生 pane 中运行 `node scripts/kitty-frames.mjs`。输入 `1`／`2`／`3` 并回车，检查两处图片同时显示红／绿／蓝和白色边框；输入 `stats` 记录生产者 PID、上传数和字节。选定一帧后输入 `quit`，确认 `KITTY_FRAMES_STOPPED` 后不再运行发送器，关闭旧 GUI 并重新附着同一存活 daemon，检查原位置和所选像素恢复。另可在无桌面时向该自有 pane 输入 `white` 来追加／选择白帧，再重新附着；`delete` 删除整份序列。不要向用户已有 pane 注入这些命令；需分别记录构建、daemon／GUI 身份、截图及资源观察，脚本本身不证明原生验收通过。


当前默认值是保守的实现参数，单位为 MiB（`1 MiB = 1,048,576 bytes`），不是已经测得的完整系统峰值：

| 范围 | 默认上限与核算 |
| --- | --- |
| 单次直接传输 | 一个未完成传输；全部 Base64 合计最多 48 MiB，逐块解码后的 partial buffer 最多约 36 MiB，另加最终 quantum 的 3 字节预留；APC、partial、增长期旧／新分配及同批待处理内容纳入工作空间会计 |
| 单图 | 每边最多 8,192 像素；编码内容及 RGBA 解码权重各最多 32 MiB。常规 `3840 × 2160 × 4 = 33,177,600 bytes`（约 31.64 MiB）的 4K 截图可落在单图限制内；PNG 压缩体小不豁免解码后限制 |
| daemon 每窗格 | 实际编码分配合计 64 MiB、RGBA 权重 128 MiB、临时工作空间 128 MiB；最多 1,024 个资源元数据、4,096 个直接放置与虚拟 prototype，回收提示也占元数据配额 |
| daemon 聚合 | 所有窗格实际编码分配合计 128 MiB、RGBA 权重 256 MiB、临时工作空间 256 MiB。RGBA 权重用于准入，不代表 daemon 另存整份 RGBA。raw zlib 用 64 KiB 输出 scratch、预留 256 KiB 校验空间；PNG 逐行校验 scratch 限 4 MiB。外层 zlib 的 PNG 逻辑展开限 32 MiB，按实际阶段预留 inflate state、增长期旧／新 source 分配，随后保留 normalized source 并另计 4 MiB decoder scratch；parser 仍持有的压缩输入独立占账，不再同时固定预留不共存的 100 MiB 工作空间 |
| daemon 图形传输 | 已编码资源与在队列中的图形 packet 共享同份数据与租约，单独受 256 MiB 聚合池约束；资源被删除或回收后，仍在 writer 中的 packet 在最后引用释放前继续占账，不能提前归还信用 |
| 桌面源内容 | 每窗格实际源内容及接收工作最多 64 MiB，整个桌面进程合计 256 MiB；本地与多个远端 daemon 共用同一池。空窗格不预留整份额度，也没有“四个图形窗格”的固定限制。每次 `GraphicsOffer` 按实际 packet 分配先预留 `2 × encoded bytes + 256 KiB` 接收峰值，提取帧后缩至实际源分配，decoder 输入释放后归还。仅在接收容量落在本次预留内时转移大帧所有权；先前大文字 Snapshot 或合并帧留下的超额容量不会带入图片源，已消费的闲置大缓冲会释放 |
| 桌面派生缓存 | 每窗格 384 MiB，整个桌面进程 1,024 MiB。每份资源在接收前预留 `RGBA bytes + encoded bytes + GPU page bytes`，同一 store 的全部待解码／活动任务另共享最大 `3 × RGBA bytes` scratch；同 store 跨 reader 代次的 decoder 串行运行，保留单次解码原有 `4 × RGBA` 上界，不为不会并发执行的任务重复预留峰值。完成后保留实际 CPU 分配与 GPU page 票；queued／in-flight／decoded／painted-retired 与 snapshot 均持有相应租约，取消不提前归还活动 decoder 的票。GPU 票按当前图片实际 page rounding 上界计算：`4 × max(width, 1024) × max(height, 1024)`；正式 Windows DirectX／macOS Metal 路径的 image tile padding 为零，一个小图最多按独占 4 MiB page 预留，不把所有图当作最坏 64 MiB。Linux 只有 headless daemon，不将未支持的 Linux 桌面 wgpu 当作本产品的已交付渲染路径 |
| 桌面消费者准入 | 每窗格 daemon 编码上限 64 MiB、RGBA 权重 128 MiB，仍同时受桌面的实际 source／derived 字节池限制。daemon 接受新资源及回复成功前，渲染消费者必须对 `GraphicsOffer` 返回实际字节预留的 `GraphicsGrant`；拒绝、取消、超时与断连释放未完成预留。不设两个驻留资源槽，小图可在真实字节预算内继续接收 |
| 保留元数据 | 每个资源或 placement 按 512 bytes 保守覆盖实际 owner、BTree／Arc 开销；daemon 与桌面分别使用独立的每 pane 4 MiB、aggregate 16 MiB 票池。无像素 notice 仍占票，旧 snapshot 也延续持票直到真正释放。新资源、新放置及 replay notice 分别准入，已有同 key 更新复用原票；元数据满额会拒绝新内容，不为无法释放元数据的历史位置做无效像素回收 |

同一桌面的 source、derived 与 metadata 三个池的会计上限合计为 1,296 MiB；一个 daemon 的权威编码内容、临时工作空间、图形传输及 metadata 合计为 656 MiB。一个桌面连接一个 daemon 的这部分组合上限为 1,952 MiB；连接四个独立 daemon 时为 3,920 MiB，且远端 daemon 的内存在各自所属主机。这里没有将 daemon 的 RGBA 准入权重重复算作实际像素副本。这些是各分配阶段的保守会计范围，不是整进程 RSS、整机或 GPU 驱动峰值承诺：终端文字、其他界面、allocator、系统管道／socket buffer、驱动与平台缓存仍须另测。

容量不是可以忽略的提示。所有生产 pane 客户端声明有限上限；渲染消费者另按每份资源的真实成本授权，同一 pane 多消费者均须满足准入。等待授权不持有 `PaneState` 锁，删除、resize、清理与退出仍可取消旧工作；无 GUI 或 detached 时仍按 daemon 自身预算接收输出。新桌面不能容纳已经保留的图片时，附着会明确失败并保留 daemon 权威内容，不以静默漏图或虚构回收提示冒充恢复成功。只有精确确认原 pane 不存在才可创建替代 shell；graphics admission 拒绝、断连或附着未获完整答复不能替换仍存活的会话。旧 reader 及在途解码退出前不提前归还它们仍持有的信用。

终端视图释放时，无条件从应用级可见性注册表移除其连接事实并退休 reader，不能把这两步依附在仍然有效的窗口 handle 上。仍存活的窗口负责实际 atlas 清理；窗口先关闭时，其 atlas 随窗口销毁，派生 cache 与在途任务的最后 owner 释放后才归还各自信用，注册表不能继续强持有已关闭窗格的图片池。

`GraphicsOffer` 的零像素形式只申请资源或放置的元数据，不分配 source／GPU 票；`a=T` 在改变权威内容或回复成功前须同时获得资源与首次放置的授权，任一失败都会取消此前授权。GUI session 的独立输入 pump 优先处理授权、视口及压力请求；同一连接先应用已收到的视口，再处理其后的压力请求。桌面视口报告遇到终端 grid 锁竞争时，保留至多一个后台唤醒，取得锁后采样并发送最新视口，不排队保存过时快照。隐藏即时撤销已知视口，首次 Screen 或重连后重新报告；最后一个 reporter 释放后后台任务退出。连接发送仍遵守既有积压上限，超限报告连接错误，不承诺在断链后送达。普通输入待处理队列最多 64 条、每条最多 1 MiB；超限明确断连而不静默丢弃。这一普通输入边界不属于上述图片分配池合计。

回收优先级为无引用、非可见历史、受保护内容；同级按原有准入顺序确定。可见历史不是“实时屏幕之外”的同义词：渲染连接通过 `GraphicsViewport { screen, epoch, top, rows, cols }` 报告真实滚动视口，`top` 是绝对文本行锚点，`None` 跟随实时屏，`rows=0` 撤销隐藏窗格的视口保护。`GraphicsUpdate::Screen` 携带对应 `epoch`；resize 行重排、主备屏切换、reset 和历史清理使旧代次失效。daemon 直接在自身资源／网格上核验 direct 放置与实际 placeholder 单元，不复制资源模型；同批新输出推进实时原点时，用户仍在看的历史锚点不随相对 offset 漂移。detach、控制器抢占及 observer 移除同步撤销相应连接事实；桌面跨 pane／跨 daemon 压力选择同样读取真实视口，最终仍由负责 daemon 决定能否回收。普通文字输出的准入屏障只访问当前 pane 已有资源，不扫描全 daemon 注册表。

非活动屏不等于全部受保护：进入备用屏后，主屏仍属实时屏的图片保持保护，已离开实时屏且未被真实滚动视口引用的旧历史仍可回收。daemon 向桌面传递这一权威引用事实，避免跨 pane／跨 daemon 的桌面压力错误钉住非活动屏全部历史；direct 与 placeholder 使用相同优先级。

本次 pane `15` 修复已通过完整默认成员检查：Windows 的 25 个 Rust suite 共 4,709 项通过，另有 CLI E2E 24 项通过，合计 4,733 项，34 项 ignored；Linux 原生 headless workspace 的 `--all-features` 检查中，24 个 Rust suite 共 2,286 项通过，另有 CLI E2E 24 项，合计 2,310 项，30 项 ignored。计数不重复包含子进程内部重跑的单个用例。随后显式执行真实 Windows→Linux SSH transport 1 项及 rooted consumer 2 项，均通过，不将其他 ignored 归为通过。Windows 使用已准备的官方 ConPTY，Linux 与 Host 边界检查使用原生 Node 22.23.4；格式及 Host 边界检查通过。以上覆盖集成 `a75257d` 的同一代码；macOS 自动化以匹配提交的 CI 为准。原生窗口／GPU 仍须分别取证，headless paint 不等同于最终 GPU 像素。

本地主机的间接传输仍有平台边界：Linux 文件／POSIX shm 通过有界 descriptor read，普通文件不使用可能因并发截断触发 `SIGBUS` 的映射。macOS 的 POSIX shm FD 不提供 `read`／`write`，且对象仅允许初次 `ftruncate`；因此使用最多 32 MiB 的只读 `MAP_SHARED` 范围，复制所请求字节后立即释放映射，映射与副本合计先预留 64 MiB 临时工作额度。macOS 对象名最多 31 bytes，Linux 最多 255 bytes。以上不启用 Windows 间接传输，也不将远端路径解析到桌面主机。平台依据为 [Apple XNU 的 POSIX shm 实现](https://github.com/apple-oss-distributions/xnu/blob/main/bsd/kern/posix_shm.c)。

普通 SSH 子进程的间接媒体在接受及实际读取前重新核验前景进程组；同组本地父进程不能掩盖带远端命令的 SSH 子进程，无法证明本地时拒绝该传输。跨片段传输一旦经历远端或未知来源，后续本地片段不能恢复其读取权限；后续独立本地请求仍可正常使用。普通文字与直接传输不触发这项进程组扫描。文件／共享内存显式声明的读取长度超过偏移后实际可用范围时返回 `EBADF`，不将短内容截取成成功请求。

#### 当前实现：终端布局与屏幕生命周期（#42）

- 放置锚点由 daemon 在 Kitty 命令的流位置确定，采用包含已丢弃行计数的稳定文本行坐标。输出滚动和浏览历史时，图片跟随关联文本；完全超出 daemon 保留的 10,000 行历史的放置会过期，不会漂移到新输出。部分过期的图片只保留未丢弃的源切片；改变列数时复用同一 Rio 网格的精确行重排映射，不在桌面另建图片位置模型。Windows 本地 ConPTY 的 daemon 镜像与桌面消费者共用同一高度调整／光标补偿；原生 SSH 及远端 Linux 的标准 PTY 保持 Rio 的普通调整语义，不根据 GUI 所在平台选择 ConPTY。
- 图片只在所属屏幕绘制。主屏保留自己的资源和放置；进入／离开备用屏会释放上一轮备用屏图片，主屏与备用屏中的相同图片 ID 互不替换。滚动区域只移动完全位于区域内的图片，越过边缘的部分被永久裁切；跨页边距的图片保持固定。`DECCOLM` 的 set／unset 均与 Rio 一起恢复全屏滚动区域。部分裁切图片调整尺寸时只映射保留切片，不复活已丢弃源行。最终绘制仍受窗格视口裁切，不覆盖相邻窗格。
- `CSI 2J` 清除当前可见图片；其他普通文字擦除不删除图片。`CSI 3J` 丢弃历史中的图片部分，保留仍属于活动屏幕的部分。匿名资源失去最后一个放置后释放资源及会计；命名资源仍可再次放置。终端 reset 清除两屏图片；活连接中，用户清屏／“清空回滚”只通过控制器的有序 pane 命令清理，observer 不能获得清理／写入权限。已退出或断链的保留窗格则先退休 reader，再在本地清理文本、selection 及适用的派生图片：清屏保留原有历史，清空回滚同时丢弃历史与相关资源，不能向已终止 reader 请求清理；后续 `Ctrl+L` 仅发送到活连接。
- 窗口／分屏、终端字体及显示缩放变化继续使用实际测量的单元尺寸；自然像素尺寸与按单元指定的尺寸分别处理。`CSI 14t` 返回终端文本区域设备像素 `CSI 4;height;width t`，`CSI 16t` 返回单元设备像素 `CSI 6;height;width t`，统一由 daemon 回答，GUI 不重复应答。放置光标移动按占用行列执行，`C=1` 不移动光标。
- 透明像素保留 alpha，桌面解码结果采用绘制后端所需的 BGRA 通道顺序；多个放置共享像素。隐藏窗格继续消费状态和解码，不因图片输出通知整窗重绘；返回窗格时保留当前缓存，不要求应用重发。这不等于关闭 GUI 或重连后的图片恢复。

#### 当前实现：Unicode 占位符（#43）

- `a=p,U=1` 或 `a=T,U=1` 创建不可见的虚拟放置 prototype，不自行显示或移动光标。随后输出普通 `U+10EEEE` 网格单元，才按对应 prototype 的保持比例区域显示源切片。它与直接放置共用 pane 资源版本、预算及异步解码像素，不为每格复制或重传图片。
- 前景色编码图片 ID 低 24 位（indexed 模式使用色槽编号，true-color 模式使用 RGB 数值），第三个 diacritic 编码高 8 位；下划线颜色编码放置 ID，缺省或零时确定性选择该图片最小的虚拟放置 ID。首／次 diacritic 分别编码源行／列，按 Kitty 的三条左至右规则继承缺省坐标与高位；颜色属性变化、非连续显式坐标或普通文本会中断相关继承。无效 diacritic、缺失资源或放置不产生图片像素，PUA 字符及其组合符不进入普通字形绘制。
- 真正显示的切片由真实 Rio 单元控制：文字插入、删除、擦除、区域滚动、历史截断、列重排及主备屏切换同步改变图片，最终仍受窗格裁切。虚拟 prototype 没有物理位置，只受 `d=i/I/n/N/r/R` 删除；`d=a/c/p/q/x/y/z` 及其大写形式仅影响直接放置，不删除占位符 prototype。普通文字擦除可消除占位符显示而保留 prototype，后续输出匹配单元可再次显示。
- daemon 的资源引用查询与桌面视口使用共享行投影及 prototype 解析，不维护第二套占位符身份规则。桌面只投影当前 viewport 的真实行；隐藏窗格继续保留既有通知门控。当前 4,096 次放置上限合计计算直接放置和虚拟 prototype，不按显示单元扩增资源数。
- 共享确定性 PTY fixture 的真实独立 daemon → `RemoteTerminal` → rooted `TerminalView`／production decoder／paint 回归已在 Windows 通过，覆盖身份、继承、源切片、混合路径、单元擦除／移动和屏幕切换；另有独立 CLI／ConPTY 的查询、仅上传、prototype、删除和后续文字冒烟。测试窗口无 `HeadlessRenderer`；本轮 Windows 原生及 SSH 图片观察与这些自动化分开记录，macOS 和完整平台矩阵仍未验收，不构成 tmux/screen 兼容承诺。

#### 当前实现：预算与历史回收（#44）

- **最旧**在同一 daemon 内按资源准入单调序号确定，不按 GUI 最近访问时间、图片 ID 或墙钟排序；替换后是一个新版本。跨 daemon 的共享桌面池按资源首次成功接收的进程内单调序号排序，不假设远端主机共享墙钟。先回收无引用资源，再按对应范围的序号回收非可见历史。direct 的真实保留片段和 placeholder 的共享文本投影合并判定；活动屏 live rows 及必须保留的非活动主／备用屏内容受保护，隐藏或无 GUI 不会绕过预算。
- 多窗格共用聚合池。跨窗格回收只锁预算注册表和资源 slot，再通过合并唤醒让各 pane 按原输出顺序公布变更，不在持有某个 pane 锁时反向锁其他 pane。跨 daemon 桌面压力通过资源所属连接请求权威回收，daemon 必须重新核验 direct／placeholder 可见性及 screen；客户端不能要求删除受保护图。daemon 先有序公布本次权威回收效果，再仅向发起请求的 endpoint 发送 `DaemonMsg::GraphicsPressureResult { key: u64, reclaimed: bool }`，不向同 pane 的其他消费者广播完成结果；`reclaimed=false` 明确结束本次未能回收的请求。若保护内容已耗尽任一适用预算，新图按 `ENOSPC` 及 `q=1/2` 规则拒收，不替换旧图、不改变文字或光标。
- 每份资源最多有一个未完成的桌面压力请求；重复需求不能叠加在途请求。客户端只在收到匹配资源 `key` 的完成结果时解除在途锁，不用其他资源的结果或普通图形更新冒充完成。拒绝只结束本次尝试，不永久禁止该资源：后续新的准入需求可重新请求，由 daemon 按届时全部消费者的最新视口决定。另一消费者滚离历史、隐藏或 detach 后，即使没有新 PTY 文字、资源变更或本窗格重绘，也不必等待这些事件才允许后续需求重试。不新增自动重试定时器，不在收到拒绝后立即循环重发。一个放置离开 live 不解除同资源其他 live 放置或消费者历史视口的保护；隐藏只撤销该连接的视口事实，不把 live 内容变成可回收历史。
- 只有预算回收留下无像素元数据。重访仍保留的原位置时，用界面语言在原区域内绘制 `Image evicted`／“图片已淘汰”；颜色使用 `muted_foreground`，保持原裁切。它不是终端文本，不进入选择内容，不插入行、不写 PTY、不发 toast。应用删除、clear／reset、历史过期会删除相应位置，不留下回收提示；拒收且未创建放置的新图不获得假位置。
- 删除、替换、回收、连接退休及 pane 关闭都会使旧 completion 失效；CPU／GPU 信用在实际持有者释放后才归还。图片事件批次在窗口上下文立即回收 retired atlas，已有周期后台 UI 更新继续兜底隐藏 pane，不必等它重新 paint。为避免旧大 page 被后续小 tile 长期钉住，必要时对同一窗口的终端 atlas 做实际 compaction：批量释放旧 tile，保留当前 CPU 图片，并使存活图片在下次 paint 重新注册／上传。只有被失效 tile 的 owner 当前已显示时才安排整窗重绘；仅有隐藏 pane 的旧 tile 被释放不会唤醒无关可见面。隐藏 pane 返回时仍显示当前像素，不会永久钉住退休 GPU 票。daemon 不保留像素的隐藏备份以伪装可恢复。
- 真实 daemon-session 与生产 GPUI consumer 的确定性小预算回归已在 Windows 通过，覆盖可见保护、跨 pane／daemon 压力、回收提示、容量拒收及关闭后再次准入。Windows 原生 Shell／CPU／GPU 采样与 SSH 压力观察见下方；macOS、其他 DPI、远端峰值和完整压力认证仍未完成。

##### 可执行压力夹具与待测证据

`history` 在 direct／placeholder 两条路径交替输出渐变、棋盘与半透明像素，然后退出；向上浏览可检查最旧历史提示及原位置裁切。`visible` 在同一区域重复创建不同资源，使保护图片先占满配额，后续新图片应被拒收而不替换已接受图。所有图片命令使用 `q=2`，不把协议应答留给退出后的 shell；看到 `KITTY_PRESSURE_DONE` 后输入普通 shell 命令验证交互。以多窗格并发及隐藏／重新显示工作区补充聚合压力，另做删除、清理、关闭后的资源释放观察。

#### 当前实现：存活会话的图片恢复（#45）

- 图片资源与放置保留在仍运行的 pane daemon 内，不依赖旧窗口缓存。销毁旧消费者后，新消费者重新接收仍被保留的资源版本、直接放置与 Unicode 占位符 prototype，并结合文字、历史锚点及当前主／备用屏恢复；无 GUI 时产生、替换或删除的内容也进入同一权威状态，不要求应用重传。
- 恢复先按实际资源成本与元数据身份申请容量，再在 pane 锁内把最新文字、尺寸、模式、screen／history 和图片状态作为同一次快照接入 live。普通文字或纯几何变化不撤销仍适用的资源授权；资源集合变化时先释放旧授权，再在有限期限内重新准入。持续变更或容量不足导致明确附着失败，不静默漏图、不启动替代 shell，也不借恢复绕过预算。资源／放置可先于权威 `Screen` 解码，但新 reader 代次在其到达前不把旧坐标或默认 history origin 当作可绘制坐标，首个 `Screen` 即使数值全为零也会唤醒恢复绘制。reader 退休会拒绝旧帧和解码完成，但保留已知的权威坐标；已退休 pane 的本地清屏在同一锁内更新清理后的 origin，保留的历史 placement 可继续重绘，不影响重连等待权威快照的规则。
- 已删除或离开历史范围的位置不会复活。被预算回收的历史资源只恢复无像素提示及仍有效的位置；新消费者不能从旧 window／decoder／texture 中取回隐藏副本。控制器接管与 observer 权限沿用原会话规则，daemon／pane／生产者身份保持连续。
- 断连、接管或 observer 失效后，旧 writer 关闭双向连接，输入 reader 以有界接收检查既有 owner，并保留跨读取的半帧。活连接空闲或尚未收齐 Input 不被当作新命令或断链；reader、Session 及容量票在实际退休后释放，不提前归还仍被持有的资源。

真实 daemon 回归覆盖共享资源、多个裁剪放置、两屏与历史、detached 修改、replay／live 并发、部分授权拒绝、控制器抢占及跨接收期限的半帧；真实 rooted GPUI 回归覆盖旧 view／store／texture 全部释放后的 fresh 恢复、像素与几何、无重传、回收提示和容量不足的明确断连。测试先按实际字体测量并设置窗口物理尺寸，再挂载终端，避免 headless 默认最大化首绘意外 resize 正在恢复的备用屏。

另以独立生产 CLI／ConPTY／daemon 冒烟验证：首客户端销毁后，同一生产者在 detached 状态替换资源、删除另一份并创建新占位符；新 `PaneClient::observe` 只恢复新版本及同代文字，上传计数不变，普通输入仍可到达。该 CLI 证据与下面的原生 GUI／SSH 结果分开记录。daemon 终止后不保留图片，未新增图片磁盘缓存。

Windows 原生补充：禁用隔离实例的托盘后，以标题栏关闭按钮真正退出 GUI PID `53860`，新 GUI PID `46676` 重新附着同一 daemon PID `35412` 与 shell PID `50728`。两张 direct／Unicode 图片在新窗口恢复，发送器早已退出，发送记录在重开前后均为 `789 bytes`，没有重新执行发送器。此证据仅覆盖存活 daemon；后续为隔离 SSH 信任库而重启 daemon 不属于图片恢复。

#### 完整功能的已确认能力边界


以下是 #39 的完整目标；尚未完成的平台与原生验收不能由局部实现或自动化结果替代：

- 显示静态图片、透明背景、应用连续替换的画面，以及 daemon 保留的完整帧与手动选帧；正确处理终端滚动、裁剪和重绘。不包含图片查看器、点击放大、复制／另存为或自动动画播放。
- 图片属于窗格会话，不属于某个窗口。在历史保留范围和资源预算内，切换工作区、关闭后重开 GUI，以及重新连接同一存活 daemon 后，图片应恢复，无需应用重新发送。
- 图片不新增磁盘持久化；daemon 结束后不保证历史图片恢复。智能体重新启动后主动重绘，是新的图片输出，不是 lyrel 恢复了旧图片。
- 以 [Kitty graphics](https://sw.kovidgoyal.net/kitty/graphics-protocol/) 为支持协议，覆盖传输与独立放置、重复放置、裁剪、删除、Unicode 占位符，以及已有的传输并显示路径；SIXEL 与 iTerm2 inline images 不列为本次支持协议。
- lyrel 如实报告已实现的能力。尚未识别 lyrel 的应用可通过自身公开选项选择图片协议；接入文档应注明已验证的应用版本与启动方式，不通过伪造 `TERM_PROGRAM` 取得支持，不承诺所有第三方应用自动识别。
- 单图、每窗格及整体图片资源均须有界，预算不能只按压缩文件大小或图片张数计算。优先回收最旧的非可见历史图片，保留文字；可见图片已占满预算时拒绝新图，不无限增长或阻塞 Shell。被回收图片不再属于可恢复内容。
- 因预算回收历史图片后，只在仍保留的原显示区域绘制“图片已淘汰”提示，不改写终端文本、插入新行、写入 PTY 或弹出通知。应用主动删除、清屏或显示位置离开历史保留范围时不显示此提示；尚未成功接收的新图没有显示位置时，按协议应答规则报告失败。
- 正式兼容范围为 Windows/macOS 桌面的本地窗格，以及经 lyrel 原生 SSH 远程工作区连接 Linux daemon 的图片路径。tmux/screen 的中转配置与版本组合不列入本次兼容承诺。

#### 实现验收

以下条件全部满足才算实现完成；仅显示第一张图片不构成交付：

1. **真实智能体出图**：记录 omp 的正式版本与启动配置，在 lyrel 实窗显示 SVG 转成的图片和截图，而非源码；不依赖修改 omp 源码或伪造终端身份。
2. **协议语义**：仅传图不显示，放置后才显示；重复放置、裁剪、替换、删除、透明背景和 Unicode 占位符均正确，不同窗格使用相同图片 ID 不串图。遵守协议的删除应答、光标移动及主屏／备用屏语义。
3. **终端行为**：滚动、分屏缩放、字体／DPI 变化、清屏及主屏／备用屏切换不留下错位或残影；隐藏窗格出图不驱动整窗无效重绘，窗口像素与字符单元尺寸查询与实际显示一致。
4. **存活会话恢复**：应用发送图片后不再重发，关闭重开 GUI 或重连同一 daemon，仍能恢复预算内且位于历史保留范围的图片；恢复与实时输出交错时不重复、不错序。
5. **资源与异常**：连续出图、超大尺寸、损坏数据和分块中断不造成无限内存增长、Shell 卡死或相邻文字丢失，回收提示与拒收符合上述约定。资源上限须核算解码后像素、缓存副本及实测峰值，交付时公布实际默认上限，而非只限定图片张数。
6. **平台证据**：Windows/macOS 本地与原生 SSH→Linux 路径分别记录实际运行结果；未验证的平台保持明确标注，不以单机测试替代。tmux/screen、图片落盘及图片查看器不属于本次验收范围。

## 机器

上述一切都按**机器**独立存在。你的笔记本电脑是一台机器；通过 SSH 连接的开发机是另一台，它有自己的服务器、工作区和窗格。

切换器会将它们列在一起，CLI 则通过 `-m` 访问它们：

```bash
lyrel -m devbox ls
```

远程窗格运行在远程机器上——文件、仓库、git 数据和进程树都在那里。
[远程工作区 →](/remote/workspaces)

### 机器树的事务与恢复

daemon 是机器树的持久化权威，`lyrel-core::core::machine` 是 GUI、CLI 和 server 共用的 canonical interface。内部 `model` 与 `layout` 保存机器／工作区／标签页／窗格的领域定义和纯布局操作，`operations` 负责无副作用的校验与记录整理；`store` 中的 `MachineStore` 仍是唯一事务 interface，工作区、标签页、窗格、sidecar 与事实观察都不能绕过它另建 feature store。

结构变更沿用 `notify_order` → `state` 的加锁顺序：在状态锁内完成修改和同步持久化，失败先回滚，再返回错误；只有成功接受后才释放状态锁并按原顺序通知订阅者，通知期间仍持有顺序锁。订阅列表只在复制回调时加锁，回调运行时不持有状态锁或订阅锁，发起操作的订阅者仍不接收自己的 delta。窗格事实和工作区活跃时间保留原有延迟写盘策略，由同一个 store 的弱引用定时线程刷新；它们不被改成异步发布，也不承诺每次通知前已经落盘。连接 attachment 仍只存在于内存，不随机器树写盘。

`persistence` 负责现有 `machine.json` 格式、原子私有写入、三代间隔备份、损坏文件隔离与恢复；store 负责决定何时写入以及失败后的回滚／重试标记。有效主文件优先，损坏或不可读取时沿用现有备份恢复规则，不重建已有工作区／标签页／窗格 ID；启动读回的窗格等待原有复活流程。`paths` 负责 `LYREL_DATA_DIR` 优先于实例配置目录的解析及 daemon 启动时的既有旧目录接管规则，路径查询本身不移动数据。`appearance` 单独保存 GUI 最后应用的明暗提示，保持缺失／损坏时采用浅色默认值和未变化时不写盘的语义，不取得机器树写入权。

窗口侧 `MachineMirrors` 仍独立维护客户端镜像：拉取期间的本地操作按原规则重放到返回的快照之上，避免旧快照撤销新操作。它不与 daemon store 合并，也不接管事务、持久化或恢复。
