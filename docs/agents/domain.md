# 领域文档

工程技能探索代码前，按下面的规则消费本仓库的领域文档。

## 探索前阅读

- 仓库根 `AGENTS.md` 及任务涉及的正式文档；以当前源码、配置和实际运行证据核对其中约束。
- 根目录 `GLOSSARY.md`（如存在）：输出领域概念时使用其中定义的术语。
- `docs/adr/`（如存在）：读取与即将改动的区域相关的 ADR。

上述文件不存在时静默继续：不指出缺失、不提前建议创建；`/domain-modeling` 在术语或决策真正落定时才惰性创建。

## 文件结构（单上下文）

```
/
├── GLOSSARY.md
├── docs/adr/
│   ├── 0001-<标题>.md
│   └── 0002-<标题>.md
├── src/
└── crates/
```

将来若出现根目录 `GLOSSARY-MAP.md`，说明仓库已转为多上下文：按其中指向逐个读取相关上下文的 `GLOSSARY.md`，并检查 `src/<context>/docs/adr/` 的区域决策。

## 产品语言

- **lyrel**：面向桌面本地开发与桌面远程开发的终端工作台。
- **桌面本地开发**：在运行桌面应用的同一台电脑上执行开发任务。
- **桌面远程开发**：通过桌面应用连接另一台主机，并在该主机上执行开发任务。
- 手机操作不属于桌面远程开发，也不属于当前产品范围。

## 使用与冲突

- 输出中出现领域概念（issue 标题、重构提案、假设、测试名）时，使用术语表定义的词汇，不漂移为术语表明确避免的同义词。
- 需要的概念尚未收录时：先判断是“发明了项目不用的词”还是真实缺口；真实缺口交给 `/domain-modeling`。
- 输出与现有 ADR 冲突时，显式指出而非静默覆盖：`有违 ADR-0007（事件溯源订单），但值得重新讨论，因为……`

## 维护

- 产品行为更新到对应使用文档；依赖、平台和开发约束更新到安装指南或仓库工作指南；视觉约束更新到界面设计规范。
- 术语含义、文档约束与代码冲突时，指出具体位置及影响，先查证再决定；不静默改写已确认的产品边界。
- 只记录当前仍有效的约束和明确的验收缺口；不将历史试验或已被取代的方案当作当前要求。
- 已确认内容直接收敛到相关正式文档；未获明确要求时，不另建术语表、架构决策目录、规格或工单树。
