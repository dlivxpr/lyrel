lyrel 通过 [russh](https://github.com/Eugeny/russh) 处理 SSH 协议，连接失败时不会自动回退到系统 `ssh`。配置了 `ProxyCommand` 时，Lyrel 会直接执行其中指定的传输程序。

正因如此，以下功能才得以实现：将凭据存入操作系统钥匙串、在侧面板中使用
[SFTP](/remote/sftp)、在会话期间添加[端口转发](/remote/port-forwarding)，
以及在窗格内以浮层形式显示身份验证提示，而不是让密码回显到 shell 中。

协议层使用正式 registry 发布的 `russh 0.63.3` 与 `russh-sftp 2.4.0`，精确身份由
`Cargo.lock` 固定。依赖升级不改变主机密钥信任模型：不协商 OpenSSH 主机证书，
也不把证书中的裸密钥自动视为可信；当前不支持 CA 信任。

主机密钥仍按 `known_hosts` 校验。未知或变更的密钥由用户决定是否接受、是否记住；
拒绝或取消不会写入新信任。标为 `@revoked` 的密钥即使关闭普通主机密钥验证也会拒绝。
用户接受并记住替换密钥时，会先移除被替代的信任记录，避免旧密钥继续被信任。

<a id="profiles"></a>
## 配置

**设置 → SSH → 主机**包含完整的连接配置。基本字段如下：

| 字段 | |
|---|---|
| **名称** | 此连接的标签 |
| **主机** | 主机名或 IP 地址 |
| **用户** | 登录用户——留空则在连接时确定 |
| **身份验证** | *自动*（尝试所有适用的方法）、*GSSAPI*、*密码*、*密钥*、*代理*或*双重验证* |
| **跳板主机** | 另一个配置，或一条 `ProxyJump` 链 |
| **端口转发** | 随连接建立而启用的规则 |

列表顶部的**默认设置**会由所有主机继承，因此需要全局应用的设置只需配置一次。

右键单击 SSH 标签页会打开该连接的主机表单——对于已保存的连接，菜单项为**编辑主机**；
对于手动输入地址建立的连接，则为**另存为 SSH 主机**。工作区切换器的机器菜单中也有
相同的菜单项，因此发现主机名或密码输入错误时，可以直接从当前标签页进行修正。
菜单操作针对的是打开菜单的标签页，而不是当前获得焦点的窗格。保存时，表单会基于
整个活动连接打开——包含代理、密钥、端口转发以及地址——因此最终保存的主机就是
你当前连接的那一台。

已保存的主机保存在与 `config.json` 同目录的 `servers.json` 中，而不是保存在
`config.json` 内，因此在机器之间同步 `config.json` 时不会携带这些主机。
密码和密钥口令存入**操作系统钥匙串**，绝不会存入这两个文件，也绝不会以明文形式
写入磁盘。配置菜单中的**忘记密码**会移除已存储的密码。

删除配置会删除其钥匙串凭据，并移除通过该配置连接的远程工作区条目——
确认对话框会先统计这些条目的数量。机器上的会话本身会继续运行；
[这些条目会如何处理 →](/remote/workspaces#deleting-a-profile)

### 高级

配置中的**高级**选项按以下类别分组：

| 分组 | 字段 |
|---|---|
| **身份验证** | 身份文件（每行一个路径，支持展开 `%h`/`%r`）、代理转发 |
| **代理** | ProxyCommand（直接执行程序与参数，替换 `%h`／`%p`／`%r`，不自动解释 Shell 语法）、SOCKS5 代理、HTTP 代理 |

所有留空的字段都表示“使用库的默认值”，因此只需填写确实需要覆盖的选项。

<a id="inline-images"></a>
## 终端内联图片

原生 SSH 工作区复用本地 pane 的 Kitty 图片协议、放置、Unicode 占位符与恢复状态，
不另建 SSH 图片模型。远端应用应优先直接传输像素或 PNG；文件／共享内存请求由
负责 PTY 的远端 daemon 按自己的能力与路径读取，不在桌面文件系统上查找同名路径。
这与下方 OSC 5522 **剪贴板**功能不同，也不要求开启远程剪贴板权限。

本地与远端使用同一套 [IPC 版本与协商规则](/reference/architecture#ipc)。动画帧、局部编辑、合成、单帧删除、父子图与播放由持有该窗格的存活 daemon 管理。桌面在取得 grid 锁后重新采样视口，并在首次收到 Screen 或重连后重新上报。图片资源不足时，所属 daemon 核验各消费者的保护状态，再向请求端返回结果。

远端 daemon 的编码资源、元数据、partial／校验工作，与桌面的 source、派生像素、
解码工作及 atlas／GPU 分别计账；SSH 重连不豁免任何预算。恢复仅限同一存活 daemon
仍保留的内容，不恢复已删除／淘汰的像素，也不新增图片磁盘持久化。
[预算和历史提示规则 →](/getting-started/concepts)

<a id="native-ssh-tests"></a>
### 重现真实 SSH 回归

以下 opt-in 用例经过生产 SSH 引擎、原生 router、真实 Linux PTY 与同一 pane 协议，
不是本地 socket 替身。维护者须先准备独立 Linux 账号或隔离 HOME 的 SSH 服务，
预部署匹配当前版本／方言的 `lyrel-server`，并提供 Linux Node 22.19+。
shell／control 报告的 HOME 与 SFTP `Realpath(".")` 必须同属该隔离目录；
仅在 shell 中修改 `HOME` 不足以隔离 SFTP。不要指向真实工作账号的 HOME。

`lyrel-server` 的 `native_ssh_graphics`、`native_ssh_lifecycle`、`native_ssh_surface` 和 `remote_interrupt` 需要显式启用 `native-ssh-tests` 才参与普通测试命令的编译。具备真实端点后，按下文选择目标并用 `--ignored` 执行。

本机与远端必须真正满足路径隔离前提：本机创建的绝对路径哨兵在远端应不存在。Linux 客户端连接同 UID、同文件系统的 loopback SSH 时，只有隔离 HOME 并不满足这个条件；先以真实 SSH 检查哨兵的不可见性，再运行 locality 用例。本轮使用不提权的 user／mount namespace，将 propagation 设为 private，**只给新建的任务自有本机 `TMPDIR` 挂 256 MiB 有界 tmpfs**；sshd 与远端 daemon 留在 namespace 外，结束后卸载该自有挂载。不挂全局 `/tmp`，不修改 sysctl、账号、系统 sshd 或个人配置；内核不允许该方式时如实记录前提阻塞，不能关闭断言或把失败记为通过。

远端 `regular` 文件仍放在自有生产者目录；`t=t` 的正向 handoff 则用 `fs.mkdtempSync(path.join(os.tmpdir(), 'lyrel-media-'))` 创建真正的唯一临时目录，保留 `tty-graphics-protocol` basename 和 `finally` 清理。不要把任意 HOME 子目录称作 eligible temp，也不要为通过夹具而放宽 daemon 的删除范围或把 HOME 伪装为 `TMPDIR`。

先构建 `cargo build --locked -p lyrel-server`，然后在启动测试的进程环境中设置：

| 环境变量 | 内容 |
| --- | --- |
| `LYREL_TEST_SSH_HOST` | 专用测试服务的主机地址 |
| `LYREL_TEST_SSH_PORT` | SSH 端口，必须显式提供 |
| `LYREL_TEST_SSH_USER` | 隔离测试账号 |
| `LYREL_TEST_SSH_IDENTITY` | 专用私钥的本机绝对路径；不要把私钥正文写入命令或日志 |
| `LYREL_TEST_SSH_KNOWN_HOSTS` | 仅含该端点一条 `ssh-ed25519` 固定公钥记录的文件；非 22 端口使用 `[host]:port` |
| `LYREL_TEST_SSH_REMOTE_HOME` | shell／control／SFTP 共用的隔离 Linux HOME 绝对路径 |
| `LYREL_TEST_SSH_NODE` | 该 Linux 主机上 Node 可执行文件的绝对路径 |
| `LYREL_TEST_SSH_LOCAL_SERVER` | rooted GPUI 用例所需的同一提交本机 `lyrel-server` 绝对路径 |

```bash
cargo test --locked -p lyrel-server --features native-ssh-tests --test native_ssh_graphics native_ssh_graphics_ \
  -- --ignored --nocapture --test-threads=1 --skip nested_ssh
cargo test --locked -p lyrel --lib native_ssh_consumer_ \
  -- --ignored --nocapture --test-threads=1
```

夹具使用临时本机配置、固定主机公钥和明确的测试身份；未知主机不会自动接受，
缺少前提会使显式用例失败。结束时仅移除本次创建的 pane 与唯一生产者目录；
远端 daemon 由测试端点的维护者管理，用例不停止它或删除整个远端 HOME。

该 transport 目标分别包含基础恢复／压力、已加载帧的实际网络像素计数、准入拒收／部分 grant 取消／observer 控制权／不兼容方言，以及 Linux regular file／eligible temp／POSIX shm 的正向读取和生命周期。rooted consumer 另检查 full／partial／edit／compose／frame delete 的实际 BGRA、direct／relative／Unicode 同版本图、隐藏多消费者、真正无消费者时的变更、fresh 恢复及 replay/live cutover。它们是执行入口，不是通过声明。

嵌套用例额外要求 Linux 主机已有专用第二层端点及 `LYREL_TEST_SSH_NESTED_HOST`、`LYREL_TEST_SSH_NESTED_PORT`、`LYREL_TEST_SSH_NESTED_IDENTITY`、`LYREL_TEST_SSH_NESTED_KNOWN_HOSTS`。后两项是 **Linux 上**的绝对路径，不能上传桌面私钥、借用个人 SSH 配置或关闭固定 pin 验证。第二层使用真实 `/usr/bin/ssh -tt -F /dev/null`，间接媒体必须返回 `ENOTSUPPORTED`，直接 RGBA 仍须成功。缺少这组前提时，先单独执行非 nested 用例；不得把过滤掉的 nested 用例记为通过。

```bash
cargo test --locked -p lyrel-server --features native-ssh-tests --test native_ssh_graphics \
  native_ssh_graphics_nested_ssh_refuses_indirect_and_preserves_direct \
  -- --ignored --exact --nocapture --test-threads=1
```

该 loopback nested 夹具要求第二层端点可访问第一层相同的隔离 Linux 文件系统，既有 fixture 脚本路径与自有媒体目录在两层均有效；它证明真实 SSH 前景进程带来的 locality 撤销，不冒称支持任意跨主机文件映射。regular／temp／shm 与桌面哨兵使用相同唯一 basename、不同像素；只检查 EBADF 拒绝一个不存在的 Linux 路径不足以替代这项隔离证明。

两层前提都齐备时，完整 headless 入口不跳过 nested；Linux 不运行根桌面包或 rooted GUI 命令：

```bash
cargo test --locked -p lyrel-server --features native-ssh-tests --test native_ssh_graphics \
  -- --ignored --nocapture --test-threads=1
cargo test --locked -p lyrel-server --features native-ssh-tests --test native_ssh_lifecycle \
  -- --ignored --nocapture --test-threads=1
```

**2026-11-05 Linux headless 升级验收（[#173](https://github.com/dlivxpr/lyrel/issues/173)）：**`31712d8e` 的上述真实 native SSH `5` 项和 shell-channel lifecycle `1` 项均 exit `0`，没有过滤 nested。双方使用生产 router／daemon 与真实 Linux PTY、固定 ed25519 pin 和独立两层 key；远端同一存活 daemon 的生产 server 为 `5df2f286` Release（该后续提交只修测试夹具，生产源码相同），实际为 `0.3.0`、pane `17`／control `16`，远端 Node `22.22.1`。覆盖拒收／取消／observer／不兼容 peer、图片恢复与排序、regular／eligible temp／POSIX-shm 生命周期以及 nested 间接媒体 fail-closed、直接 RGBA 成功。已加载帧记录 `initial_resource_pixel_bytes=16`、`steady_resource_pixel_bytes=0`、`steady_select_packets=21`，不把 Select 包数当作 FPS。

同轮生产 SFTP `Realpath(".")` 与 control HOME 一致；独立 OpenSSH SFTP oracle 对 `4122` bytes 的 UTF-8／二进制 payload 完成 upload／rename／download，前后 SHA-256 相同，只清理本次对象。该 oracle 不冒充生产 SFTP 全操作覆盖；完整 stdio Host 契约另已在 Linux 全 feature 套件实跑。首次同文件系统的 `2` 项失败及隔离后的 temp 夹具 `1` 项失败均保留，只有修正真实前提／夹具后才记录上述通过。这里只证明 Linux headless／真实 SSH 行为，不证明 GUI GPU、真实 Kerberos 认证、Windows 或 macOS 原生验收。

### 连接、历史与工作区所有权验收

历史必须分别检查两条生产路径：远端 daemon 工作区通过对应 `Host` 读取其 HOME；
单个原生 SSH shell-channel 窗格则通过自己的 SFTP 连接读取远端历史。
在工作区内再次执行 `ssh` 后，不得把工作区主机或本机历史播种到内层 scope。
这些场景与工作区重连所有权是独立的，不能用一次 SSH 连接成功代替。

以下 rooted 消费者复用上述固定 key／pin、隔离 HOME 与同提交本机 server 前提。
每条命令须分别启动测试进程，因为配置覆盖是进程级且只写一次；内跳用例还需要上文的
`LYREL_TEST_SSH_NESTED_*`，不会使用个人 SSH 配置。
原生 shell-channel 历史用例开启 shell integration，并先确认真实连接和 prompt editor 已激活；
只连通关闭 shell integration 的窗格，不能证明 lyrel 的历史播种正常。
隔离 SSH 服务报告的 `SHELL` 必须与实际执行者一致，不能用广告 bash、强制执行 fish 的夹具判定产品失败。
更正服务端 shell 前提后，使用新的自有本机 router daemon 验收；同一 daemon 对相同连接 key 的 shell probe 会缓存，关标签页或切换 profile 开关不代表重新探测。

```sh
cargo test --locked -p lyrel --lib native_ssh_connected_shell_seeds_remote_history -- --ignored --test-threads=1 --nocapture
cargo test --locked -p lyrel --lib native_ssh_workspace_history_uses_remote_home_and_isolates_inner_hop -- --ignored --test-threads=1 --nocapture
cargo test --locked -p lyrel --lib native_ssh_workspace_reconnect_yields_to_active_client -- --ignored --test-threads=1 --nocapture
cargo test --locked -p lyrel --lib native_ssh_host_menu_disconnect_preserves_other_window -- --ignored --test-threads=1 --nocapture
```

所有权用例在真实传输中断后，由另一个真实 control 客户端取得工作区，再让 rooted 工作台执行生产重连，
检查工作区是否仍归活动客户端、窗口是否显示被接管，以及显式 **Take Back** 是否仍可取得控制权。
这不是两个独立原生 GUI 进程的验收。菜单用例经过生产工作区行更多菜单与真实 pointer down/up，
检查断开后无关 rooted 窗口的工作区与标签仍有效；原生窗口仍须另做同一旅程验收。
测试入口和夹具就绪不代表这些场景已经通过；须分别记录 rooted、真实 SSH 与原生窗口证据。

### 双路由前台中断与远程工作区重连（#433）

复用上文的 `LYREL_TEST_SSH_*` 固定 pin、隔离 HOME 和 Node 环境。远端还需提供 Linux `/proc`、`/bin/bash`、`/usr/bin/env` 与 `stty`。由端点维护者预先提供与待测提交匹配的 Release server 和专用 daemon。仅在已授权的专用端点上运行，保持现有 OpenSSH、主机密钥与账号配置。缺少配置时显式失败。

先在采样窗口之外完成下列构建和测试编译。保留一份 Release 测试驱动。按每轮版本选择匹配的远端 Release server，并将 `LYREL_TEST_SSH_INTERRUPT_LOCAL_SERVER` 设为该版本本机 Release `lyrel-server` 的绝对路径。未设置时使用随驱动构建的本机 server。记录两端二进制的 SHA-256。在同一对预留机器上交替运行，暂停其他构建、测试和 GPU 工作负载。

```bash
cargo test --release --locked -p lyrel-server --features native-ssh-tests --test remote_interrupt --no-run
LYREL_TEST_SSH_INTERRUPT_SAMPLES=25 cargo test --release --locked -p lyrel-server \
  --features native-ssh-tests --test remote_interrupt ssh_interrupt_and_workspace_reconnect \
  -- --ignored --exact --nocapture --test-threads=1 > "$LYREL_SSH433_LOG" 2>&1
```

```powershell
pwsh scripts/cargo-windows.ps1 test --release --locked -p lyrel-server --features native-ssh-tests --test remote_interrupt --no-run
$env:LYREL_TEST_SSH_INTERRUPT_SAMPLES = '25'
pwsh scripts/cargo-windows.ps1 test --release --locked -p lyrel-server --features native-ssh-tests --test remote_interrupt ssh_interrupt_and_workspace_reconnect -- --ignored --exact --nocapture --test-threads=1 > $env:LYREL_SSH433_LOG 2>&1
```

每次指定一个本次自有的 `LYREL_SSH433_LOG` 路径，保存完整输出和真实退出码。每条路由先跑 1 个预热，再跑 `LYREL_TEST_SSH_INTERRUPT_SAMPLES` 个样本，默认值 `1` 用于最小功能验收。正式比较保留每轮的所有样本和 p95，以及多轮的范围和失败数。记录两端 `git rev-parse HEAD`、系统及硬件、Node／OpenSSH 版本、daemon PID 与网络条件。在同一条件下先记录实际网络 RTT，可将独立测得的 RTT 毫秒中位数填入 `LYREL_TEST_SSH_INTERRUPT_NETWORK_RTT_MS`。`ssh_control_rtt_*` 是 12 次生产 SSH control `Ping` 的往返时间，包含 IPC 和处理开销。网络 RTT 未提供时输出 `null`。

- 两条路由使用相同的 Linux 前台任务和 `80×24` 网格。正常原生 SSH shell channel 与远端 daemon 持有的工作区 PTY 各运行同一脚本。脚本每 16 ms 写入 128 行，每行含 CRLF 共 64 bytes，目标 512,000 PTY bytes/s。客户端校验编号和 payload，读到第 3,072 行后用生产 pane `Input` 发送 `0x03`。隔离 PTY 启用 `ISIG` 和 `NOFLSH`，令 Ctrl-C 触发真正的 SIGINT 并保留已写入的输出。记录每轮实际产量与按远端单调时钟计算的输出率。
- `input_to_ack_ms` 从本地 `Input` 发送前计至收到任务的 ACK 行。验证 ACK 前每一行完整、连续、无重复，ACK 的行数与接收一致，ACK 后任务停止输出，Bash 返回状态 130。继续等真实 Bash prompt 并发送一条新命令，等到对应结果才记为可用。指标边界是生产 pane 协议层。
- `remote_receipt` 来自本轮私有远端目录中的独立文件。任务在 SIGINT 回调入口读取 Linux 远端单调时钟，写出 ACK 后保存文件。回调时间包含从内核投递到 Node 回调开始的调度时延。只在远端时钟域内求差，客户端从终端 ACK 获得的时间保留为往返量。文件同时记录前台进程组、任务 PID 和处理时的行数，并由客户端逐项核对。
- 原生 SSH 在同一本地 router 上断开 pane 客户端，重新附着同一 pane 并核对 Bash PID。远程工作区另做一次硬重连。仅重启本次自有的本地 router，确认旧流断开，再建立新的真实 SSH control 和 pane 路由，核对同一个远端 daemon instance／PID、workspace、tab、pane 和 Bash PID。两条路由都用 `Snapshot` 验证已完成任务的编号行、ACK、退出状态和探测结果，再经实时 `Output` 核验新命令成功。远程工作区的 `restore_to_usable_prompt_ms` 包含本机 router 重建、固定 pin 的重连、fixture 的 SFTP HOME 核验、回放验证和新命令往返。原生 shell channel 的附着指标适用于同一个仍在运行的 router。
- `SSH433` JSON 行记录样本、汇总和进程身份。远端 Node 的 `resourceUsage` 包含进程 CPU 时间（µs）和峰值 RSS（KiB）。正式运行另用 OS 计数器按 PID 采集本机 router、远端 daemon 与专用 sshd 会话进程的 CPU 和内存。Linux 可运行 `pidstat -u -r -p <PID列表> 1`。Windows 可轮询 `Get-Process -Id <PID>` 的 `CPU`、`WorkingSet64`、`PrivateMemorySize64`。保存采样间隔、单位、空闲与负载阶段的原始数据，并按同等工作量比较。该 headless 进程链的 GPU 指标不适用。实际桌面按键、自动重连状态条和已呈现像素需在专用原生窗口中另行记录。
- 原生窗口补验使用同一份 `crates/lyrel-server/tests/fixtures/remote_interrupt.mjs`。由专用端点维护者准备脚本和私有临时目录，使用已有、已核验的 SSH 配置，通过隔离的普通 `lyrel-app` 分别打开原生 SSH 窗格和远程工作区窗格。在两条路由各启动 `stty isig intr '^C' noflsh; node <任务脚本绝对路径> 001 <私有目录中的新证据文件>`, 在编号行滚动时按 Ctrl-C，检查 ACK、紧接着的 prompt 和新命令输出。退出再打开同一隔离窗口，核验原生 SSH 窗格的本地 router 附着。重连远程工作区时保持远端 daemon 存活，检查原始窗格、任务最后几行、ACK 和新命令回显。手动按键与精确到第 3,072 行的自动化样本分别记录。

当前条目提供运行方法。真实两端的网络、CPU／内存、原生窗口和基线／候选比较仍待在已授权的预留环境中采样。


- `input` 原样发送指定 `pane: 0|1` 的命令；两个 pane 的 load 完成后分别发送 `start\n`。`capacity` 原样上传并运行 `scripts/kitty-capacity.mjs --pane 0|1`，每 pane 固定 60 个 distinct `1920×1080` raw RGBA 帧，包含固定 seed／frame-ID barcode。不能传小尺寸替代。读取 `pane-0.pty.log`／`pane-1.pty.log` 中真实 `KITTY_CAPACITY_STATE`，要求两边各 `uploads=60` 和 `rawBytes=497664000`；任何 `ENOSPC` 都是验收失败。
- `sample` 加 `label`（ASCII 字母数字或 `-`）写出实际 SSH pane 协议累计计数：`graphics_bytes`、`resource_pixel_bytes`、`resource_packets`、`select_packets`。先在开始 load 前采 `before-load`，两 pane 全部加载后采 `loaded`，播放稳定后采 `steady`；steady 差值必须没有新增 Resource 像素且 Select 持续增长。它测的是真实 SSH channel 中图形协议有效负载，不冒称包含加密封装的 TCP 总字节，也不以发送端 stdout 计数替代网络观察。

`partial` 与 `frames` 复用同一个 `scripts/kitty-frames.mjs`，依次发送 `partial\n`、`edit\n`、`root-edit\n`，不是另一套缩小媒体实现；`mutations` 复用 #143 的 `compose`／`replace`／`edit`／`current-delete`／`delete-first`／`delete-last`／`delete-only`／`loading`／`append` 命令。
- sampler 是 read-only Observe，只报告 `rows=0`，不控制 resize、不保持图形可见；关闭全部普通 GUI 后的暂停不会被采样器伪装成可见。隐藏 pane、切换 tab／screen、滚出与恢复、相对／virtual 链及剩余间隔仍须在正常 UI 路径逐项观察。
- `reopen` 只在旧自有 GUI 进程已真正退出后重新启动普通 app；不重启 sender。发送 `quit\n` 后 wrapper 保留同一真实 PTY 的 shell，便于验证 sender 已停止且仍从同一 daemon 恢复。可再发 `restart-router` 后 `reopen` 检查本机 router 硬重建；该操作不停止 Linux daemon。
- `stop` 结束执行器，只退休自己创建的 GUI／workspace／pane／producer 目录与本机 router；证据目录保留。不要向用户安装的窗口、daemon 或 HOME 投递命令。

<a id="copying-a-remote-image-to-this-machine"></a>
## 将远程图像复制到本机

SSH 主机上的程序可以使用 OSC 5522 剪贴板协议，将 PNG、JPEG、GIF 或 WebP 图像
写入运行 lyrel 的机器的系统剪贴板。请先为该已保存的主机启用
**高级 → 安全 → 远程剪贴板图像**。此功能默认关闭，否则任何能够输出终端内容的
程序都可以替换剪贴板内容。

可以将以下 Python 脚本以 `lyrel-copy-image` 的名称安装到远程主机上：

```python
#!/usr/bin/env python3
import base64
import os
import pathlib
import re
import select
import secrets
import sys
import termios
import time
import tty

path = pathlib.Path(sys.argv[1])
mime = {
    ".png": "image/png",
    ".jpg": "image/jpeg",
    ".jpeg": "image/jpeg",
    ".gif": "image/gif",
    ".webp": "image/webp",
}.get(path.suffix.lower())
if mime is None:
    raise SystemExit("supported formats: png, jpg, jpeg, gif, webp")

data = path.read_bytes()
if len(data) > 16 * 1024 * 1024:
    raise SystemExit("image exceeds lyrel's 16 MiB clipboard limit")

osc, st = b"\x1b]5522;", b"\x1b\\"
encoded_mime = base64.b64encode(mime.encode())
request_id = secrets.token_hex(8)
out = sys.stdout.buffer
fd = sys.stdin.fileno()
old = termios.tcgetattr(fd)
status = None
try:
    tty.setraw(fd)
    rid = request_id.encode()
    out.write(osc + b"type=write:id=" + rid + st)
    for offset in range(0, len(data), 4096):
        chunk = base64.b64encode(data[offset:offset + 4096])
        out.write(
            osc + b"type=wdata:id=" + rid + b":mime=" + encoded_mime + b";" + chunk + st
        )
    out.write(osc + b"type=wdata:id=" + rid + st)
    out.flush()

    reply = bytearray()
    pattern = re.compile(
        rb"\x1b\]5522;type=write:status=([A-Z]+):id=" + rid + rb"\x1b\\"
    )
    deadline = time.monotonic() + 5
    while time.monotonic() < deadline:
        ready, _, _ = select.select([fd], [], [], deadline - time.monotonic())
        if not ready:
            break
        reply.extend(os.read(fd, 4096))
        match = pattern.search(reply)
        if match:
            status = match.group(1).decode()
            break
finally:
    termios.tcsetattr(fd, termios.TCSADRAIN, old)

if status != "DONE":
    raise SystemExit(f"clipboard write failed: {status or 'timeout'}")
```

运行 `lyrel-copy-image screenshot.png`。符合协议的发送端可以包含 OSC 5522
请求 ID，并等待 lyrel 的 `DONE`、`EPERM`、`EINVAL` 或 `ENOSYS` 响应。
剪贴板控制数据包不会保留在回滚缓冲区中，也不会在重新连接后重放。

## 身份验证提示

密码、密钥口令和双重验证提示会在窗格内以浮层形式显示，并在适用时提供
**记住（钥匙串）**选项。

手动 SSH 文本由 `ssh_connect::input` 解析，`ssh_connect` 的窗口适配负责别名覆盖、凭据交接与原生 pane 打开；
解析器不拨号、不保存配置，也不成为工作台根模块的一部分。已有远程机器的整工作区连接则由
`remote_workspace::connection::WindowConnection` 持有窗口级尝试身份，和单个原生 SSH pane 的会话生命周期分开。
两条入口继续复用现有 `SshPrompt`，共享机器连接仍由 `RemoteLinks` 监督；取消认证不会创建第二套连接或终端。


GSSAPI 仅在启用 `gssapi` feature 的 Unix 构建中可用，使用系统 Kerberos 凭据，
不会把票据存入 lyrel 配置或钥匙串。Linux 源码构建需要 Kerberos 开发库
（Ubuntu 的 `libkrb5-dev`），可用 `LIBGSSAPI_IMPL=mit` 明确选择 MIT 实现。
验证需要启用 `gssapi-with-mic` 的真实 SSH 服务与有效本地票据；普通单元测试或
ignored 用例不会证明该路径已工作。维护者可在隔离的 `KRB5_CONFIG`、`KRB5CCNAME`
环境中设置 `LYREL_LIVE_SSH_HOST`、`LYREL_LIVE_SSH_USER` 和 `LYREL_LIVE_SSH_PORT`，
显式运行现有实连用例：

```bash
cargo test --locked -p lyrel-core --features gssapi \
  daemon::ssh::tests::live_gssapi_connects_and_opens_a_channel -- --ignored --exact
```

该实连用例关闭普通主机密钥验证，只适用于维护者控制的隔离服务，不能用作
主机信任策略证明。安全回归另用临时 `known_hosts` 完成真实握手矩阵。

<a id="host-keys"></a>
## 主机密钥

默认情况下，会使用 `known_hosts` 验证主机密钥。首次连接时会要求你确认指纹；
如果密钥**发生变化**，则会显示更醒目的提示，要求输入 `yes` 才能覆盖，
因为密钥变化值得如此慎重对待。

**设置 → SSH → 安全 → 验证主机密钥**可以关闭普通密钥匹配与首次信任询问，
但不会豁免 `@revoked` 撤销记录。默认开启验证；拒绝或取消不会写入新信任。

“安全”下还有一个选项：关闭活动连接前的**关闭前警告**，默认关闭。

<a id="reconnecting"></a>
## 重新连接

<kbd>⌘ ⇧ R</kbd>——或全局搜索中的 *SSH：重新连接*——会重新启动当前窗格中的会话。
适合在笔记本电脑休眠后或网络发生变化后使用。

<a id="what-is-not-supported"></a>
## 不支持的功能

- 不会回退到系统 `ssh` 二进制程序
- 不支持 `~/.ssh/config` 中的 `Match` 或 `canonicalize*` 指令
- `~/.ssh/config` 中的 GSSAPI 指令不受支持。启用 `gssapi` feature 的 Unix 构建可在「身份验证」字段选择 **GSSAPI**，使用系统 Kerberos 凭据。
