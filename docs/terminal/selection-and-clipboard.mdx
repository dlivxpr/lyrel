## 选择

| | |
|---|---|
| 拖动 | 选择一段范围 |
| 双击 | 选中光标下的内容——见下文 |
| 三击 | 选中整行 |
| <kbd>⇧</kbd>-单击 | 将当前选择扩展到单击处 |
| <kbd>⌘ A</kbd> *(macOS)* | 全选——也位于右键菜单中，并在所有平台的全局搜索中提供 |

拖选超出网格顶部或底部时会自动滚动，并继续扩展同一选择；按词拖选反向经过起点时仍保留最初选中的词。选择锚点跟随 live grid 中的内容，输出滚动不会把它固定在旧的屏幕行。选择及滚动的状态转换由 `SelectionScroll` 共同维护，剪贴板写入仍在 `TerminalView` 的鼠标释放适配中执行；选中即复制不会清除高亮。

### 智能双击

双击并不只是抓取由空格划界的单词。它会判断你正指向什么：

| 光标下的内容 | 得到的结果 |
|---|---|
| URL | 完整的 URL——包括被 shell 折成两行的那个 |
| 文件路径 | 完整路径 |
| 电子邮件地址 | 完整地址 |
| 括号或引号 | 与之配对的那一个，以及两者之间的全部内容 |
| CJK 文本 | 按词典而非按字符切分出的词语 |

可通过**设置 → 键盘与鼠标 → 选择与剪贴板 → 智能选择**将其关闭。
关闭后，双击会退回到普通按词选择，使用 `config.json` 中的
`word_separators` 列表——默认值如下：

```
,│`|:"' ()[]{}<>⇥
```

## 复制与粘贴

| | macOS | Windows |
|---|---|---|
| 复制 | <kbd>⌘ C</kbd> | <kbd>Ctrl ⇧ C</kbd> |
| 粘贴 | <kbd>⌘ V</kbd> | <kbd>Ctrl ⇧ V</kbd> · <kbd>⇧ Insert</kbd> |

有两项设置决定剪贴板中最终得到什么，二者都位于**设置 → 键盘与鼠标 →
选择与剪贴板**中：

<CardGroup cols={2}>
  <Card title="选中即复制" icon="clipboard">
    用鼠标选中后立即复制，无需按 <kbd>⌘ C</kbd>。默认关闭。
  </Card>
  <Card title="复制时去除行尾空格" icon="scissors">
    去掉每一行复制内容末尾的空白——从按窗格宽度补齐空格的 TUI 中
    复制时很有用。默认关闭。
  </Card>
</CardGroup>

<Note>
  粘贴多行内容时，会将其作为键入输入发送，与任何终端的行为一致。
  如果 shell 支持方括号粘贴，它会将整块内容视为一次粘贴，而不是逐行执行。
</Note>

## 文件与图片投递

复制文件后粘贴、文件拖放和 composer 附件共用终端的文件投递路径。剪贴板同时带有文件和文字时优先识别文件；普通文字仍交给当前输入所有者，不通过文件上传流程。composer 接收附件，其余路径按 pane 的 shell 规则引用，并在末尾保留空格。

- 本地 pane 使用本机路径；WSL pane 使用既有路径转换，不把本机文件误当作远端上传。
- SSH workspace 或独立 native SSH pane 使用请求发起时捕获的 pane 与 `SftpRoute`，后台准备私有暂存目录并启动上传。路径在传输启动后即可投递，不等待整个文件传完；文件通过临时名称写入并在完整后重命名。
- 准备或启动失败时保留既有本地路径回退和通知；逐文件传输失败继续反馈，取消不报告为上传错误。远端文件树拖出的路径已经属于远端，不重复上传。
- 图片沿用本地 macOS 与其他平台／远端的既有差异：可共享系统剪贴板的本地 macOS 程序保留 SYN 路由，其他受支持场景准备图片文件后走相同投递路径。

### 实现职责与生命周期

`TerminalView` 保持同一个 pane、终端附件与焦点 identity。私有 `view::clipboard` 适配负责复制、剪切、粘贴、拖放及远端图片写入的 GPUI 副作用；键盘、Action、菜单、工作台和 composer 调用同一组终端入口，不各自实现投递策略。文本的 prompt／raw／composer 路由仍复用既有输入所有者。剪贴板分类、shell 路径引用、图片准备与远端暂存／上传生命周期由 `terminal::paste` 维护，不依赖视图根模块的辅助函数。

远端图片写入仍以 daemon 权限判定为主；GUI 在保留 SSH spec 时补充拒绝已明确禁止的请求，未保留 spec 不代表禁止。图片 MIME、内容及尺寸校验在后台完成，只有仍匹配当前 relink generation 的结果才能写入系统剪贴板并向原请求回报 `DONE`；拒绝权限与无效内容分别保留 `EPERM`、`EINVAL`。后台任务持有弱视图引用，视图关闭后不延长其生命周期；文件上传继续沿用捕获的目标路由与既有失败反馈规则。
