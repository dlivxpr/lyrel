<a id="fuzzy-search-with--r"></a>

## 使用 <kbd>⌃ R</kbd> 进行模糊搜索

<kbd>⌃ R</kbd> 会打开模糊搜索，搜索你实际运行过的命令。输入任意片段即可缩小列表范围，字母不必相邻。

每一行都包含普通 shell 历史记录不会保留的上下文：

- 上次运行的**时间**，以相对时间显示
- **是否失败**，根据退出码判断

无论运行过多少次，一条命令都只会出现一次：重复记录会合并为最近的一次。排序综合考虑使用频率和最近使用时间，并优先显示在*当前*目录中运行过的命令，因此你想找的命令通常就是上次在这里执行的那条。

<kbd>⏎</kbd> 将命令放入提示符。<kbd>⌘ ⏎</kbd> 将命令放入提示符并运行。<kbd>Esc</kbd> 关闭搜索，不改动提示符中的内容。

<a id="handing--r-back"></a>

### 交还 <kbd>⌃ R</kbd>

如果你已经有喜欢的 fzf、percol、atuin 或 McFly 按键绑定，请关闭
**设置 → 终端 → 提示符与命令历史记录 → 命令历史记录搜索**（`history_search: false`）。
这样，<kbd>⌃ R</kbd> 就会交由 shell 处理，你在 shell 中设置的绑定仍然有效。

这只会释放 <kbd>⌃ R</kbd>，不会影响其他按键：<kbd>↑</kbd> 仍会遍历 lyrel 自己的历史记录列表。要将整个提示符交还给 shell，包括 <kbd>↑</kbd> 及其绑定的任何组件，请关闭
[提示符编辑器](/terminal/prompt#giving-the-whole-prompt-back-to-the-shell)
（`prompt_editor: false`）。

<a id="where-the-history-comes-from"></a>

## 历史记录来自哪里

直接使用你现有的 shell 历史记录文件。不导入，也不转换，在 lyrel 之外写入的历史记录也会立即显示。

每行的额外信息——上次运行时间、是否失败——来自 lyrel 在历史记录文件旁维护的一个小文件，这些信息会在你运行命令时写入。lyrel 从未见过的命令也会显示，只是没有时间戳或退出码。

### 作用域与实现职责

命令历史按本地 shell 或远端目标分开。离开一个已加载的作用域时，窗格保留它的列表；从 SSH 返回后，立即可以用 <kbd>↑</kbd> 召回本地命令，无需等待后台刷新。尚未加载完成的空列表不会作为有效缓存保存，旧作用域或旧 Host 的异步读取结果也不能覆盖当前列表。

`src/terminal/history_session.rs` 的 `TerminalHistory` 统一拥有作用域、有限缓存、频次与目录元数据、排序、导航草稿、末词召回、反向搜索及待写记录。`history.rs` 保留文件格式、加载和持久化；`TerminalView` 仅调度 Host 读取、应用编辑结果与刷新界面。补全通过借用候选切片读取历史，不为跨模块调用复制整份列表。

<a id="one-history-or-one-per-pane"></a>

## 共享历史记录，还是每个窗格独立记录

默认情况下，所有窗格共享 shell 的历史记录文件，这与终端一贯的行为相同：在一个窗格中输入的命令，在另一个窗格中也能找到。

**设置 → 终端 → 提示符与命令历史记录 → 每个窗格使用独立的命令历史记录**
（`per_pane_history: true`）会改变这一行为。每个窗格都会获得一个私有的历史记录文件：

- 窗格打开时，以你的实际历史记录为**初始内容**，因此不会是空白的
- 窗格关闭时，**合并回**你的实际历史记录，因此输入过的命令不会丢失

当多个智能体或多项任务并行运行，而你不希望它们的命令在按 <kbd>↑</kbd> 时交错出现，这个功能就很有用。默认关闭，因为对于未主动启用此功能的人来说，这种变化会让他们觉得历史记录莫名其妙地忘记了另一个窗口中的命令。
