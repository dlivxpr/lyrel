按住 <kbd>⌘</kbd>（Windows 上为 <kbd>Ctrl</kbd>），指针下方的链接就会显示下划线；单击即可打开。

<a id="urls"></a>
## URL

任何看起来像 URL 的内容都会被检测到，即使 shell 将其换行显示在两行中也不例外——lyrel 会在打开前将其重新拼接起来。

可通过**设置 → 终端 → 链接 → 检测 URL**
（`link_url: false`）关闭检测。

<a id="files"></a>
## 文件

输出中的文件路径——无论来自编译器错误、测试失败，还是 `grep -n` 的匹配结果——都会在 lyrel 内置编辑器中打开，并跳转到链接指定的行。如果文件面板已打开，还会选中该文件。如果路径指向目录，则会在文件面板中打开该目录。

绝对路径和相对路径都能被检测到。解析相对路径时，会先以窗格的工作目录为基准，再以该目录所在的仓库为基准。因此，即使 shell 位于某个成员目录中，也能正确解析构建工具以工作区根目录为基准输出的路径。如果这两个位置下都找不到匹配的路径，lyrel 会给出提示，而不是毫无反应。

连接到另一台机器的窗格中的路径会*在那台机器上*解析，因此下划线会在指针停稳片刻后出现，而不是立即出现。如果窗格是在本地 shell 中输入 `ssh` 后运行的会话，就没有可为其解析路径的主机，因此其中的文件链接会被禁用。

**设置 → 终端 → 链接 → 文件打开方式**决定单击后如何打开文件：

| 模式 | 打开方式 |
| --- | --- |
| 内置编辑器 | 在 lyrel 编辑器中打开，并定位到 `:line:column`。这是默认选项。 |
| 默认应用 | 使用操作系统为该文件类型关联的应用打开。 |
| 命令 | 使用你自定义的命令——见下文。 |

无论设置了哪种模式，另一台机器上的文件始终在内置编辑器中打开：刚在远端解析出的路径对本地的 `open` 或 `code` 没有意义，这些命令只会打开本机上相同路径的文件副本，或者什么也打不开。

选择**命令**时，运行命令前会替换其中的占位符：

```
code --goto {path}:{line}:{column}
zed {path}:{line}
herdr edit {path} --line={line}
```

`{path}`、`{line}` 和 `{column}` 的值会从链接中提取。如果某个选项的值不可用，就会移除该选项，而不是传入空值——因此，当链接没有行号时，`--line={line}` 会直接被省略。

对应的设置项是 `config.json` 中的 `link_file_open`（可取 `internal`、`system` 或 `command`）和 `link_file_command`。在引入 `link_file_open` 之前编写的配置仍然有效：已设置命令的配置会继续使用**命令**模式，未设置命令的配置则会改用内置编辑器。

<a id="localhost-ports"></a>
## localhost 端口

按住 <kbd>⌘</kbd> 并单击 `localhost:3000`，即可在浏览器中打开该地址；但只有服务器运行在本机时，这样做才有用。

当窗格处于 SSH 会话中时，服务器通常不在本机，因此 lyrel 会先通过该连接建立端口转发，再让浏览器访问转发的本地端。如果转发尚未建立，就会在单击时创建。

此功能默认启用；通过**设置 → 终端 → 链接 → 转发远程端口**
（`ssh_loopback_forward`）可将其关闭，同时也会关闭对远程窗格开始提供服务的端口的自动转发。

<Tip>
  远程窗格正在监听的每个端口都会列在信息面板中，无论其 URL 是否曾在输出中出现——参见[端口转发](/remote/port-forwarding)。
</Tip>
