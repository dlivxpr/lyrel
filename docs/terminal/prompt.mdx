lyrel 在 shell 提示符处提供了一个编辑器。无需安装任何东西，也无需加载插件
——只要受支持的 shell 在窗格中启动，提示符就会具备以下功能。

这一层只在 shell 提示符处接管输入。前台智能体（包括使用主屏而非 alternate screen 的 TUI）
运行时，方向键、字符和输入法提交直接交给程序；例如 omp 的 ask 弹窗可用 <kbd>↑</kbd>／<kbd>↓</kbd>
选择答案，不会调用 shell 命令历史。智能体退出并回到 shell 提示符后，编辑器自动恢复。

<a id="ghost-suggestions"></a>
## 幽灵建议

输入时，光标前方会以灰色显示来自历史记录的建议，补全这一行的剩余部分。

| | |
|---|---|
| <kbd>→</kbd> | 接受整条建议 |
| 继续输入 | 缩小建议的匹配范围 |
| 输入任何不匹配的内容 | 建议消失 |

建议直接来自现有的 shell 历史记录——无需先积累一个单独的数据库，
而且历史记录会在会话之间以及重启后保留。

<a id="tab-completion-with-descriptions"></a>
## 带说明的 Tab 补全

按下 <kbd>⇥</kbd> 会打开补全菜单，其中的候选项按以下内容提供：

- **命令**：来自 PATH 和 shell 内置命令
- **文件和目录**：其中 `cd`、`pushd`、`popd` 和 `rmdir` 只提供目录
- **选项和子命令**：为约 100 个常用命令提供说明，包括 `git`、`cargo`、
  `docker`、`kubectl`、`npm`、`brew` 等
- **选项值**：当某个选项只接受特定值时，提供这些值

当 lyrel 没有可用的补全建议时，<kbd>⇥</kbd> 会交由 shell 自身的补全功能处理，
因此你精心配置的 zsh 补全仍然可用。

若要将 <kbd>⇥</kbd> 完全交还给 shell，请关闭 **设置 → 终端 →
提示符与命令历史 → Tab 补全**（`config.json` 中的 `tab_completion`）。

菜单中的 <kbd>↑</kbd>／<kbd>↓</kbd> 更改候选，<kbd>⏎</kbd> 只将当前建议插入输入行，不发送命令；接受后可以继续输入，再按一次 <kbd>⏎</kbd> 才提交。<kbd>Esc</kbd> 关闭菜单；插入换行也会关闭菜单，但不会接受建议或执行命令。

远端目录列举期间显示等待提示；列举失败显示错误，下一次按键将其关闭。成功但没有匹配项时不显示失败提示，而是按既有规则把 Tab 交回 shell。已取消的请求、旧输入、旧 Host 或旧工作目录的迟到结果不能改变当前建议、输入或等待／失败提示。

### 补全实现职责

`src/terminal/completion/state.rs` 的 `TerminalCompletion` 私有持有会话、请求代次、远端请求与失败提示，并统一执行候选合并、过滤、选择、公共前缀扩展、shell 引用与插入。幽灵建议直接借用 `TerminalHistory` 的 entries、目录亲和性与 metadata，保持最近成功命令优先；历史 frecency 仍供反向搜索排序，不为补全复制历史存储。

`TerminalView` 保留 GPUI identity、按键与输入协调、任务调度、菜单呈现及真正的 PTY 发送。异步结果通过当前 Host／目录上下文和请求代次交给补全所有者判定，不能先清除新请求的等待状态再判断结果是否过期。

职责迁移后的定向测试与原生 smoke 由集成分支集中执行，尚未执行不能记为通过。原生验收使用隔离开发配置：在真实 shell 输入有多个候选的路径，选择并按 Enter 接受后继续输入，确认整行保留且尚未执行；再提交并检查 shell 收到完整命令。远端慢列举期间依次编辑、取消、切换目录／Host 后再次补全，确认迟到成功或失败都不能替换新建议或复活旧错误；分别检查成功空列举、失败提示及下一次按键关闭提示。

<a id="syntax-highlighting"></a>
## 语法高亮

输入过程中，命令行中的各个部分会实时着色：命令、选项、参数、路径、
带引号的字符串、运算符和注释。它是一个快速的词法分析器，
而不是 shell 解析器——绝不会改变实际执行的内容。

<a id="line-editing"></a>
## 行编辑

提示符的行为就像一个文本框，因为它本来就是：

- **单击放置光标**：可放在行内任意位置
- **使用鼠标选择文本**，拖动以扩展选区
- **按词移动**和按词删除
- **撤销**

readline 的所有功能仍然有效——这一层建立在其之上，而不是取代它。

<Tip>
  在 macOS 上，如果你希望 <kbd>⌥ B</kbd> / <kbd>⌥ F</kbd> 按词移动，
  而不是输入 `∫` 和 `ƒ`，请开启 **设置 → 键盘与鼠标 → 键盘 → 将 Option (⌥) 用作 Meta**。
</Tip>

<a id="typing-with-an-ime"></a>
## 使用输入法输入

拼音、假名、韩文等输入法在窗格中的工作方式与文本框中相同：
预编辑内容直接显示在光标处，只有确认提交的文本才会传给程序。
切到其他输入区域时会取消原区域尚未提交的预编辑；要保留文字，请先在原区域确认候选，
再移动焦点。未提交的候选不会作为新输入框的文本继续提交。

按键交给谁处理，由两条规则决定：

- **普通的可打印按键交给输入法。** 按住 <kbd>⌃</kbd>、
  <kbd>⌘</kbd>、<kbd>fn</kbd> 或 <kbd>⌥</kbd> 时按下的键则不会——
  它们是组合键，不是字符。
- **要求接收所有按键的程序会收到所有按键。** 当某个程序启用
  kitty 键盘协议的报告所有按键模式时，输入法会让出处理权，
  使程序能够收到原始输入。

<Note>
  在 macOS 上开启 **将 Option (⌥) 用作 Meta** 后，<kbd>⌥</kbd> 组合键会完全绕过输入法，
  因此 <kbd>⌥ B</kbd> 会以 meta-b 的形式传给 shell，而不会被当作死键吞掉。
</Note>

中日韩文字的良好渲染是另一个问题——请参阅
[字体与双列网格](/customization/fonts#cjk-and-the-two-column-grid)。

<a id="multi-line-commands"></a>
## 多行命令

无论命令是自动折行，还是被你主动拆成多行，都可以就地编辑。
网格会移动以保持光标可见，而不是把整个屏幕的内容滚走。

当提示符本身占据了一行的大部分空间——例如工作目录层级很深，或主题内容繁多——
输入内容会改从下一行开始，使用窗格的完整宽度。
当提示符留下的可用列数少于总列数的三分之一时，就会触发这一行为
（该阈值不会低于 20 列）；普通长度的提示符仍会让输入内容紧随其后。
如果你更希望缩短提示符，可以在 shell 中调整：使用 zsh `PROMPT` 中的 `%2~`、
fish 的 `prompt_pwd`，或 starship 的 `truncation_length`。

| | |
|---|---|
| <kbd>⇧ ⏎</kbd> · <kbd>⌥ ⏎</kbd> | 插入换行，而不是提交 |
| <kbd>⏎</kbd> | 提交整个缓冲区，无论有多少行 |

换行键可以在 **设置 → 快捷键绑定** 中通过 `InsertNewline` 重新绑定。

<a id="which-shells"></a>
## 支持哪些 shell

提示符功能由 lyrel 的 shell 集成提供。对于 **zsh**、**bash**、
**fish**、**PowerShell** 和 **WSL**，集成会自动注入，无需向 rc 文件添加任何内容。
其他 shell（nushell、elvish、xonsh 等）也能在窗格中正常运行，
只是没有这一提示符层。

集成还会报告工作目录、每条命令的退出码，以及提示符的起始位置——
侧边栏的分支信息、“命令已完成”通知和 `lyrel procs` 都建立在这些信息之上。

[了解 shell 集成的工作原理 →](/reference/shell-integration)

<a id="turning-it-off"></a>
## 关闭功能

每项提示符功能都有独立开关，关闭后会将对应按键直接交还给 shell：

| 设置 | 交还的按键 |
|---|---|
| **设置 → 终端 → 提示符与命令历史 → Tab 补全** | <kbd>⇥</kbd> → shell 自身的补全 |
| **设置 → 终端 → 提示符与命令历史 → 命令历史搜索** | <kbd>⌃ R</kbd> → shell 自身的 reverse-i-search，或你的 fzf 绑定 |

<a id="giving-the-whole-prompt-back-to-the-shell"></a>
### 将整个提示符交还给 shell

关闭 **设置 → 终端 → 提示符与命令历史 → lyrel 提示符编辑器**
（`prompt_editor: false`）后，交还的不只是某个按键，而是整条命令行。
提示符处的所有按键输入——可打印字符、方向键、输入法提交内容、粘贴——
都会直接传给 PTY，由 shell 自身的行编辑器负责编辑：
zsh 的 ZLE、bash 的 readline、fish 的 reader。
你自行绑定的组件会像在 lyrel 之外一样运行：

```zsh
# ~/.zshrc — 关闭编辑器后，可在 lyrel 提示符处使用
bindkey '^[[A' history-beginning-search-backward-end
```

你失去的是本页介绍的这一层功能：幽灵建议、补全菜单、模糊搜索 <kbd>⌃ R</kbd>、
多行编辑器、在提示符处用鼠标放置光标和撤销。
关闭编辑器时，设置中的 Tab 补全和历史搜索会变灰——
这两者都是 lyrel 在该编辑器内打开的菜单，编辑器关闭后，它们也就没有可供切换的功能了。

你保留的是 shell 集成报告的全部信息：提示符边界、工作目录、退出码、
“命令已完成”通知、侧边栏的分支信息，以及 `lyrel procs`。
这项设置改变的是行编辑器的归属，而不是集成本身。

该设置会立即应用到已打开的窗格，无需重启；
已经输入了一半的命令行也会交给 shell，而不会被丢弃。

<Tip>
  如果你重视 shell 自身的历史遍历功能——例如窗格之间共享历史记录、
  `HIST_FIND_NO_DUPS`、绑定到 <kbd>↑</kbd> 的前缀搜索——
  或者希望由你依赖的插件（zsh-autosuggestions、
  zsh-syntax-highlighting、atuin）接管命令行，就可以使用此设置。
</Tip>
